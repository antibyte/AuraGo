# Storymaker Player Runtime - Child DOX Contract

The player draws a story in the browser: the app preview (a sandboxed iframe), the headless render page of the export and the
fallback in the host realm all run the same code. The app side is `../desktop/apps/AGENTS.md` (Storymaker), the story format and
catalog index are `../../../internal/storymaker/AGENTS.md`, the generated catalog is `../../img/storymaker/` (`assets/storymaker`).

## Layout and build

- Classic scripts, never modules, outside `ui/js/desktop`. `host.bundle.js` (document realm: host, app protocol, render driver,
  deadlines) and `player.bundle.js` (worker realm: compile, render, rig, code-scene API, role handlers) are generated by
  `npm run build:ui` from the part lists in `scripts/storymaker-bundle-parts.js`; never edit a bundle by hand, `npm run check:ui`
  fails when one is stale. Every part keeps its own IIFE scope; the shared parts (`schedule.js`) sit in both bundles.
- The player CSS `../../css/storymaker-player.css` is the only stylesheet of the player host page and is named in its CSP.
- Workers are blob workers: one prelude line sets the role and imports the local `js/vendor/storymaker/runtime.js` followed by `js/storymaker/player.bundle.js`
  plus, for a scene worker, the scene bundle text. A line number inside a worker minus one is a line of the scene bundle.

## Rules

- Catalog v2 uses persistent PixiJS 8.22.0 scene graphs (`raster.js`, `raster-rig.js`), hardware WebGL first and a fresh Pixi CanvasRenderer when unavailable or a known CPU rasterizer is reported. `timeline.js` evaluates numeric channels through paused GSAP 3.15.1 timelines. The locally bundled vendor has inert timers/tickers and a fixed clock; only explicit `frame / fps` sampling advances a frame. No animation callbacks may mutate story state. The legacy renderer remains for v1 fixtures.
- `textures.js` verifies catalog-only `texture:<path>` buffers, hashes, encoded and decoded image dimensions. Original bytes remain cached in the host; each worker gets its own copy and textures. The limits and schemas are owned by `../../../assets/storymaker/ASSET-CONTRACT.md`.
- `prepare_frame` decodes and warms trusted renderer resources under the asset deadline; it never runs a scene's `onFrame`. Actual frame callbacks retain their frame deadline. Code-scene v2 builds are serial; inactive scene workers are terminated and rebuilt deterministically when seeking back. A project reset releases renderers, fonts, bitmaps, raw buffers and GSAP timelines; generation checks discard late asynchronous loads.
- Planted walking solves two-bone leg contact from compiled walk distance, with horizontal ankle-pivoted shoes and entry/exit blending. Sitting uses body-specific lowering and replacement drawings. Text wrapping, captions, speech, compiler timing and the restricted code-scene API retain their existing owners.
- Raster attachment transforms apply catalog-calibrated local shear after pivot/upright placement. This aligns measured sprite centerlines with the unchanged skeleton in Canvas and WebGL. The asset owner calibrates matching knee/elbow widths, wrist anchors and view-specific arm order; the player must not stretch individual hand swaps independently.
- Bitmap shoulders use cached Graphics masks for round proximal caps. Masks follow the attachment transform, are cleared when a reused slot no longer needs one, and share scene pruning/disposal with sprites. Hand selection uses the pose/active gesture's palm or side/back intent. Sprite gesture arms blend away the base pose's arm angles during the gesture envelope, avoiding doubled rotations; legs and compiler timing are unchanged. `render.rigState.basePoseBones` is internal presentation metadata, and legacy vector rendering stays additive.
- No `innerHTML`, `insertAdjacentHTML`, template string with data, `eval` or `Function` anywhere under `ui/js/storymaker`
  (`TestStorymakerSourcesAreSafeAndSmall` and `scripts/storymaker-tests/10-static-guards.mjs`). Story text is drawn on a canvas.
- Determinism: time is the frame number; no `Date`, `Math.random` or wall-clock reads in a render path (`determinism.js` shadows them
  in the code-scene realm); the same story twice renders the same frames. Do not pin pixel hashes of one version in tests.
- Deadlines: scene build 2 s, app code frame 250 ms (the first three frames after a load 4 s; exports use the boot frame deadline), trusted v2 raster painting 4 s, compile 10 s, assets 20 s. A worker that
  overruns is terminated and reported (`deadline`); a code-scene frame error kills only that scene's worker and shows a placeholder.
- The app protocol (contract section 8) accepts only messages from `window.parent`, in a fixed schema with caps, and posts to the
  origin of `data-sm-base`. `load` resets everything; the first `time` message after a compile is the "ready to play" signal.
  The render page (`data-sm-mode="render"`) fetches only from its own base and posts frames in strict order (contract section 7).
- Support matrix: beats enter exit walk move pose gesture emote look show (item and text) hide highlight camera wait; transitions
  cut fade slide-left wipe (others fall back to fade with a `not_supported_yet` note); everything else the validator accepts is ignored.
- Motion: `motion.js` holds rhythm factors, beat defaults, lead fractions and holds; `beats.js` runs the scheduler; `lint.js` holds the
  static lint, which reads `built.log` and never blocks a render. Code-scene API defaults are not scaled.
- Text: compile never measures. Shrink to fit and balance run in `text.layout`. The layout memo is keyed on text, style name, canvas
  size, family and `maxWidth`, because `maxWidth` follows the anchor, so frame n stays a pure function of n.
- Tables and seeds: `ranges.js` is generated by `scripts/build-storymaker-ranges.mjs`; never edit it by hand. No `Intl.Segmenter`,
  `\p{...}` or `normalize` in compile or the wrap. Every seed comes from strings (`seed.js`), because no project seed exists.

## Speech

- New parts: `glyphs.js` (coverage, font needs, family chain), `cuemap.js` (`cueMap(block, offset)`, the one function behind cue and caption times), `captions.js` (2 lines, width 42, at least 1.0 s), `lipsync.js` (mouths from stored levels, seeded from the block id), `bubble.js` (speech and thought bubbles, 0.12 s fades).
- `say` is in the support matrix. With text it runs one `dialogue` block after the previous block ends. Without text it draws the active caption line of the scene narration until that narration ends, has no block and moves nothing. In a silent scene it draws nothing. An actor off stage keeps the audio events and gets no bubble and no lip-sync.
- `audio_events` has one entry per piece and no `gain`; Go computes every gain. `captions` are always filled, and `style.captions` decides drawing only. Compile drops events at or past `duration_ms` and cuts captions at it.
- Fonts are needed per character, so a Latin story fetches no CJK face. Compile and the wrap use the generated `ranges.js`, never `Intl.Segmenter`, Unicode property escapes or `normalize`, so an ICU version cannot change a layout.
- The render page keeps the boot token in a closure and adds it to `/report`, `/frame` and `/error` itself. Failure texts name only the route, so neither token nor prefix reaches `__smStatus`, the `/error` body or the job record. Font fetches are lazy through `boot.fonts`.

## Parallel render

- `host-pool.js` sits in `host.bundle.js` between `host-app.js` and `host-render.js`. `H.runPool({engines, limit, chunk, preRoll, post, status}) -> outcome` sends chunk j to worker `j % N` and a chunk with code-scene frames to worker 0. A worker waits while its chunk starts `>= N*C*2` frames past the next frame to post. One in-order poster keeps one POST in flight, so Go's ingest is unchanged.
- On `restart` the poster stops, the generation is abandoned, the buffer is cleared and the same engines re-run from frame 0. A crash or deadline rejects and the page posts `/error`.
- `Engine.load` accepts `shared_code_scenes` and then builds no scene workers. `Engine.render(n, {png:true})` returns a Blob. `worker-player.js` `render` with `msg.png` returns `{blob}` from `main.canvas.convertToBlob({type:'image/png'})`.
- The page creates `workers-1` helper engines before the report, so they cannot trip the 10 s frame watchdog. A different `frame_count` or schedule is `render_failed`. `workers` 1 or absent keeps the serial path.
- Verify `node scripts/storymaker-tests/22-host-pool.mjs` through `npm run test:storymaker`, and `AURAGO_RUN_BROWSER_SMOKE=1 go test ./internal/storymaker/render -run '^TestParallelParityBrowser$' -count=1 -timeout 20m`.
