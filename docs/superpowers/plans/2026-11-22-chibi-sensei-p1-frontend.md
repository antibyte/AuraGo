# Chibi Sensei P1 frontend plan

## Contract changes

None. The UI uses every P1 route of `C:\disposable\chibi-sensei\p1-api-contract.md` as written. Two clarifications for the backend chain. Neither changes a route or a payload:

- **Check texts.** The UI words check findings itself, from `chibi_sensei.check.<id>` with the generic `value`, `threshold` and `row_count` fields of each check. It ignores `message_key` and `args`. The backend may keep emitting them.
- **Server reason keys.** `suggested_profile.reason_key`, the plan `reason_key` and import `issues[].message_key` are shown only when the key exists in the locale files. Otherwise the UI shows a fallback. The UI ships these keys: `chibi_sensei.suggest.{specialist_short_inputs, assistant_other_language, assistant_lfm_language, default}`, `chibi_sensei.plan.training_later` and `chibi_sensei.import.issue_generic`. B3 should emit exactly these suggest and plan keys.

**Layout decision.** The modules live in the sub-folder `ui/js/desktop/apps/chibi-sensei/`. Every relevant mechanism already accepts a sub-folder:

- ECalc uses one: `module-loader.js:29-32` lists explicit paths, and `loadScriptsInOrder` takes any path.
- The line-budget walk recurses: `ui/desktop_js_line_budget_test.go:38-63`.
- So do the i18n scans: `ui/i18n_lint_test.go:462-503` and `ui/desktop_i18n_cleanup_test.go:206-225`.
- `scripts/build-ui-bundles.js` never bundles app modules. Only the shell parts are bundled (`:10-24`, output `:147`). `module-loader.js` itself is loaded on its own (`ui/desktop.html:141`).
- Locale sections are cut by key prefix (`internal/i18n/i18n.go:172-193`), and the loader walks folders recursively (`:91-135`). So `ui/lang/chibi_sensei/` needs no registration beyond `APP_I18N_SECTIONS`.

**Rules every batch follows** (root `AGENTS.md:5-12` DOX, `:65` syntax checks; `ui/AGENTS.md:15-26` no external assets and no `cc-`/`ad` prefixes, `:1404-1405` semantic controls, visible focus, never `alert`/`confirm`/`prompt`; `ui/js/desktop/apps/AGENTS.md:80-101` Storymaker contract, `:3617-3648` app materials, `:5393-5403` local i18n helper and the 1100-line budget):

- **File shape.** Each module is one classic-script IIFE under 1100 lines. It starts with a `//` purpose comment and `'use strict'`, and attaches only to `window.ChibiSenseiParts`. The root alone publishes `window.ChibiSenseiApp`.
- **Safe output.** Text reaches the page only through `P.el` (`textContent`). No `innerHTML`, `outerHTML`, `insertAdjacentHTML`, template literals (no backticks at all), `eval`, `new Function`, `localStorage`, `sessionStorage` or `document.cookie`.
- **Network.** Only `chibi-sensei-api.js` calls `fetch` or creates an EventSource.
- **Keys.** Every visible string is a full literal key `t('chibi_sensei.…')`, or a family prefix plus a value from a `const` list that the guard test reads.
- **Read-only.** A read-only desktop disables every write control, and its title names the reason (`chibi_sensei.readonly_banner`).
- **Errors.** Every network error becomes a translated inline message in a `p.csn-error[role=alert]` of the view that made the request. The polite live region `.csn-live` carries success notes.
- **Dialogs.** Confirmations use `ctx.confirmDialog`. Typed confirmations and short text input use `ctx.modalDialog({title, message, input: true, value})`, which resolves to the trimmed string or `null` (`menus-and-routing.js:752-829`, `:810`, `:821-826`). Forms use native `<dialog>` built with `P.el` and `showModal()`, following `storymaker-dialog.js:27-102`.
- **Keyboard and focus.** Every control is a real `button`/`input`/`select`/`textarea`. The rail uses roving `tabindex` with Arrow Up/Down. Escape closes the side sheet and the dialogs, and focus returns to the opener. Focus style: `outline: var(--ds-focus-ring-width) solid var(--ds-color-border-focus)` (pattern `desktop-app-storymaker.css:22`).
- **Long operations.** Progress comes from SSE `job` events. A 2.5 s poll of `GET /projects/{id}/jobs?active=1` runs while any job is queued or running; a job that leaves the active list is read once with `GET /jobs/{id}`.

    const FILTER_KEYS = ['q', 'split', 'source', 'flag', 'label', 'batch'];
    const emptyFilter = () => ({ q: '', split: '', source: '', flag: '', label: '', batch: '' });
    const closedEditor = () => ({ state: 'closed', rowId: null, draft: null, baseRev: 0, serverRow: null, issues: [], dirty: false, error: null });
    function initialState() {
        return { offset: 0, limit: PAGE_SIZE, total: 0, rows: [], dataRev: 0, filter: emptyFilter(), sort: 'seq', dir: 'asc',
            selection: { mode: 'ids', ids: [] }, status: 'idle', error: null, needsReload: true, editor: closedEditor() };
    }
    function lastOffset(total, limit) { const n = Number(total) || 0, l = Number(limit) || PAGE_SIZE; return n <= 0 ? 0 : Math.floor((n - 1) / l) * l; }

        const base = { split: row.split || 'auto', tags: Array.isArray(row.tags) ? row.tags.slice() : [] };
        return row.kind === 'text' ? Object.assign(base, { text: String(row.text || '') }) : Object.assign(base, { messages: (row.messages || []).map(m => ({ role: m.role, content: String(m.content || '') })) });
    }
    function sortedIds(list) { return Array.from(new Set(list.filter(n => Number.isInteger(n)))).sort((a, b) => a - b); }
    function reduce(state, action) {
        const s = state || initialState(), a = action || {}, set = patch => Object.assign({}, s, patch);
        switch (a.type) {
        case 'load_start': return set({ status: 'loading', error: null, needsReload: false });
        case 'load_ok': {
            const total = Math.max(0, Number(a.total) || 0), last = lastOffset(total, s.limit), rev = Number(a.data_rev) || s.dataRev;
            if (s.offset > last) return set({ status: 'idle', total, rows: [], offset: last, dataRev: rev, needsReload: true });
            return set({ status: 'idle', total, rows: Array.isArray(a.rows) ? a.rows : [], dataRev: rev, needsReload: false });

        case 'page': return set({ offset: Math.min(Math.max(0, Math.floor((Number(a.offset) || 0) / s.limit) * s.limit), lastOffset(s.total, s.limit)), needsReload: true });
        case 'filter': {

            return set({ filter: next, offset: 0, selection: { mode: 'ids', ids: [] }, needsReload: true });
        }
        case 'sort': return set({ sort: a.sort === 'est_tokens' ? 'est_tokens' : 'seq', dir: a.dir === 'desc' ? 'desc' : 'asc', offset: 0, needsReload: true });
        case 'select_toggle': {
            if (s.selection.mode !== 'ids') return s;
            const has = s.selection.ids.indexOf(a.id) >= 0;
            return set({ selection: { mode: 'ids', ids: sortedIds(has ? s.selection.ids.filter(x => x !== a.id) : s.selection.ids.concat([a.id])) } });
        }
        case 'select_page': {
            const page = s.rows.map(r => r.id);
            return set({ selection: { mode: 'ids', ids: sortedIds(a.on ? s.selection.ids.concat(page) : s.selection.ids.filter(x => page.indexOf(x) < 0)) } });
        }
        case 'select_filter': return set({ selection: { mode: 'filter', ids: [] } });
        case 'select_clear': return set({ selection: { mode: 'ids', ids: [] } });
        case 'remote_rev': return Number(a.data_rev) > s.dataRev ? set({ needsReload: true }) : s;
        case 'edit_open': return set({ editor: Object.assign(closedEditor(), { state: 'editing', rowId: a.row.id, draft: draftFromRow(a.row), baseRev: a.row.rev }) });
        case 'edit_new': return set({ editor: Object.assign(closedEditor(), { state: 'editing', rowId: 'new', draft: blankDraft(a.kind) }) });
        case 'edit_change': return s.editor.state === 'closed' || s.editor.state === 'saving' ? s : set({ editor: Object.assign({}, s.editor, { draft: a.draft, dirty: true, state: s.editor.state === 'conflict' ? 'conflict' : 'editing', issues: [] }) });
        case 'edit_save_start': return set({ editor: Object.assign({}, s.editor, { state: 'saving', error: null }) });
        case 'edit_save_ok': {

        case 'edit_invalid': return set({ editor: Object.assign({}, s.editor, { state: 'invalid', issues: Array.isArray(a.issues) ? a.issues : [] }) });

    function rowPreview(row, max) {
        const cap = v => { const t = String(v || '').replace(/\s+/g, ' ').trim(); return t.length > (max || 240) ? t.slice(0, (max || 240) - 1) + '…' : t; };

        return { prompt: cap(u >= 0 ? m[u].content : ''), answer: cap(a >= 0 ? m[a].content : '') };

## Decisions beyond the spec

1. **Sub-folder layout.** The modules live in `ui/js/desktop/apps/chibi-sensei/` (ECalc precedent). The loader, the recursive line-budget and i18n walks, and the Go guard globs all accept it.
2. **Translation keys.** Modules call `t('chibi_sensei.full.key')` with full literals, as Storymaker does. They are still registered in `desktopLocalI18nHelpers` (spec), and `chibi_sensei` joins `keyPrefixes` in F5, so all-locale coverage is checked once all 16 locales exist.
3. **Server keys.** The UI ignores check `message_key`/`args` and words findings from its own keys with `value`/`threshold`. Server reason keys show only when present, with a fallback. This removes a hard key coupling with B3 and B4.
4. **Multi-instance.** It comes from the `matchesExistingAppWindow` exclusion list, not a new flag. Each window has its own SSE stream.
5. **Dialogs.** Simple confirmations and typed confirmations use the shell helpers (`confirmDialog`, `modalDialog`). Forms use native `<dialog>` (Storymaker export dialog pattern), so no `alert`/`confirm` is ever used.
6. **Explicit saving.** The Goal step saves on Save or on the primary action, not by autosave. A dirty draft blocks Back and close.
7. **"New example" toolbar button.** It is added because the mockup has no entry point for manual rows.
8. **Preset choice.** Choosing a preset card on the read-only plan view saves `preset` through PATCH. Nothing trains.
9. **Cleaning review.** It loads all suggestions (at most 500) and applies an explicit ID list. It never sends `"all"`, so removals stay opt-in.
10. **Export overwrite.** The save dialog asks before overwriting, so the request always sends `overwrite: true`.
11. **Read-only Check dataset.** A read-only desktop also disables Check dataset (a POST). Stored results (`GET /checks`) still show.
12. **Mascot.** It is decorative (`aria-hidden`); the tip carries the meaning. `celebrating` is drawn but unused in P1, because it means "run succeeded".
13. **Job strip.** It lives in `chibi-sensei-data.js`, because imports (F3) need it before the helpers (F4).
14. **Config page.** It shows only the P1 fields (switch, storage, dataset, import, generator). Agent, training and runtime settings arrive with their phases.
15. **Browser smoke location.** It lives in `internal/server` as a test-only file, because only there can it run the real handlers (pattern `findit_browser_test.go`, `storymaker_app_browser_test.go`). This is a deliberate exception to "frontend owns `ui/**` and `scripts/**`". It also stays out of the `ui` package browser shard matrix (`TestUIBrowserCIShardsCoverEveryTest`).
