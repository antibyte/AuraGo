## Batches, parts and landing order

Phase 2 is one plan in parts, landed in four batches. Each batch works on its own, lands alone and leaves main green.

- 2A Motion: part M. Motion craft in compile, static lint, `style.rhythm`, highlight beat, D11 default transition. The sfx rule is implemented with impact 0 until 2C. `style.auto_sfx` is accepted only in 2C, when it works. Regenerate timing tests, goldens, contract line 618.
- 2B Speech: parts G (glyphs), N (narration backend, report token, report cap, `Plan.AudioInfo`, audio routes), S (speech in the player: cue map, say blocks, bubbles, captions drawn, lip-sync, `needs` fonts), E1 (voice panel, narration status, narration-only preview, scrubber waveform). The `narration_incomplete` gate does NOT land here.
- 2C Sound: part A (SFX set, catalog fields, take rotation, `auto_sfx`, `sfx.typing`, music jobs, mix, stems, loudness, frame gate, deferred start, D15 body, SRT and VTT, library copy, `narration_incomplete` and `music_incomplete` gates with a seeded-audio test helper), E2 (music panel, preview with music and SFX). First task of 2C: nothing to measure again, the real-material result is in `evidence/mixReal.md`.
- 2D Export: E3 (export dialog, finished-job actions, handoff, `projectId`), W (parallel workers, last and droppable), I (integration, acceptance, docs).

Ownership inside a batch: `validate.go`, `plan.js`, `host-render.js` are edited by several parts, so each batch names one owner per file and its tasks run in order. Locale files (`lang/storymaker/*.json`, 16 locales) belong to one final task of each batch; the i18n guard is run there. `storymaker.js` has 162 lines left under its 1100-line guard, so every panel is a new module. Player parts stay under 600 lines.

## Security (applies from 2B)

S1 Report and frame token. A scene worker knows the render base and could POST a forged report, and the first report wins (`render.go:594-598`). `boot.json` returns `token` on its FIRST GET only; the host makes that GET before any worker exists (`host-render.js:55`). Every POST (`/report`, `/frame`, `/error`) and `GET /start` carry `t=<token>` as a query parameter (a header would force a CORS preflight per frame). A missing or wrong token is a 403. Tests: second GET of boot.json has no token; a report without the token is refused and does not consume the one-shot.

S2 Report validation in Go, even with the token. `audio_events` refs must be in Go's own block map (Plan) or be a catalog SFX with a valid take; the count is under a bound derived from the Plan; times lie inside the film; a JS `gain` is ignored (the field is dropped from the report). Each caption's text, with whitespace removed, must be a substring of a block's text with whitespace removed; control characters stripped; `<`, `&`, `>` escaped and `-->` broken when writing SRT and VTT. `maxReportBytes` goes from 1 MiB to 8 MiB in 2B (a maximal Hindi story's captions alone reach it).

S3 Audio routes. `GET /projects/{id}/audio/narration/{hash}.{ext}` and `GET /projects/{id}/audio/music/{key}.{ext}`: `ValidProjectID`, hash regex `^[0-9a-f]{64}$`, ext whitelist (wav, mp3), fixed Content-Type, `nosniff`, sandbox CSP (`writeStorymakerScript`, `storymaker_handlers.go:502`), `http.ServeContent` for range requests. SFX come from `/img/storymaker/sfx/`. The parent builds URLs only from its own `/narration` answer and the catalog, never from player-message text.

S4 Music inputs. `music.file` only through `OpenPreviewFile`. A `GetMedia` path must be audio, under DataDir/audio and not protected. Copy to a hash name; FFmpeg sees only that copy, with `-protocol_whitelist file`, `-map 0:a:0`, `-t film+2`, and `-fs` against decode bombs.

S5 Paid calls. The read-only flag is re-checked immediately before every paid provider call inside a job (spec line 771), not only at job start. Disk: estimate decode + mix + stems before mixing and fail early with a clear message; the 256 MiB floor (`render.go:51`) is too low on its own (a 900 s film with stems is 1.3 GB). The Videos method takes a slug only and builds the path itself; it honours the desktop read-only flag. Go decoders cap the WAV data length at the file size and recover go-mp3 panics.

## Narration

D1 Blocks and pieces. `internal/storymaker/narration.go`: `Blocks(story)` returns one narration block per non-silent storyboard or code scene with narration text (`id "<scene>:n"`, speaker from the scene, voice = cast voice when the speaker is a cast ID, else project voice), and one dialogue block per `say` beat with `text` in a storyboard scene (`id "<scene>:b<beatIndex>"`, voice = cast voice or project voice). Code scenes have no beats (`compile.js:61-63`). Markers `{n}` are stripped by a rule shared with `narration.js`. JS `\s` is Unicode and Go's is ASCII (`narration.js:19`), so Go implements the JS set explicitly and a cross-language fixture pins it, with U+00A0 and U+3000 in it. PIECE SPLIT, one sentence per piece (`evidence/perSentence.md`; this changes spec line 495, which grouped sentences up to the chunk limit): sentence ends are ASCII `.!?` followed by whitespace or the end, and `…。！？۔؟।॥` plus U+037E anywhere, with closing quotes kept on the sentence. A fragment under 20 characters (East Asian wide characters count 2) or of 3 words or fewer merges into the next sentence, or into the previous one if it is last, as long as the result stays within the limit. A sentence over the provider's limit (spec table, line 478) splits at the comma nearest its middle, each part at least 40 characters, recursively, then at the last whitespace before the limit, then at a code-point boundary. Piece key: sha256(provider|voice|lang|pieceText), lower-case hex, so editing one sentence re-synthesises only that sentence. One `audio_events` entry per piece. Cost, measured: both local providers spawn a process per call (sanotts 1.5 s + 3 ms per character, phonon about 0.5 s + generation), so a typical film of 20 scenes with 2 sentences each takes about 30 s longer on sanotts and 13 s on phonon. Cloud: the same characters billed, about twice the calls.

D2 Compile input. `GET /projects/{id}/narration` (scope read) returns:
`{narration:{<sceneId>:{blocks:[{id, kind:"narration"|"dialogue", beat?, speaker, duration_ms, spans:[[startMs,endMs]...], levels:[0-255 per frame at the project fps], pieces:[{hash, ext, at_ms, in_ms, out_ms, chars}]}]}}, missing:[{scene_id, block_id, chars}], chars:{total, missing}, music:{key, ext, duration_ms}|null}`.
`at_ms` = where the piece's used audio starts inside the block; `in_ms`, `out_ms` = the used range of the piece's file (D5). `duration_ms` = the end of the last piece's used audio. `chars` = UTF-16 units of that piece's text including its joining whitespace, so offsets in the stripped block text map onto pieces; if the sum differs from the stripped text length, JS falls back to `placed: proportion`. `compile(story, audioInfo, catalog, opts)` keeps its inputs; `audioInfo` = this answer's `narration`. Levels are inline: 27000 frames at most, about 100 KB. Render jobs get the same object: `Plan.AudioInfo` computed at queue time and served in `boot.audio_info` (`listener.go:342`), so app and render compile identically. The app sends it in the `load` message (`storymaker.js:391`). Contract section 6 (first block only) and section 8 (caps) change.

D3 Narrate queue. A second `Manager` instance: `ManagerOptions{Kinds:{"narrate","music"}, Dir:"storymaker/narrate", MaxQueued:128, Workers:1}` so a running export does not block it (a shared Dir would clobber jobs.json and wipe render staging, `jobs.go:226,233`). `Enqueue` no longer hard-codes render (`jobs.go:384`); `load` keeps the manager's kinds (`jobs.go:266`). A job synthesises the missing pieces of one project, one provider call at a time; a restart marks it interrupted and a rerun continues from the cache. `POST /projects/{id}/narrate` (scope write): 409 `voice_required` when the story has no voice; if a narrate job for that project is queued or running, return it (200) instead of a second job. Handlers: a small router finds a job by id in either manager; `GET /projects/{id}/jobs` merges both; SSE keeps two revisions; `storymaker-export.js:267` filters to `kind === "render"`. Caps: `narration.max_job_chars` (20000) and `narration.max_daily_chars` (100000) for cloud providers, local ones exempt; the daily count persists in `storymaker/narrate/usage.json`.

D4 Decoding without FFmpeg. New `internal/storymaker/audio_decode.go`: WAV (PCM16, PCM24, float32, mono or stereo, WAVE_FORMAT_EXTENSIBLE, streamed size 0 or 0xFFFFFFFF, data length capped at file size) and MP3 (go-mp3: stereo s16 at the source rate; recover panics). Unknown format: `narration_failed` naming the provider. `voice.DecodeWAVPCM16Source` refuses all of those except mono s16, so it is not reused. Supertonic is forced to WAV. Facts: phonon 24 kHz mono s16; sanotts 22.05 or 24 kHz mono s16; google MP3 24 kHz; cloud formats unknown except OpenAI and xAI (MP3 by default).

D5 Envelope. For each piece, a 10 ms RMS envelope, stored as `audio/narration/<hash>.env.json` `{v:1, duration_ms, rate:100, levels:[bytes]}`, fps-free (this replaces the spec's `<hash>.<fps>.env.json`: per-piece frame envelopes drift when concatenated). Level byte = round((clamp(dBFS,-60,0)+60)*255/60). Each piece's speech span: runs above -40 dBFS, gaps under 100 ms bridged (measured: raw runs fragment into 4-5 per sentence, -50 sits on the pause floor, -30 splits words), first run start to last run end.
Block assembly, one pure Go function `AssembleBlock`, used by the `/narration` answer, `Plan.AudioInfo` and the mix: each piece plays only its used range, `in_ms` = speech start - 40 ms (floor 0), `out_ms` = speech end + 100 ms (ceiling the file), with a 5 ms fade at both trimmed edges, and pieces are separated by an explicit pause: 350 ms between sentences, 150 ms inside a split sentence. Reason: raw joins differ by provider (phonon's tails make a join 852 ms against 572 ms natural, the film 9-16 % longer; sanotts English 816 ms) and a raw hard join is safe only because its edges are silent; trimming without a fade jumps by up to -29 dBFS. The pause and margin values are first guesses for the user's ears (D20). A piece without detectable speech is used untrimmed, and its block is `placed: proportion`. Go then builds the block's `levels` (RMS per project frame over the assembled block, pauses at 0) and `spans` (the pieces' speech runs at their block positions).

D22 Cue placement. The spec's vowel-weight rule (spec line 501) is dropped on evidence: over spans it erred 581-730 ms mean against 341 ms for proportional, at every threshold (n=30, de, en, fr, es). Replacement, one JS function `cueMap(block, utf16Offset)` in a new module `cuemap.js`, used by cues and by caption lines: find the piece that holds the offset by its cumulative `chars`; time = piece `at_ms` + (offset - piece start offset) / piece `chars` x (`out_ms` - `in_ms`). A marker at a sentence start therefore lands on that sentence's speech onset within the 40 ms margin, exact by construction. A marker inside a sentence is proportional over that sentence's speech, measured about 130-190 ms mean error at comma onsets (small samples, commas with a gap only). `placed: span` when the block's pieces are measured and their `chars` sum to the stripped text length; otherwise `placed: proportion` over the block duration, as is an estimated block without audio. No per-script weights, so every script is placed the same way, and the `placed` fallback no longer depends on the script. Each cue records `placed`; the report gives `cue_precision`. Word-level alignment stays out of scope for v1. This is the concrete meaning of the user's "lands on the word".

D6 Voices endpoint per spec lines 474-488, with these facts: OpenAI list is the 13 voices alloy, ash, ballad, coral, echo, fable, nova, onyx, sage, shimmer, verse, marin, cedar (`gpt-4o-mini-tts` is hard-coded at `tts_cloud.go:21`; `tts-1` supports only 9; shutdown 2027-01-06 recorded in D21). `FetchXAIVoices` is a live client method, cached 5 min. Speech Lab: no per-call voice, the `/ready` snapshot. ElevenLabs: `url.PathEscape` for the URL and real JSON for the body (`tts.go:485-488`), both with a test.

D7 Project voice. `POST /projects {title, language?}`: with `language`, Go snapshots the active provider and voice, resolves per spec line 505, and answers 422 `narration_unavailable` with the supported languages if nothing fits; without `language`, the project gets `voice:null` as in phase 1. The app sends the desktop language and, on `narration_unavailable`, offers to create without a voice. Phase 1 stories keep `voice:null`: the voice panel preselects the active provider and one action writes the voice into the story. A cast speaker's narration and a say block use `cast[].voice`, else the project voice.

D20 Per-language voice notes need ears. Nobody here can judge speech: earshot measures and describes sound, not speech quality. Phase 2 ships the mechanism and the `not tested` mark, with notes only for facts (no voice for the language, provider limits). The listening notes wait for the user's tests. The rhythm factors stay first guesses for the same reason.

## Motion

D10 Cue lead and the walk circularity. An arrival's duration is computed from its target's position at max(previous same-target end, 0), which equals its position at the start, because only same-target beats change that track. Start = max(0, previous same-target end, marker + delay - lead). `cue_late` fires only when the previous same-target beat holds it back (spec line 413), never on a clamp at scene time 0. Targets are compared as resolved instances (`beats.js:287`), not strings.

D11 Default transition. `ApplyDefaults`: `wipe` when the environment differs from the previous scene's, otherwise `fade`; `cut` for the first scene. Reaches new scenes only. The lint still flags a stored fade between worlds. Default goldens change in 2A.

D23 Shrink to fit lives in `text.layout`, not in compile: compile has no canvas and runs before fonts (`host-core.js:279` against `:289`). The static `text_too_small` reads the style size only.

D24 Holds. Han and kana text counts as one word in `narration.js:31`; for holds, a run of CJK characters counts 1 word per 2 characters (first guess).

D25 Rhythm: calm 1.25, standard 1.0, lively 0.8, first guesses (D20). Determinism: no project seed exists among the compile inputs, so every seed comes from strings: takes from scene id, beat index and sound id; lip-sync from block id. `Intl.Segmenter`, `\p{Script}` and `normalize` vary with ICU and V8 (Chrome 128 against 156), which would break timeline identity, so compile and the wrap use generated range tables.

## Glyphs

D12 Coverage from generated data. The catalog build reads each face's cmap (Node `zlib.brotliDecompressSync` and a WOFF2 table reader, or plain sfnt; working code in `spikes/fonts/cmap.mjs` and `glyphs.mjs`) and commits `ui/img/storymaker/glyphs.json` in the delta format: `{"schema":"storymaker-glyphs/1","faces":[{"id","family","file","weight","unicode_range","max_bytes"?,"d":[gap,len,...]}]}`, faces in fallback order, first `d` value = start of the first range, then gap = start minus previous end, len = end minus start; 11 KB raw. A codepoint is covered if it is in the face's cmap and inside `unicode_range`. `glyphs.json` joins the catalog `version` hash and `--check`; `catalog.json` names it (`glyphs:{file}`), otherwise the key is unlisted. Go mirrors `LoadCatalog`: `fs.FS`, LimitReader 1 MiB, schema check, monotonic ranges, binary search. No WOFF2 code and no new dependency in Go.
Family order: `SMGreek` (Inter Greek and Greek Extended, `unicodeRange` U+0370-03FF and U+1F00-1FFF, already in `ui/fonts`, OFL, add `ui/fonts/Inter-LICENSE.txt`), `Geist`, `SMDeva`, `SMArab`, `SMCJK`, then `sans-serif`. Greek must come first with its range: Geist has 6 Greek letters and Chrome otherwise draws ω as Ω. Geist's Greek is excluded in the data. CJK is last because it also covers Latin.
Validation (`glyph_missing`, error, at the text's path, naming the character): show text, say text, bubble text, and narration text only when captions are on (burn-in override included). Check the NFC form. Default-ignorables (U+200C, U+200D and the like) are exempt, and U+2026 is always included. Emoji, Thai, Hebrew are `glyph_missing`. Code-scene text stays a minor `layout_unverified`. D15's override runs before `Validate` in `Prepare` (`render.go:157-158`), or burned captions skip the check.

D13 Fallback fonts load on need. Compile adds the faces it needs to `needs` (`compile.js:106-113`), and `ensureAssets` already filters to `needs` (`host-core.js:320`); make `host-render.js:72-76` lazy too. Keep the faces out of `catalog.fonts`, or `style.font` would accept them (`validate.go:166`). A need that misses a face draws host fonts silently (measured), so every drawn text source must feed the calculation; code-scene workers also get the faces of `voice.language`. The 8 MiB per-font cap stays, with one named exception through `max_bytes` for `NotoSansCJKsc.otf` (17 MiB), in both font paths (`host-app.js:42` checks `load` only). No subset: a subset breaks "every Han character is validated". Measured: 80-120 MiB per worker with the CJK face, 292-330 ms load per worker.

D26 Text flow in `text.js`. `fontString` takes a family list. Break opportunity between CJK characters with kinsoku (nothing like 。、，！？）」 at line start, no 「（ at line end). `breakWord` must not split surrogate pairs or Devanagari clusters (generated tables, not `Intl.Segmenter`). `fitEllipsis` trim set extended with Arabic and CJK punctuation. `ctx.direction` set explicitly per text, from the first strong character, or canvas state leaks across frames and workers diverge. Captions: 2 lines of 42 characters, East Asian wide characters count 2.

## Sound

D8 SFX set. No CC0 downloads. Rendered once at dev time with earshot (MIT): forge sounds are code-made, fits derive from CC0 recordings and keep their source licence on record (whoosh Kinoton fs-427979; click qubodup fs-167829; ding and success steffcaffrey fs-452379). 25 WAVs, 48 kHz mono PCM16, 1.06 MB, in `spikes/sfx/set/`, normalised per take to -18 LUFS loudest-50-ms with a sample-peak ceiling of -1.5 dBFS. Names and takes: whoosh 4, pop 4, click 4, ding 3, success 2, error 2, typing 6 (single keys). The build copies WAVs, never renders (no Python in the build). Source `assets/storymaker/sfx/`, output `ui/img/storymaker/sfx/`, `assets/storymaker/README.md` holds provenance with the render recipe and sha256 per WAV. `*.wav binary` in `.gitattributes`. Procedural effects in `mix.go` are not built: the dev-time render gives the same repeatability without code in production. Nobody has listened: `error` reads synthetic (p_real 0.01) and `success` is uncertain (0.6).

D27 Catalog fields. Go `Entry` gains for kind sfx: `takes[{file, dur_ms, onset_ms, peak_ms, impact_ms, l50_lufs, true_peak_dbtp}]`, `impact_ms`, `align`, `hit:{over_db, dip_db}?`, `pattern?`, `source{kind, basis, url}`. `file` = take 1. impact_ms: whoosh ~130 (peak), pop ~4, click 7.5, ding 32.5, typing ~12; success 1.2 and error ~0.5 (onset: their peak wanders). `VerifyFiles` covers takes. Thumbnails: sfx is exempt from the thumbnail rule (no image). `versionOf` (`assets/storymaker/lib/catalog.mjs:256`) hashes text with `lf()`; WAVs need a raw-Buffer path; `listExisting()` adds `sfx`. `hit`: pop over 4.5 dip 3; ding over 4.5 dip 3; success over 4.5 dip 4; error over 4.5 dip 4. whoosh, click, typing: no hit block. `sfx.typing` carries `pattern:{spacing_ms:[90,140], default_duration_ms:1200}`; compile expands it into spaced key events with seeded takes, within the beat's duration.

D9 Take rotation. Compile picks a seeded take and never repeats the last take of that sound; `audio_events` gain `take`. Go computes each event's gain: gain_db = (reference + over_db) - take.l50_lufs; over_db 0 without a hit block. Reference = the actual bed level when music is on (narration I - 12 LU + 20*log10(volume/0.25)), narration I - 12 when no music, -18 LUFS when no narration.

D28 Mix, a streaming pure-Go mixer in `internal/storymaker/render/mix.go`. A working prototype is in `spikes/mix/mixer/` (and `spikes/mixreal/`). Replaces `sidechaincompress` and `acrossfade`: those exist on both FFmpeg versions with the same options, so the reasons are exact stems, a 1000-clip graph, look-ahead and unit tests, not compatibility.
Inputs: WAVs already at 48 kHz (the SFX) are read directly; everything else FFmpeg decodes to 48 kHz stereo s16 in job staging (`-protocol_whitelist file -map 0:a:0`), cached per hash for the job. Passes: (1) stream the narration stem and the raw assembled bed into the meter; (2) stream the pre-gain mix into the meter; (3) write stems and mix. No float temp file: the meter reads `-f f32le -ar 48000 -ac 2 -i pipe:0`, measured byte-identical to the file on 8.1.1 and 5.1.9, with no added wall time at 900 s (28.8 s, 67 MiB peak; 39 s, 109 MiB on 5.1.9). Block 4800 frames.
Per-voice match (new, `evidence/mixReal.md` shape C: two speakers of different level landed at -19.66 LUFS, -17.09 with the match): before pass 1, Go computes the RMS over the speech spans per voice key (provider|voice) from the decoded samples, and each voice gets gain = loudest voice's RMS - its RMS, capped at +6 dB. It scales that voice's clips in the narration stem, so the stems still sum to the mix. A short clip needs no meter of its own this way, which keeps the spec's rule that an interjection cannot block the export. No per-sentence match: the spread is sentence character (3.8-4.8 dB), not splitting. Clips open when they start and drop when they end; the bed streams through two read windows.
DSP order, fixed by spec line 519: bed gain to the reference, ducking, carve, master gain. Ducking: feed-forward keyed by the narration stem, one block of look-ahead, attack 50 ms, release 400 ms, threshold -45 dBFS, depth 6 dB (measured narr-minus-bed under speech: 18.3 dB at 6). Carve: stateful biquad, 2.2 kHz band, -5 dB, gated by the speech spans with short ramps. Impact dips: depth from `hit.dip_db`, 80 ms, return over 0.3 s. Loop: equal-power crossfade of 2 s. Fades: music in 0.5 s, out 1.5 s (first guesses). Stems are quantised after the master gain; the mix is the clamp of the sum of the three quantised stems, so the integer null is exact.
Master gain G = min(-16 - I, -1 - TP, -0.1 - max stem peak), one formula for every film. No limiter (spec To verify "Mix limiter" closes): on real material A, B, D, E, F, H land at -16.0 to -17.6 LUFS (narration with phonon is peak-bound, its true peak sits 15.8 dB over its loudness). An sfx-only film ends quiet (-22) because its peaks bind it; accepted. A narration stem that measures `-inf` fails with `narration_failed` only when narration events exist; `-inf` otherwise gives G = 0. A film with no events and no music keeps `anullsrc` (now with `-t`) and has no stems. Meter graph: `ebur128=framelog=quiet,loudnorm=I=-16:TP=-1:LRA=11:print_format=json`, with I from ebur128's summary (`I:` line) because loudnorm under-reads short films (8 s: -19.09 against -17.5) and TP from the loudnorm JSON (last `{` to last `}` on stderr, values are strings, `-inf` handled, identical on 5.1.9 and 8.1.1). Agreement within 0.1 LU on long films. The plan must confirm the combined graph on both versions in its first mix test. Stems sum to the mix exactly before encoding only; after AAC the residual is about 18 dB below the mix at 64k and 23 dB at 192k, so the guarantee says "before encoding". Audio is AAC 192k (`ffmpeg.go:25` is 64k today).

D29 Deferred start (CRITICAL, was D6). Mixing must not run inside `onReport`: the handler is synchronous and three timers cut it (WriteTimeout 2 min `listener.go:146`, report timer 3 min `render.go:427-443`, proxy header timeout 5 min). `POST /report` validates and answers `{pending:true}` at once, closes `reportCh`, and a goroutine (no `run.mu` held) sets phase `mixing`, mixes, starts FFmpeg, the watchdog, the ingest and `driveScreenshots`, then signals `startCh`. The host long-polls `GET <base>/start?t=<token>`; Go holds at most 20 s and answers `{pending:true}`, `{start:true}` or `{error,message}`. Long-polling needs no timer in the page. One path for every story, silent ones included. The mix goroutine stops on cancel at block boundaries. All four files in staging. `host-render.js:105-110` and `:154` (dead `from_frame`) change.

D30 Frame gate. The mix has exactly round(frames*48000/fps) samples. `-shortest` is removed everywhere; `anullsrc` gets `-t`. After FFmpeg ends, in `finish()` before anything is published: `ffprobe -v error -count_packets -select_streams v:0 -show_entries stream=nb_read_packets -of csv=p=0 FILE` must equal the frame count (`render_failed` otherwise), and |audio stream duration - video stream duration| < 25 ms, because the packet count alone does not notice a wrong audio length. `Settings` gains `FFprobePath` (`render.go:64-73`).

D31 Music. Modes generated and file (file XOR track, track numeric); `validate.go:209-217` and spec lines 171, 511 stay. Generation: `tools.GenerateMusicResult`, instrumental, quota inside, budget through `IsBlocked("music_generation")` and `RecordCostForCategory` as Game Maker does. Key: generated = sha256("generated|mood|prompt"), length excluded; file = sha256("file|path|size|mtime); track = sha256("track|id|size|mtime"). Stored as `audio/music/<key>.<ext>` create-only via `Publisher.WriteStream`. `POST /projects/{id}/music {duration_ms}` (scope write) is a job in the narrate queue, kind `music`; length range-checked, from the app's last compile until phase 3's check job; a stale length is absorbed by the loop or the trim. Render 409 `music_incomplete` when the key's file is missing. Large files: `Store.ReadFile` stops at 50 MB (`service_files.go:347-353`), and a 600 s WAV is 115 MB, so add `Store.Open` over `OpenPreviewFile`.

D32 Gates. `narration_incomplete` and `music_incomplete` land in 2C, with a seeded-audio test helper, because they break tests with narrated fixtures (`storymaker_e2e_test.go`, `storymaker_parity_browser_test.go`, `browser_smoke_test.go`). Until 2C a narrated story exports silently, as it does today.

D14 Preview audio is parent-side. New module `storymaker-audio.js`: `createAudio({api}) -> {load(info, events), play(frame), pause(), seek(frame), dispose()}`. Narration and SFX: `decodeAudioData` of pieces in a sliding window (a 15-minute bed would be 345 MB decoded). Bed: `<audio>` through `MediaElementSource`; the app CSP has `media-src 'self' data: blob: http: https:` (`server.go:2300`). Schedule by `audio_events` from the `compiled` message (whitelist extended, size caps raised), driven by the `time` messages; drift above 120 ms reschedules. Ducking with WebAudio gain from stored levels. No carve in preview. The iframe stays without audio or connect access. 2B: narration only. 2C: music and SFX.
