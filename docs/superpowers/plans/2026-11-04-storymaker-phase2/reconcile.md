# Findings the review confirmed

Each was checked by a second reviewer and is fixed in the parts.

- **A scene can only be set to silent by hand-editing JSON, although the new gate relies on that escape** (important, E2d): A user on a box with no TTS provider, or with a phase 1 project that used to export silently, has narration text in a scene. After 2C the export panel blocks with 'Generate it in the voice panel', and the voice panel says no provider is ready. The only way out is to open the Code tab and type "silent": true into each scene, and nothing in the app says so. Generate gets 409 and Start stays disabled, so the user is stuck.
- **Handoff is lost when the window closes, contrary to section 8's 'a closed window cannot lose it'** (important, E3c): A user ticks Open in Video Studio on a long film (spec limit 15 minutes, render timeout up to 13,500 s), then closes the window or leaves the project while it renders. The job succeeds and the stems are published. On reopening, the export panel shows the start view: no result, no warnings, no stem or subtitle paths and no Open in Video Studio button. To hand off, the user must render the whole film again. The spec rejected browser-bound export because of exactly this weakness.
- **A queued music job can start a paid generation that nobody clicked** (important, A25c): The user clicks Generate narration, which runs for minutes. In the Music tab they pick a file, and the auto-start queues a free music job behind the narration. They then switch the mode to generated; the mode select saves at once and sets the default mood (storymaker-music.js:292-295). When the narration ends, the queued job re-reads the story, sees mode generated with no stored file, and pays the provider. No Generate button was clicked, and the mood and prompt were never confirmed. A variant: the user clicks Generate, the job waits, the user keeps typing the prompt, and the job pays for a half-typed prompt whose key no longer matches the final text.
- **A narrated code scene's length ignores its narration, so speech overlaps the next scene or is cut, with no warning** (important, S3): A code scene has 8 s of measured narration, its last tween ends at 3 s, and it does not call api.duration. D is 3.5 s, so the next scene's narration starts about 4.5 s before this one ends. The export has two voices talking at once, and settle() cuts the captions of the two blocks against each other. The report has no issue. If the code scene is last and its narration is one sentence, the film ends at 3.5 s and speech is cut with a 5 ms fade. No warning fires, because no event was dropped. The same overlap happens silently when the scene calls api.duration(5) and the narration is 8 s.
- **A period after an ordinal or abbreviation ends the sentence, which puts a pause and a separate synthesis call inside a German sentence** (important, N2): The narration is "Die Firewall wurde am Ende des 19. Jahrhunderts in einem kleinen Labor erfunden." The parts are "Die Firewall wurde am Ende des 19." (width 34, 7 words) and "Jahrhunderts in einem kleinen Labor erfunden." (width 45, 6 words). Neither is a fragment, so they become two provider calls joined by JoinSentence. The film has about 490 ms of near-silence inside the sentence, the first call ends on a sentence-final "19." with no following noun to give the ordinal its reading, and the second starts cold. The same happens with "am 3. Oktober ...", "bei ca. 20 Euro ...", "bzw.", "Dr. Müller" and "e.g." whenever the left part has more than 3 words and at least 20 columns. Dates and centuries are common in explainer narration, and German is a main language here.
- **The preview plays SFX and the bed at levels far from the export, so a mix judged in the app is wrong** (important, E2c): With the mixReal shape A material at the default volume 0.25, the export has the bed at -12 LU against the narration. The preview plays it at about -23.6 LUFS against the voice's roughly -19 to -22, which is about 7 to 10 dB too loud relative to speech. A whoosh sits at -12 LU against narration in the export and about level with it in the preview, roughly 12 dB or more too loud. A user who turns the music or the SFX down to suit the preview then gets an export where they are barely audible, and finds out only after a full render. The panel gives no hint.
- **A say block running past an explicit scene duration overlaps the next scene or is cut, with no warning** (important, S7): A scene has `duration: 3` and a say block of 5 s. The next scene's narration starts near 3 s, so two voices overlap for about 2 s, and the report carries no issue. Spec line 503 says blocks never overlap, and the same mistake on scene narration does warn. In the last scene, a one-sentence say is cut mid-word at the film end with no issue.
- **A free file or track music job turns into a paid generation with no Generate click** (important, A25c): The user clicks Generate narration, which runs for minutes. They open Music, choose File or track and pick a file. The auto job is queued behind the narration. They change their mind and select Generated by AI, and the panel sets mood upbeat-corporate. The Generate button is hidden because a job is active. When the narration ends, the queued job reads the story, sees mode generated and pays the provider. The user never clicked Generate or saw the mood and prompt summary. A narrower form exists: the route also reads the stored story, so an auto POST can land after the mode has changed.
- **Generate and Audition use the saved voice while the panel shows a different picked voice** (important, E1f): (1) The story has voice A with audio. The user selects voice B and clicks Audition: they hear voice A, conclude B sounds fine, and keep the wrong voice. (2) The user selects a voice but does not click Apply, then clicks Generate. The job synthesises and bills the stored voice, not the one on screen. (3) On a phase 1 story with voice null, the panel preselects a voice and Generate is enabled. The click answers 'Choose a voice first' while a voice is visibly selected.
- **Voices that are not installed are offered and can be auto-selected, then the job fails** (important, E1e): With Phonon and only its default voice installed, the user changes the language to French. fitDraft picks the first French voice, which is not installed. Apply and Generate lead to narration_failed with 'Phonon voice is not installed'. Nothing marked the voice before the click, and the same happens when the user picks any listed voice by hand.
