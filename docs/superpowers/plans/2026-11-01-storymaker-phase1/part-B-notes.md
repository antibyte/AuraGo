## Egress findings (spec "To verify in the plans: strict-mode capture proxy and CDP Fetch interception for worker targets")

Measured on Chrome 156 with a loopback probe server on another port:

- `Fetch.enable` on a dedicated worker's own CDP session fails (`-32601 'Fetch.enable' wasn't found`); the contract's "interception on auto-attached worker targets" is not possible. But the **page session's** `Fetch.enable` also pauses the requests dedicated workers make (fetch, XMLHttpRequest, importScripts): one page-level interception covers both realms.
- Pausing a request that carries a frame costs about 35 ms (the browser hands the whole body to the DevTools agent); enabling Fetch without pausing anything costs nothing. The catch-all interception halves the rendering rate (16 to 8.4 fps).
- `Network.setBlockedURLs` with `urlPatterns` (allow rule first, then block rules) blocks natively, on the page session and on worker sessions, without pausing. It does not cover top-level navigations and not WebSocket handshakes.
- **Design shipped (hybrid):** `Fetch` pauses only resource type `Document` (navigations: a handful per job), the native block list covers everything else on the page and on every worker that auto-attaches (`waitForDebuggerOnStart`, resumed after its list is installed; a worker that cannot be guarded is closed); `Target.setDiscoverTargets` closes any extra page target (a popup). Fallback: the catch-all pause when the browser lacks `urlPatterns` (Chrome before 126) or `GuardFull` is set.
- `TestEgressLayersEachStopTheProbe` (hostile code: `location`, `window.open`, `fetch` to a public host and to another loopback port, XHR, WebSocket, `<img>`, `<script>`, `sendBeacon`, and the same from a blob worker, plus `self.location`, `importScripts`): the control run (no layer, no sandbox) lets the probe see the requests (the test requires at least six of the eight request kinds it counts); **strict proxy alone: 0**; **CSP + sandbox alone: only the navigation (`location = probe`)** gets through, as predicted (no `navigate-to`); **CDP guard alone: 0 except the popup of an unsandboxed page**; **all layers (hybrid and catch-all): 0**, `window.open` returns `null`, and the page's own origin (`boot.json`, `importScripts(<base>/js/...)`) still works.
- WebSocket handshakes are outside the Fetch domain and the block list: CSP `connect-src` and the proxy stop them (proved in the matrix: CSP alone and proxy alone both give 0 WebSocket hits).
- **Prefix is not a secret against scene code:** the blob worker's source names the base, so a hostile scene can read the prefix and post bogus frames, errors or a report to its own job's listener. The effect is limited to that job (its own video, or a failed job); the controls above keep it off every other origin. Documented in `render/AGENTS.md`.

## Decisions (mine, not fixed by the contract)

- **Layout.** Everything but the handlers is package `render`; `internal/server` imports it, never the reverse. Seams for tests: `Deps.OpenPage`, `FrameObserver`, `ReportObserver`, `ListenerObserver`, `SessionTweak` (render); `Server.storymakerUI/Browsers/RunOverride/FrameObserver` (server). `render.NewBrowsersWithProbe` lets server tests avoid starting a browser.
- **Job manager.** `jobs.json` version 1 with `rev` counters; SSE reads `ChangedSince(project, rev)` after a coalesced signal, so a slow client never misses the final state. Retention 200 finished jobs. A damaged `jobs.json` is moved to `jobs.json.bad` and the manager starts empty. `interrupted` jobs carry error code `interrupted`.
- **Snapshot.** The story (after defaults, canonical JSON) and the code bundles are read when the request is queued and travel as the job's in-memory payload (the spec says "at start"; this is stricter: edits while a job waits change nothing). Catalog files, the four fonts and both player bundles are read from the injected `fs.FS` when the job starts.
- **Timing.** Report within 3 minutes of navigation, 10 s without a frame after `start` -> `code_error`, overall timeout reset to `RenderTimeout` once `frame_count` is known. Any `POST /error` is fatal (C's note). A hardware encoder gets 1.5 s after the first frame to exit (FFmpeg opens the encoder only after it saw a frame); a failure later in the stream restarts once with libx264 (`{restart:true}`).
- **FFmpeg.** Frames on stdin, `-protocol_whitelist file,pipe` and `-format_whitelist` per input, silent AAC from `anullsrc` (`-format_whitelist lavfi`, 48 kHz stereo, 64 kbit/s, `-shortest`), `scale=out_color_matrix=bt709:out_range=tv,format=yuv420p` + `Encoder.FilterTail()`, `Encoder.VideoArgs`, `+faststart`. Progress comes from the frame count only (no `-progress pipe:1`: FFmpeg reads at the rate the page feeds it, the pipe adds nothing). The silent track is kept so the stream layout (video + audio) is the same in all phases; Video Studio probes find audio.
- **Browser status.** `ready` only after a successful cached launch probe (10 min for success, 30 s for failure); a configured path that does not work is reported, never replaced; `can_download` + `source: "pinned"` when only the pinned Chromium is left. The first status call costs 1.5 to 7 s (a headless launch); listing projects starts a warm-up probe in the background.
- **Env of the browser.** Chrome inherits AuraGo's environment (as `homepage_annotation_capture` does); filtering it would not change the threat model (a browser escape runs as the same user).
- **Platform.** `--disable-gpu`, `--font-render-hinting=none`, `--hide-scrollbars`, WebRTC non-proxied UDP off, viewport = canvas at DPR 1; rod's leakless helper stays enabled.

## API reference for part E (exactly contract section 5, plus these details)

All errors are flat: `{"error": c, "code": c, "message": ..., "issues"?: [...]}`; middleware errors: 401 `unauthorized`, 403 `desktop_scope_required`, 403 `desktop_readonly` (mutations while read-only), 403 `storymaker_disabled`, 503 `desktop_disabled`.

- `GET /status` (read scope): `{enabled, read_only, desktop_enabled}`; when disabled only those. Otherwise also `ffmpeg:{ready, version?, issue?}`, `browser:{ready, source:"config"|"system"|"pinned"|"missing", issue?, can_download?, version?}`, `limits:{max_duration_seconds, max_scenes, max_items_per_scene, max_beats_per_scene, max_narration_chars, max_story_bytes, max_code_bytes, max_queued_renders}`, `transport`, `catalog_version`. **Export is possible when `ffmpeg.ready` and (`browser.ready` or `browser.can_download`)**; with `can_download` the first export downloads about 190 MB (phase `starting`). A disabled Storymaker answers 200 here (every other endpoint: 403 `storymaker_disabled`).
- `GET /projects` -> `{projects:[Project]}` newest first. `POST /projects {title, aspect?, fps?}` -> 201 `{project, story, etag}` (+ `ETag`, `Location`); bad body 400 `invalid_request`/`invalid_argument`. `GET /projects/{id}` -> `{project, story, etag, issues, code_scenes}` (`story` as stored, `issues` = validation of the story with defaults + `code_error` per unbundled code scene, `code_scenes` never null); if `story.json` was edited by hand into something unreadable: `story:null`, `story_text`, `issues`. `DELETE` -> 204 (cancels the project's jobs), 404 `project_not_found` when missing.
- `PUT /projects/{id}/story`: `If-Match` required (428 `precondition_required`, 400 `precondition_invalid` for a malformed value, 412 `precondition_failed` with the current tag in the `ETag` header). Body = story JSON (<= 1 MiB, else 413 `too_large`). 422 `invalid_story` with `issues` for undecodable stories (nothing saved). Validation errors (unknown asset etc.) do **not** block the save; they come back in `issues`. 200 -> `{etag, issues, defaults_applied, story}` (story after defaults, the canonical form that was saved).
- Code: `GET .../scenes/{id}/code` 404 `code_not_found` when there is no source; `PUT` needs `If-Match` or `If-None-Match: *` (428 otherwise), body <= 64 KiB (413), 200 `{etag, ok, errors:[{line,column,message}]}` (a syntax error saves the source, `ok:false`). `GET .../bundle` 404 `bundle_not_found` when the last save failed. Scene ids are slugs (400 `invalid_id`). Both GETs answer `text/javascript`, `nosniff`, a `sandbox` CSP and an `ETag`.
- `POST /projects/{id}/render`: `If-Match` = story etag (428/400/412 as above), optional `Idempotency-Key` (1-128 printable chars, else 400). 202 `{job}` (a replay of the same key and etag returns the same job, also 202; the same key with another etag: 409 `idempotency_conflict`). Refusals: 422 `invalid_story` (+issues) or `code_error`, 409 `ffmpeg_unavailable`, 409 `browser_unavailable` (message = the status issue), **429 `busy`** (16 waiting).
- Jobs: `GET /jobs/{id}` -> `{job}`; `POST /jobs/{id}/cancel` -> 200 `{job}` (also for a finished job; `desktopStop`, works while read-only); **`GET /projects/{id}/jobs` -> `{jobs:[newest first]}` (addition)**. Job = `{id, project_id, kind:"render", status, progress 0..1, phase, frames_done, frames_total, output?:{path,size}, error?:{code,message}, created_at, updated_at, started_at?, finished_at?}`; error codes: `invalid_story`, `browser_unavailable`, `ffmpeg_unavailable`, `render_failed`, `render_timeout`, `cancelled`, `code_error`, `interrupted`, `storymaker_disabled`. Phases: `starting` (browser, download), `compiling`, `rendering`, `encoding`, `writing` (`mixing` is phase 2). `output.path` = `Documents/Storymaker/<id>/exports/<slug>-<job8>.mp4`; `exports/<job id>.json` holds title, frames, fps, size, encoder, transport, catalog version, seconds.
- `GET /projects/{id}/events`: SSE; comment `: storymaker events` first, then `event: job` / `data: {"job":{...}}` for the project's latest five jobs (oldest first), then every change (progress throttled to about 7 per second), `: ping` every 15 s. Use `fetch`/`EventSource` with the session cookie.
- `GET /player`: HTML for the sandboxed iframe, CSP exactly as the spec with the request's origin (host validated; `https` when TLS or a trusted proxy says so), `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `X-Frame-Options: SAMEORIGIN` (the middleware leaves it off for this path). Needs only the session cookie. Disabled -> 403 `storymaker_disabled`.

## Contract deviations

1. **CDP interception on worker targets** is impossible in Chrome 156; shipped the hybrid guard described above (page-level `Fetch` for navigations, `Network.setBlockedURLs` natively for the rest, also on workers). Same guarantee (three independent layers, proven by test), 2x faster.
2. **Contract 7 assumes the preflight of `POST /frame` is cached.** For an opaque-origin page Chrome 156 sends a preflight before every frame. The listener therefore also accepts the frame number as `?n=` and the type `text/plain` (CORS-simple, no preflight); the player change that uses it is task B15 (request to C).
3. `boot.json` gains `frame_deadline_ms` (5000) for the page's per-frame deadline (ignored by today's page).
4. Browser status has `can_download` and `version` beyond `{ready, source, issue}`; the pinned Chromium is downloaded by the first export, not by a status request.
5. Render snapshot of story and bundles at queue time (stricter than "at start").
6. Extra endpoint `GET /projects/{id}/jobs`; SSE replays the latest jobs on connect (E asked for it); cancel of a finished job answers 200 with the job, not an error; `GET /status` answers 200 `enabled:false` when disabled.
7. Silent AAC track decided (kept); progress by frame count only (no `-progress pipe:1`).
8. Job error codes `interrupted` and `storymaker_disabled` added to the spec's list; the 10 s watchdog is `code_error` as the brief says.
9. `Store.Remove` deletes folder trees (A's note), `WriteFile` creates parents; both implemented in `storymakerStore`.
10. Config PUT validation (A's open item) is done: `NormalizeStorymakerConfig` is called in `config_patch.go` and `config_handlers_main.go`, with a test per path that proves the config file stays untouched on a bad value.
