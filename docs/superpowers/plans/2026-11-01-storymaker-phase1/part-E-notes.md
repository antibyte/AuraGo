## The app in one page

- **Start screen:** list (newest first), new project (title + format 16:9 / 9:16 / 1:1), delete through the desktop `confirmDialog`.
- **Editor:** toolbar (back, title, format badge, save state, Storyboard | Code tabs, issues badge, Export), banners (read-only, conflict, preview unavailable, export unavailable), scene strip with player thumbnails (add scene / add code scene), stage (player iframe in a box that keeps the aspect ratio) with transport (play/pause, clock, scrubber with one block per scene, hatched for code scenes, pointer drag, arrows, Home/End), side panel with Scene (inspector) and Library tabs, issues panel, live status line.
- **Inspector:** environment, time of day, narration, entry transition (disabled for scene 1), duration (automatic or seconds), people and props in the scene (remove), move up/down, delete. Library: People / Props / Places with search; a card adds an actor or prop to the selected scene or sets the environment. Code scenes have no environment or library.
- **Code tab:** story.json and every code scene in the vendored CodeMirror (the same dynamic import as Docker Manager; a text area stays when it cannot load); problems list with line and column, marks in the gutter; drafts survive tab and file switches.
- **Export:** a popover that lists FFmpeg and browser state, blockers (read-only, FFmpeg, browser, story errors, longer than the limit, preview not ready), starts, shows phase / percent / frames, cancels, and ends in the output path with "Show in Files" and "Copy path".
- **States:** disabled (403 `storymaker_disabled` or `status.enabled=false`), signed out (401), no scope, load failure with retry, read-only (ctx.readonly, `status.read_only`, the `aurago:desktop-policy` event, a 403 `desktop_readonly` on save), no FFmpeg, no browser, conflict (412).

## Decisions (mine, not fixed by the contract)

- **Module split and namespace.** Eleven classic scripts hanging off `window.StorymakerParts` (`S`); the root `storymaker.js` loads last and publishes `window.StorymakerApp = {render, dispose}`. State lives in one `inst` object per window with a small event bus (`story`, `selection`, `report`, `time`, `thumb`, `issues`, `status`, `readonly`, `job`, `catalog`, `conflict`, `tab`); the views subscribe and repaint themselves.
- **No raw HTML anywhere.** `S.el(tag, attrs, ...children)` has no html option (it throws), icons are built with `createElementNS`, every dynamic string is `textContent`. The guard test also forbids template strings, `eval`, dialogs, `localStorage` and `document.cookie` in the app modules.
- **Save pipeline.** `inst.editScene(id, fn, {immediate})` clones the story, applies `fn`, replaces `inst.story` and saves with If-Match: 700 ms debounce for typing, immediate for selects and structure, one save in flight (`inst.saving`), a newer local edit during a save triggers another round. The server's story (defaults applied) replaces the local one only when nothing newer was typed, so a typing user is never overwritten; controls that have the focus are never replaced either. 412: banner with Reload and Keep mine (`overwrite` fetches the stored etag and saves over it). 422: the text stays, the issues are shown. `desktop_readonly`: the window turns read-only.
- **Player loading.** The parent builds `load` itself: `story`, `catalog`, `assets` = the rig, `fonts` = every face of the story's font name (four Geist faces, about 180 KB), `code_bundles` of every code scene (a missing bundle is simply absent and the player reports the scene), `format {aspect, fps, width}` with width 960 / 720 / 540 for 16:9 / 1:1 / 9:16 (the player canvas of the preview, not the export size). A story or code-scene change is saved first, then `load` is sent again 250 ms later with the frame to resume at. `need_assets` is answered by `S.createAssets().resolve`; the allow-list is `catalog.json`'s own file lists.
- **Thumbnails are asked after the first `time` message that follows a compile**, one at a time (the selected scene first, width 192). The host posts `compiled` before its assets arrive and answers an earlier `thumb` with `error {code:'readiness'}`; the first `time` is the "ready to play" signal of part C's notes. Bitmaps are cached per scene id and closed when replaced.
- **Frames and selection.** Clicking a scene seeks to 40 percent into it (the thumbnail frame); while playing the strip follows the playhead (not for 600 ms after an explicit selection). Scrubber blocks are absolutely positioned from `start_frame`/`end_frame`, so transition overlaps overlay each other.
- **Issues.** The list is the union (dedupe by severity, code, path, message) of the server's answer, `compiled.report.issues`, `report.unverified` (minor `layout_unverified` of code scenes) and run-time code-scene errors from the player's `error` messages; `narration_missing` is hidden (phase 1 renders are silent); the toolbar badge counts errors and warnings, minor notes appear in the list only. The text of an issue is `storymaker.issue.<code>` (the 19 codes of the contract, a test pins the list) plus the server's English `message` and `fix` as detail. Each row selects its scene and, with a path, opens story.json at the field.
- **Code tab details.** Pointer to position: `S.model.locate` walks the JSON text (strings with quotes and braces, nesting, a missing field falls back to the deepest value that exists). Saving story.json sends the raw text; on success the editor shows the server's canonical text if the text was not edited meanwhile. A code scene that has no source yet (GET 404) is offered as the starter program and created with `If-None-Match: *`; adding a code scene writes the starter source first, then saves the story that names it, then opens the tab. After a code save the issues and the bundle status are refreshed from `GET /projects/{id}` and the preview is reloaded when the bundle succeeded.
- **Inserting people and props.** The cast member of a character is `char.<name>` without the prefix (`office-woman-1`); an existing member with that character is reused; its `name` is the localized catalog name at insertion time. The same cast member twice in one scene is refused (the validator calls it a duplicate id). A prop goes to the first free base spot (right, left, far-right, far-left, center) of the scene's environment.
- **Export.** `start()` flushes edits first (a conflict stops it), then `POST /render` with `If-Match` = the story etag and a fresh `Idempotency-Key`. The job is followed through the project's SSE stream (`event: job`, `{job}` or a bare job) and a 2.5 s poll of `GET /jobs/{id}` that runs only while a job is active. A job of another window (active) is adopted; finished jobs of other starts are ignored. The result dir is the path up to the last slash, opened with `ctx.openApp('files', {path})`.
- **Layout.** The window is a size container: below 940 px the strip becomes a row above the stage, below 640 px the side panel is a sheet under it, the export panel becomes a bottom sheet; the Code tab takes the whole body (strip and inspector hidden). `@media (pointer: coarse)` raises hit areas to 44 px.
- **Registration details.** Permissions `files:read`, `files:write`, `notifications` (informational), category `creative`, `Requires: ["storymaker"]`, `open_maximized`, `logo_path` `/img/desktop-icons/storymaker.svg`; the icon value `storymaker` is not in `desktopPreferredIconNames` or any icon theme (as for ECalc), so every theme shows the logo.
- **Config block.** After Retro Games: toggle, two numbers (60-14400, 10-3600; a test pins them to `internal/config/storymaker.go`), the browser path, the transport select (automatic, PNG, WebP, RGBA, Screenshot) and "Check export setup", which never runs against unsaved settings and reads `GET /api/desktop/storymaker/status` (FFmpeg and browser ready; names what is missing).
- **Tests.** The tour is `storymakerTour(t, backend)` with the interface `storymakerBackend` (`projectIDs`, `storedStory`, `advance`, `watcherCount`, `joined`, `body`); `storymakerFixture` implements it on top of the real `internal/storymaker` package (a `MemStore`, `DecodeStory`, `ApplyDefaults`, `Validate`, `CanonicalJSON`, the esbuild bundler, `CodeSceneIssues`) and fakes only the capabilities and the render job (stepped by `advance()`, event stream included). The page timeout of the desktop harness (30 s) is lifted to 3 minutes for the tour (`CancelTimeout().Timeout(...)`).

## What the other parts must do or know

**Part B (server).** The app consumes exactly contract section 5. In detail:
- `GET /status`: `{enabled, read_only, ffmpeg:{ready, version?, issue?}, browser:{ready, source, issue?}, limits:{max_duration_seconds, max_narration_chars, max_scenes}, transport, catalog_version}`. **Please add `limits.max_narration_chars`** (A's default 1500). The app shows `issue` as text and does not interpret `source` beyond `config|system|pinned`.
- `POST /projects` answers `201 {project, story, etag}` (story as a JSON object); `GET /projects/{id}` answers `{project, story, etag, issues, code_scenes:[{scene_id, ok, errors:[{line,column,message}]}]}`; `PUT .../story` answers `{etag, issues, defaults_applied, story}`, `412` for a stale tag, `428` without `If-Match`, `422 {error:"invalid_story", code, message, issues}` for undecodable stories (the app shows the issues and keeps the text).
- `GET .../scenes/{id}/code` must answer `404` when there is no source (the app then offers the starter program and creates the file with `If-None-Match: *`); `GET .../bundle` `404` when the last bundle failed.
- Render refusals carry the code of the job error they stand for (`ffmpeg_unavailable`, `browser_unavailable`, `invalid_story`, `busy`, `storymaker_disabled`) in the flat body; the app maps `code` (`busy` or 429 for a full queue).
- Events: `event: job` with `data: {"job": {...}}` (a bare job object also works). Please send the active job's snapshot when a stream opens, so a window opened during a render shows its progress at once (the app also polls `GET /jobs/{id}` every 2.5 s while a job it knows is active, but it learns about a job only from the render response or the stream). A `job.project_id` that is not the open project is ignored.
- `GET /player` is an iframe navigation: the browser sends cookies and nothing else, so it must not depend on a custom request header; add it to `allowDesktopIframe`; CSP exactly as the spec (the iframe must not be able to load it as a top-level page).
- The capability `storymaker` in `desktopCapabilities.HasCapability` (the manifest's `Requires`), the config PUT normalisation (`NormalizeStorymakerConfig`, part A's open item) and the config patch path for `storymaker.enabled` and `storymaker.render.{timeout_seconds,max_duration_seconds,browser_path,transport}` (the UI writes those data-paths; the browser test `TestConfigStorymakerBrowser` proves the page sends them in the PUT body).
- Output path: `job.output.path` is the desktop path `Documents/Storymaker/<id>/exports/<slug>-<job8>.mp4`; the app opens its directory in Files.

**Part C (player).** No change needed. One usage note for the host: an early `thumb` (before the first draw) is answered with `error {code:"readiness"}`; the app avoids it by asking after the first `time` message following a compile. If the host could queue such a request until its assets are in, the app could ask right after `compiled`. The app accepts `compiled.report.unverified` and shows it as minor notes.
