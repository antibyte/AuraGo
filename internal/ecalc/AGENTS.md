# ECalc Domain

## Purpose

`internal/ecalc` is the engine of the ECalc Desktop app, an electronics formula collection: an embedded declarative catalog (YAML), a small safe expression language, unit parsing and formatting, E-series lookup, a rule propagation solver, the table and code items and the localized catalog JSON. It has no server dependency; the HTTP route, the Desktop app and the agent tool `ecalc` all use it directly.

## Ownership

- Own `internal/ecalc/` and its tests. File map:
  - `expr.go`: lexer, parser, AST (`Node`, `Sexp`), `Eval`, `Deps`, `ParseFormula`.
  - `units.go` + `catalog/units.yaml`: prefixes, dimensions, explicit, non-linear and radix units, unit aliases, `Parse`, `ParseList`, `Format`.
  - `eseries.go`: IEC 60063 tables, `Nearest`, `Combine` (standard-value combiner), `roundSig`.
  - `solve.go`: `Solve`, `SolvableSets`.
  - `catalog.go` + `catalog/categories.yaml` + `catalog/calculators/*.yaml`: schema (including the var/derived `units` whitelist, the choice option `ignore` list, the `finder` and the `chart`), strict `Load`, `Default()` (embedded, validated once).
  - `items.go`: what the three item kinds share (strict list reading, the id space, common fields).
  - `tables.go` + `catalog/tables/*.yaml`: the table type (typed columns, SI rows, key, finder), its loader, `Lookup`/`LookupGE`/`Interp`, the table items of the catalog JSON (their `generate` is the generator of a formula-derived table or ""; the page needs it to tell computed cells from transcribed ones).
  - `tablefuncs.go`: the table functions of the expression language (`lookup`, `lookup_ge`, `interp`), their load-time resolution over the choice aliases, the finder checks, `Calculator.EvalEnv`.
  - `tablegen.go` + `catalog/tables/generated.yaml`: the formula-derived tables (`awg`, `ipc2221`, `eseries_e24`, `eseries_e192`).
  - `codeitems.go` + `catalog/codes/*.yaml`: the code items and the code kind registry (`RegisterCodeKind`; the kinds are in `codes.go`).
  - `codes.go` + `codes_bands.go`, `codes_smd.go`, `codes_capacitor.go`, `codes_ceramic.go` + `catalog/codes/*.yaml`: the five component code kinds (`resistor_bands`, `inductor_bands`, `smd_resistor`, `capacitor`, `ceramic_temp`) registered with `RegisterCodeKind` in `init`; their tables are the `data` of the code items; `Catalog.Decode(kind, code)` and `Catalog.Encode(kind, EncodeRequest)` return a `CodeResult` or a `*CodeError`.
  - `localize.go`: `LocalizedJSON(lang)`, ETag, per-language cache.
  - `query.go`, `query_items.go`, `query_table.go`, `query_codes.go`: the read-only query API of the agent tool (English output, no server dependency): `Search`/`SearchAll`/`Overview` over calculators, tables and codes, `ResolveItem`, `Describe`, `DescribeTable`, `DescribeCode`, `Calculate`, `Check`, `QueryTable` (rows, filter, paging, one `exact`/`ge`/`interp` lookup), `QueryDecode`/`QueryEncode` (wrappers of `Decode`/`Encode`), `QueryError`.
  - `yamlutil.go`: strict YAML decoding helpers.
  - `testdata/vectors/core.json`, `testdata/vectors/calculators/<id>.json`: shared vectors; `testdata/vectors/tables/<table id>.json`: the cells and lookups of every table; `testdata/vectors/codes.json`: the decode, encode and error cases of the codes; `testdata/catalog.en.json`: generated snapshot.
- Owned elsewhere: `GET /api/ecalc/catalog` and its audit contract (`internal/server`, `internal/audit`), the Desktop registration (`internal/desktop`), the app, schematics and the JavaScript mirror (`ui/js/desktop/apps/ecalc/`, `ui/css/desktop-app-ecalc.css`, `scripts/test-ecalc-core.mjs`), the manual chapter (`documentation/manuals/*/32-ecalc.md`) and the translated app strings (`ui/lang/desktop/*.json`). The agent tool is `internal/tools/ecalc.go` and `internal/agent/native_tools_ecalc.go`. Pinouts are phase 4 of `docs/superpowers/specs/2026-11-01-ecalc-design.md`.

## Local Contracts

- Every value is stored and solved in SI base units. Display units and prefixes exist only in `units.yaml`, `Parse` and `Format`.
- A calculator is declared, never coded: `vars` (ordered), optional `choices`, `dof`, one explicit `rules` expression per direction (a list gives alternatives; the first whose names are all known wins), `derived`, `checks`, `formula`, optional `schematic`. The engine does no symbolic algebra. Exactly `dof` input-capable variables carry a default, and the default inputs must be one of the solvable input sets.
- `Load` is strict (unknown YAML fields are errors) and reports every problem at once. Item ids are unique across kinds, `name` is written in all 16 desktop locales (`Locales`), `doc`, variable and derived names and check warnings in English and German (other languages fall back to English), and every item has a `source`.
- The expression language is `expr.go`: a fixed function whitelist (`sqrt ln log10 exp sin cos tan atan abs round floor ceil min max if sum par`; `floor` and `ceil` round towards minus and plus infinity), no assignment or loops, IEEE-754 doubles (division by zero gives `+-Inf`/NaN, never an error). Adding or changing a function, operator or unit rule is a change to the Go code, the JavaScript mirror and the shared vectors together.
- Go/JS parity: the expression language, units, E-series and solver exist twice, here and in `ui/js/desktop/apps/ecalc/` (`ecalc-expr.js`, `ecalc-units.js`, `ecalc-eseries.js`, `ecalc-solve.js`). Both run the same vectors; `scripts/test-ecalc-core.mjs` (`npm run test:ecalc`) runs them against the JavaScript side. Behavior that can differ between the languages is pinned by a vector: `roundSig` rounds exact ties away from zero like `Number(x.toPrecision(n))`, `round` is half away from zero, `if` takes the else branch for NaN, `fmtNum` writes numbers like `String(x)`.
- Input rules of `Parse`/`ParseList` (mirrored in `ecalc-units.js`, pinned by `core.json`): the text may be at most `MaxValueLength` (64) characters for a value and `MaxListLength` (256) for a list, an item of a list at most 64 (UTF-16 code units; the app's fields carry the same `maxlength`); longer text is a parse error before any pattern runs. Every parsed value must be finite (`1e400` is an error) and, after the unit conversion, 0 or of a magnitude within `MinMagnitude` 1e-300 .. `MaxMagnitude` 1e300 (`1e301` and `1e-301 V` are errors, the same parse error), which keeps the combiner, the chart axis and the E-series lookup away from denormals and overflow. List items are separated by `;`, white space and commas that are not followed by a digit (a comma before a digit is a decimal comma). `4R7` reads only on a dimension with the alias `R`.
- Dimensions of `units.yaml` (order significant, the unit dropdowns follow it): voltage, current, resistance, power, charge, energy, number, gain, then capacitance, inductance, frequency, time, length, area, temperature, tempdiff, thermal_resistance, resistivity, tempco, ratio, angle, baudrate and integer. Energy (n µ m "" k M) and charge (n µ m "") carry the n and µ prefixes, so capacitor energies read 1.25 µJ and gate charges 47 nC. Temperature has the offset units degC and degF (non-linear `to`/`from`); a temperature difference is the separate dimension `tempdiff`, whose units only scale. Length and area carry the AWG unit (ASTM B258: diameter 0.000127 m x 92^((36-n)/39), AWG 0 = 8.251 mm, AWG 10 = 2.588 mm and 5.261 mm2, AWG 36 = 0.127 mm; the area unit is the cross-section of that diameter) and `oz` is the copper weight (35 um); the length units end `mil in ft oz AWG mm`.
- An explicit unit may list `aliases`: further spellings that `Parse` accepts behind a number exactly like the symbol (`25degC`, `2.5mm2`, `60dBuV`), longest spelling first. Aliases are never shown. Every spelling of a dimension (base symbol, dimension aliases, unit symbols, unit aliases) belongs to one thing only; `Load` rejects a clash and an empty alias.
- The integer dimension (`integer: true`) holds whole numbers from 0 to 2^53-1 (9007199254740991) and has radix units only (`radix: 2|8|10|16`: dec, hex, bin, oct; no factor, to, from, aliases, prefixes or positive flag). `Parse` with a radix unit reads an optional `0x`/`0b`/`0o` prefix of that base (either case; decimal has none), then digits of the base (hex either case) with `_` and blanks between digits (not at either end), no sign and no SI prefix; a value above 2^53-1 is a parse error. Without a unit an integer field reads an ordinary decimal number. `Format` ignores the significant-digit setting: dec plain digits, hex `0x` plus upper-case digits in groups of four from the right (`0xDEAD_BEEF`), bin `0b` in groups of eight, that is by byte (`0b11111111`, `0b1_00000000`), oct `0o`, no unit symbol; every text `Format` writes is at most 61 characters (the largest value in binary), so it is within the 64 characters `Parse` accepts and reads back to the same value (`units_roundtrip` vectors); a value that is not a whole number in range gives "" (no unit selected: decimal digits, or the ordinary number text when the value is no whole number). `Solve` reports `range` for an integer-dimension variable that is not a whole number in 0 .. 2^53-1.
- Schema fields of phase 2: a var or derived quantity may carry `units` (the display units its dropdown offers; "" is the base symbol with automatic prefixes, every other entry an explicit unit of the dimension, no entry twice, `unit` must be in the list; empty means all, JSON `"units": []`). A choice option may carry `ignore` (primary variable ids the option does not use; the page dims them, the solver is unchanged, JSON `"ignore": []`). A calculator may carry `finder: combine` (JSON `"finder": ""|"combine"`): exactly one scalar resistance variable and `dof: 1`, and `formula` may then be empty because the page shows the combinations instead. A calculator may carry `chart: {x, y, to, samples}` (JSON `null` or an object): x is a scalar variable, y a rule target or derived quantity with an alternative that uses x, `to` an expression over known names that does not use x, `samples` 11 to 401 (101 when unset); the chart plots y over x from 0 to `to`.
- `Combine(series, target, limit)` (JavaScript `ECalcCore.eseries.combine`, entries `{kind, r1, r2, value, devPct}`; JSON `dev_pct`): the single nearest standard value first (kind `single`, r2 0), then up to `limit` series pairs (r1 >= r2, value r1 + r2, both values in [target/1000, target]) and up to `limit` parallel pairs (r1 <= r2, value r1*r2/(r1+r2), both in [target, 1000*target]). Candidates are series mantissas x 10^k rounded to 3 significant digits. Each group is ordered by |deviation| (deviations that agree to 1e-9 percent are equal, so floating-point noise cannot reorder exact hits), then r1, then r2; a pair appears once. A limit below 1 leaves the single entry and a limit above `ComboMaxLimit` (1000) counts as 1000. The catalog item `eseries_combiner` (basics) uses it; its vector file carries `combos` that are checked against `Combine` and the JavaScript mirror, and only a `finder: combine` calculator has them. `Nearest` and `Combine` refuse a value below the smallest normal double (2.2250738585072014e-308, where `math.Log10` is wrong), and a group whose range bound is not usable (`target/1000` below that, `target*1000` beyond the doubles) is skipped, so the decade loop is always bounded (vectors for 1e306, 1.8e305, 1e-321, 1e-322).
- `LocalizedJSON` normalizes the language (unknown or empty means `en`) and caches by the normalized language, so the cache never exceeds the 16 locales; the body and ETag of `en`, `xx` and `""` are identical. Collections in the JSON are never `null`.
- Content honesty: `source` names a standard by number or a well-known work at book or chapter level only, never an invented page, URL or application-note number. Every rule direction is covered by at least two hand-checked sets (two per option of every choice); expected values come from exact arithmetic, a definition or a published constant, never from running the solver. Every calculator must pass the round-trip test (defaults, then every solvable input set, for every choice option).
- E-series: E3 to E24 are the IEC 60063 hand-picked values; E48 and E96 are 10^(k/N) rounded to three digits; E192 is the same except 9.20 at index 185. `eseries_tables` in `core.json` publishes them for the JavaScript mirror.
- The agent tool reads the catalog only through `query*.go`. A bare number in a request is in the variable's default display unit and list items carry their unit without a space (`ParseList` splits at white space). `Calculate` solves from the first solvable set (catalog order) inside the given variables, lists the other given values that differ from the computed one by more than 1 % as contradictions, fills the defaults of variables an option ignores only when the given values are not a solvable set, and adds `combos` for `finder: combine`. Ids of calculators, variables, choices and options stay inside `^[a-z][a-z0-9_]{0,31}$` (calculators 63) because the desktop bridge drops longer ones (`TestCatalogIDsFitTheDesktopBridge`). `TestCalculateEveryCalculatorFromItsDefaults` re-solves every calculator from its defaults.
- Item kinds: `Load` reads `calculators/`, `tables/` and `codes/` (sorted, in that order); `kind` must match the directory; ids are unique across the kinds, `^[a-z][a-z0-9_]*$`, at most 63 characters; calculators use the calculator categories, tables the category `tables` and a `group` (`conductors`, `components`, `materials`, `general`), codes the category `codes`.
- Tables: columns have a `dim` (a dimension or `text`), a cell `unit` (`""` = SI, otherwise an explicit unit) that is also the default display unit, and a `units` whitelist with the semantics of a variable's; numeric cells are finite numbers or `null` and are converted to SI at load, text cells are strings (quoted, language-neutral) or `{en, de}`; the key column (first unless `key`) is filled and unique; `generate:` replaces `columns` and `rows`. A row that is no data row (the per-volt row of the IPC-2221 spacing tables, whose length columns hold millimetres per volt) has no value in the numeric columns that lookups, `lookup_ge` and `interp` run over (its voltage band is empty) and is selected through a marker column (`lookup_ge(T, per_volt, 1, col)`); the key of such a table is a text column (`band`), so that no numeric lookup can reach the row by its key either. A table's finder names a calculator, a numeric column, a variable or derived quantity of the same dimension, and fixed choices under which the calculator's table functions name the table.
- Table functions: `lookup(T, C, key)` (key column numeric, match within 1e-9 relative), `lookup_ge(T, C, x, OUT)` (first row in table order with `C >= x`, no tolerance) and `interp(T, X, Y, x)` (strictly monotonic `X` over the rows where both are filled, exact at the nodes) give NaN, not an error, when nothing matches. The names `T`, `C`, `X`, `Y`, `OUT` are no variables (`Deps` skips them); a choice option may define aliases with `refs: {alias: id}` (every option the same aliases, each alias used, each a reserved name), and `Load` resolves every call for every combination of the options of the choices whose aliases it uses. Table functions are not allowed in a chart's `to` or in a unit conversion. Adding or changing one is a change to Go, `ecalc-expr.js` / `ecalc-tables.js` and the vectors together.
- Table vectors: every table has `testdata/vectors/tables/<id>.json` with at least three cells (five for a generated table) that name their source in `ref`; the file name is the table id and a file without a table fails.
- Table and code sources: `documentation/ecalc-sources/` keeps the research behind the tables and codes (sources with URLs, cross-checks, why a cell is empty, where the catalog deliberately differs). A changed value updates that record, the YAML and its vector together.
- Component codes: the tables (colours, digits, multipliers as exponents of ten, tolerances, letters, voltage codes, class tables) are data in `catalog/codes/*.yaml`; Go and `ecalc-codes.js` hold only the rules. A symbol that the research marks UNVERIFIED or that a single source lists is not in the data; the decoder answers `unsupported: ... is not cross-checked` (the data keeps the bare symbol in `not_cross_checked`). Resistor colours follow IEC 60062:2016 with the older tolerance reading as a warning; the voltage codes are a maker convention and say so in a warning.
- Code errors are `*CodeError` with the code `invalid_code` (the text to decode is malformed), `invalid_value` (an encode field cannot be read or contradicts another) or `unsupported` (not decodable or not codable); the message is English and the prefix `code: ` only appears in `Error()`. A result's `Value` is SI (NaN, JSON `null`, when the kind has none), its field texts are language neutral and its names and warnings English.
- Encode replaces a value by the nearest standard value of the series its tolerance implies (20 % E6, 10 % E12, 5 % E24, 2 % E48, 1 % E96, finer E192; below 5 % the E24 values count as well) and says so in a warning; Go and JavaScript build numbers from digits (`codeDecimal`, `codeScaleDec`) so that both give the same bits. Adding or changing a kind, a rule or a message that a vector pins is a change to the Go code, `ecalc-codes.js` and `codes.json` together.
- Query API of tables and codes: `SearchAll` ranks the three kinds together (equal ranks keep calculators, then tables, then codes) and `Overview` leaves out categories without items. The id of an item of another kind answers `not_a_calculator`, `not_a_table` or `not_a_code`. `QueryTable` formats the cells in the column units (a column with an empty `unit` writes each number with its own prefix): a cell of a generated table with 4 significant digits, a cell of a transcribed table (no `generate`) with up to 9 (`transcribedSig`; the shortest decimal prints, so a published number is never shortened: 434.79 MHz, 2.4835 GHz, never 434.8 MHz), a result computed by `interp` always with 4. It adds the SI numbers rounded to 12 significant digits, limits `filter` to `MaxFilterLength` (128) characters, an item `id` (and the `kind` of decode and encode) to `MaxIDLength` (256) characters (a longer one is the unknown-id error at the top of `lookup`, `lookupTable`, `lookupCodeItem` and `ResolveItem`, before the search for close matches, and is not echoed) and the page to `MaxTableLimit` (50) rows, and answers a lookup that finds nothing with `found: false`, not with an error. `ge` is the row with the smallest cell that is still at least the value (equal cells: the first in table order), which is the first qualifying row on a column that rises and the smallest fit on a falling one such as the AWG diameters (AWG 18 for 1 mm, not 4/0); it differs from the expression function `lookup_ge`, which stays the first row in table order because the finders rely on it. `interp` needs a strictly monotonic x column. `QueryDecode`/`QueryEncode` accept a code kind or the id of a code item, keep the code of a `CodeError` and leave NaN values and empty lists out of the JSON (an embedded `CodeResult` would bring its `MarshalJSON` along).

## Work Guidance

- To add or change a calculator: edit `catalog/calculators/*.yaml` (quote every expression and text string; use the micro sign U+00B5 and the Greek omega U+03A9, never the look-alike code points), add or update `testdata/vectors/calculators/<id>.json`, run the tests, regenerate the snapshot with `go test ./internal/ecalc -run TestCatalogSnapshot -update` and review its diff, then update the UI schematic id and the manual when the change is visible to users.
- Every file in `testdata/vectors/calculators/` is `<calc>.json` and names a calculator of the catalog (`TestCalculatorVectorFilesNameACalculator`, and the same check in `npm run test:ecalc`), so writing the vectors before the YAML goes red. The tests that count the catalog follow it (the basics category is pinned by id, the item total by the catalog itself), so adding a category file does not break them.
- `testdata/catalog.en.json` is generated; never edit it by hand. A stale snapshot fails `TestCatalogSnapshot`.
- Run `gofmt` on Go files before closeout.

## Verification

- `go test ./internal/ecalc -count=1` runs the unit tests, the shared vectors (calculators, tables and codes), the generated tables, the round trip over all calculators and the snapshot check; `TestQueryTable*`, `TestLookup*` and `TestQuery{Decode,Encode}*` run the table and code queries against the generated tables, the fixture tables and the code vectors.
- `go vet ./internal/ecalc/` and `gofmt -l internal/ecalc` must print nothing.
- `npm run test:ecalc` runs both parity scripts, `scripts/test-ecalc-core.mjs` and `scripts/test-ecalc-codes.mjs`, which run the shared vectors against the JavaScript mirror.
