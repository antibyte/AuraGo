# Docker Manager hosts

## Purpose and ownership

`internal/dockerhost` owns the Docker Manager's host registry (the local Engine and remote Engines over plain TCP, TLS, mutual TLS or SSH), their vault secrets, one Engine client per host, connection health, and the Engine reads and container actions that `/api/docker-manager` serves. `transport/` owns the TLS client configuration and the SSH Engine dialer that Invasion shares. The HTTP API lives in `internal/server`, the desktop app in `ui/js/desktop/apps/docker-manager*.js`; their contracts are in the design `docs/superpowers/specs/2026-10-26-docker-manager-design.md`.

## Local contracts

- The built-in host `local` is synthesized from `docker.host` (the OS default when empty), is never stored and cannot be changed or deleted (`ErrLocalHostFixed`). Remote hosts live in table `docker_hosts` of `<data dir>/docker_manager.db` with ids `h_` plus 12 hex characters. Names are unique ignoring case and never "Local". `ValidateHost` judges a `Host.Normalized()` host: names have no control characters, `stacks_dir` and `host_socket_path` are absolute POSIX paths without blanks, control characters, `: , = ' " ` and backslashes (they end up in bind-mount strings). `Host.ReachesEngineAt(docker.host)` tells whether a tcp/tls/mtls host is the Engine AuraGo itself uses (same address incl. loopback aliases, same effective port); the API then classifies its containers like the local ones.
- Host secrets live only in the vault: `docker_host_ssh_<id>` (SSH private key or password) and `docker_host_tls_<id>` (JSON `ca`/`cert`/`key`). They never reach the database, an API answer or a log, and the prefix `docker_host_` stays in `tools.blockedSecretPrefixes`. `SecretInput` is write-only: nil or blank fields keep what is stored, `Clear` empties both first, secrets the kind does not use are removed. The stored SSH secret is kept only while address (compared bare, ignoring case), effective port and `ssh_user` stay the same and the kind stays `ssh`; otherwise `Update` without a new `SSHSecret` is a `ValidationError` for `ssh_secret` and `TestDraft` ignores the stored one, so a stored password never reaches another machine. TLS material keeps merging. `transport.TLSMaterial` prints no PEM (`String`/`GoString`). A host whose secrets cannot be stored is not created; a failed update puts the vault back.
- Verification is never disabled. `tls`/`mtls` use TLS 1.2 or newer, the stored CA or the system roots and `ServerName` = the host address; unusable material fails every request and never falls back to plain HTTP. `tcp` is the only unencrypted kind.
- `Registry.Client` caches one `dockerutil.Client` per host, keyed by a fingerprint of the connection settings; `Update` and `Delete` drop it (`forget` also bumps the host's generation, so a client built across the change is discarded and rebuilt). `Create`, `Update` and `Delete` are serialized by one write mutex; `Close` makes later client requests fail. Clients dial nothing until the first request. SSH hosts pool connections (one SSH client per Engine connection, closed with it); `Registry.Close` releases them.
- `Registry.Test` (GET /version, then /info) caches a `HostStatus` (`TestNow` is the deliberate variant behind `POST /hosts/{id}/test`, see the SSH rule below); `ClassifyError` maps failures to `dns`, `refused`, `timeout`, `tls`, `auth`, `ssh_host_key`, `socket_missing`, `api_too_old` or `unknown`. Engines below API 1.41 are refused (`api_too_old`).
- SSH login protection (`sshguard.go`): per stored SSH host an `authBreaker` pauses logins after a rejected login (`ClassifyError` = `auth`, not a failed socket open): 2 min, doubling per consecutive failure up to 30 min; a successful dial and `forget` (Update/Delete) reset it; `TestNow` only lifts the running pause (`authBreaker.lift`) and keeps the failure count, so repeated clicks on Test/Retry with a wrong password still double the pause. While paused, dials fail fast with a `CodeAuth` error ("SSH login paused ...; next attempt in ..."), which the API reports as `host_unreachable` with `reason: auth`. A gate allows one SSH dial per host at a time (pooled connections are not capped). Background `Test` respects the pause; `TestNow` (the Test button) lifts it for one attempt; `TestDraft` uses its own uncached client and neither consults nor changes it (each click on the form's Test button is one deliberate attempt). `TestDraft` returns a `*ValidationError` (invalid field, SSH/TLS secret missing or not reusable) as its error; the API answers 400 `invalid_host` with the field, and only a real connection outcome is a `HostStatus`.
- Engine reads and actions return a `*StatusError` for a non-2xx answer; classify by `StatusOf(err)`, never by message text. Container ids are validated (`ErrInvalidContainerRef`) before they enter a path, actions are start, stop, restart, pause, unpause and kill (`ErrInvalidAction`), HTTP 304 counts as success, removal sends `v=true`.
- **Live calls** (`engine_live.go`): `StreamEvents` (`StreamEventsOpen` adds a callback for the moment the Engine accepted the request) follows `GET /events` for the types container, image, volume and network; a line is at most 1 MiB, the call ends with the context's error, with the callback's error, or with an `io.EOF`-wrapped error when the connection drops. `ContainerStats` decodes one `stats?stream=false[&one-shot=true]` sample into `RawStats` (cumulative counters; the memory cache is `total_inactive_file`, else `inactive_file`, else `cache`; a container that is not running answers a zero sample, so `Read` is the zero time). `SystemDF` totals `/system/df` like `docker system df` (image size = unique layers, reclaimable = unused images, stopped containers, unreferenced volumes, idle non-shared build cache). All three use `Client.StreamingHTTPClient`, so only the caller's context bounds them, and answer a non-2xx status with a `*StatusError`. Event attributes are raw (not masked); callers pick the few they need.
- `Store.DB()` hands the shared `docker_manager.db` handle to `internal/dockerstacks`, which keeps its `docker_operations` table in the same file; the Store owns the handle and callers never close it. `DemuxStreams` splits a non-TTY log or attach stream into stdout and stderr (either may be nil) on the frame parser that `ContainerLogs` uses. `ClassifyError` tests DNS wording before the socket-missing wording (a resolver that cannot open `/etc/resolv.conf` is `dns`), and an Engine that reports no usable API version is `unknown`, not `api_too_old`.
- Redaction reuses the admin inspect: `InspectContainer` goes through `tools.ProjectDockerInspect`, list labels through `tools.RedactDockerLabels`, bind sources through `tools.RedactDockerMountSource` (last path element only). `dockerhost` imports `internal/tools` for this; `internal/tools` must never import `dockerhost`.
- `transport.TLSClientConfig`, `transport.TLSMaterial` and `transport.DialEngineOverSSH` are the former Invasion helpers. Their error texts and tunnel semantics (known_hosts through `remote.DialSSH`, bounded socket open, closing the conn closes the SSH client) are visible in API answers and pinned by the transport tests and Invasion's Docker tests.

## Work guidance

- Add Engine calls through `engineJSON` (`dockerutil.Client.DoJSON`); stream bodies are read with `Client.HTTPClient()` and bounded.
- Tests use the fake Engine in `fakeengine_test.go` (it serves `/version` and the `/v1.45` routes of the fixtures) and the in-memory vault in `registry_test.go`; no test needs Docker.
