# Tool handlers

## Purpose

Agent filesystem, external service and Docker tool safety boundaries.

## Ownership

`internal/tools` owns this domain. The contracts below also bind related server, UI, config, asset, and test work through the root routing table.

### Web scraper and site crawler
- `web_scraper` and `site_crawler` share `tools.web_scraper.enabled`. Public fetches use `security.MaxSSRFResponseBytes`. Dynamic mode uses `newScraperLauncher` and one process-wide slot.
- `web_scraper` static, RSS, and auto share that single GET. Auto returns RSS when `rssResponseLooksLikeFeed` and `parseRSSOrAtom` both succeed; otherwise it passes the same body to `AgentScraper.ScrapeHTML` and does not GET again. A thin HTML result may still call `FetchDynamic`. A dynamic fallback warning uses that same redaction, so a blocked address never appears in the warning. `internal/tools` does not export the GET helper. `FetchStatic` does not use Colly.
- `site_crawler` honors robots.txt, applies `selector` via goquery, cuts previews at 500 runes, skips a body whose length equals `MaxSSRFResponseBytes` with the preview `page skipped because it exceeds 5 MiB`, and isolates title and preview with `ScanExternalContent`.

### GitHub repository trust
- Workspace project metadata, including `AgentCreated`, is inventory only. Runtime trust comes from explicit administrator allowlists or the protected, API-bound `github_trust.json` ledger. Legacy inventory requires visible administrator approval. Preserve a private backup and atomically replace ledger updates; malformed ledgers fail closed without being overwritten.
- Repository deletion requires `github.allow_delete` (default false), repository access and writable mode. A create response followed by a ledger failure reports the created repository plus a migration warning; never suggest retrying the creation.
- Project directories are a single `github/<name>` segment inside the workspace, created through `os.Root` before `projects.json` is saved. Names must match `githubIdentityPart`.
- `GitHubSearchRepos` keeps public hits and drops private hits unless `GitHubRepoAllowed`.
- `GitHubCreateRepo` looks up `/user` and posts to `/orgs/{owner}/repos` when the configured owner is a different account. A failed lookup does not create a repository.
- `GitHubGetFileContent` decodes base64 text up to 256 KiB and lists directory arrays. `GitHubCreateOrUpdateFile` base64-encodes plain text and preserves round-trip base64.
- `GitHubListRepos` follows same-origin `Link: rel="next"` for at most 10 pages. A positive limit slices after filtering.
- `GitHubDeleteRepo` revokes an existing grant before `DELETE`. A non-204 response restores that grant. A transport error leaves it revoked and reports `trust_revoked`.
- GitHub HTTP uses `NewSSRFProtectedHTTPClientSameOrigin` and the caller context.
- Outgoing `call_webhook` uses `NewSSRFProtectedHTTPClientSameOrigin`. A cross-origin redirect is refused before the next host is contacted. Verify `TestExecuteOutgoingWebhookDoesNotFollowCrossOriginRedirect`.

### treg catalog gateway
- `treg_catalog`, `treg_call` and `treg_status` use the fixed public-only treg transport. Never accept model-supplied origins, authentication, cost headers or polling URLs. Already-sent calls are not replayed after ambiguous failures.
- Grants bind endpoint ID, method, path and an explicit read/create/update/delete class. Check the current catalog and run/live policy before requests; use the smaller run/live cost cap, including zero. Keep `treg_token` Vault-only and excluded from Python exports.

- The bounded process-local continuation cache is not a billing store. Preserve call IDs in tool history for accounting after restart. See `documentation/treg.md`; verify `TestTreg*` across config, tools, agent, server and UI.

### Netlify integration
- The Netlify client is built with `httporigin.NewClient`, so the bearer token never follows a redirect to another origin; `Link: rel="next"` pagination targets are re-checked with `httporigin.SameOrigin` before the token is sent again. Deadlines are per call (`netlifyRequestTimeout`, `netlifyUploadTimeout` for a ZIP upload), never a client-wide timeout.
- Dispatch and both server handlers call `security.RegisterSensitive` with the Vault token before the first network call.
- `netlifyHTTPError`/`netlifyCodedError` are the only error envelopes: they keep `http_code`, parse `message`/`error`/`errors[0]` and bound provider text to 300 runes, so an HTML or binary body can never break the JSON result. Never reintroduce `%q` interpolation.
- Only GET/HEAD retry (`429`/`5xx`, at most two repeats, `Retry-After` capped at 30 s). Mutations are sent once; `set_env` PATCHes the single key only after an "already exists" answer.
- Environment variable operations resolve the account through `netlifyAccountSlug`: `team_slug` when set, otherwise `GET /accounts` (exactly one account is adopted, several require the setting). `/sites/{id}/env` is not used.
- `buildNetlifyZip` packs regular files only (a symlink is never read), filters credential material by name and caps `netlifyZipMaxEntries`/`netlifyZipMaxBytes`. A generated `_headers` is the only MIME source, and the catch-all `_redirects` rewrite is added only for a single-page output (`netlifyLooksLikeSPA`).
- `HomepageDeployNetlify` keeps `deploy_url` (immutable permalink) and `site_url` apart (`mergeNetlifyDeployObservation`), verifies the permalink, and reports `published: false` for a draft without recording a successful deployment target; operation intent/outcome still belongs in the ledger (`homepageNetlifyResultPublished`). An unreadable build answer aborts instead of deploying blindly.
- Verify `TestNetlify*`, `TestBuildNetlifyZip*`, `TestHomepageDeployNetlify*` and the `internal/audit` credentialed-redirect ratchet (no Netlify entry).

### Security Egress and Host Execution
- Native direct HTTP integrations carry the dispatch owner's context in a per-call configuration or client. Stop cancels request headers, body reads, retry/poll waits and OAuth refresh-lock waits; shared HTTP clients never hold a session context. Legacy standalone wrappers retain their existing lifetime. SiteMonitor initial SSRF DNS pinning uses the same owner. Verify `TestNativeHTTP*` in tools/agent and `TestSSRFClientInitialPinningHonorsOwnerContext`.
- Generic foreground shell, Python, saved Python tools and supported skill scripts use the existing pinned llm-sandbox supervisor by default; absent runtime/image support is an error with no host fallback. Explicit unsafe-host grants keep compatibility paths; the legacy non-Windows `allow_unsandboxed_shell` grant applies only to shell. Generic workers receive source and bounded arguments, no Vault credentials, ambient bridge token, host bind, Docker socket or network. Require digest-pinned images, read-only image plus task scratch, finite CPU/RAM/PID/output limits, no-new-privileges and the documented DAC_OVERRIDE-only capability exception for upstream private-file injection. Do not claim zero capabilities. Supervisor startup is a trusted fixed-command exception, carried only by the private container-sandbox context; user MCP servers retain shell/unsafe gates. Stop reaches the MCP request and connection acquisition; never hold a cancelled request on a shared connection. `documentation/isolated-executor.md` owns operator guidance. Verify `TestDefaultExecutorFailsClosedWithoutSupervisor`, `TestSandboxCallerCancellationAndBorrowWait`, `TestBrowserPublicationRequiresWriteAndRoot`, and `python internal/tools/sandbox_launcher_security_test.py`.
- Python Tool Bridge workers use supervisor-brokered framed requests. Grants remain in trusted supervisor memory, bind the originating run and expire; never inject a global admin token, worker HTTP origin or credential into worker source/env. Bound frames, results and call count, validate sequence, refuse redirects and recheck current server/run policy on every call.
- VirusTotal omitted/hash/auto modes only look up existing hashes or URL reports. File uploads and previously unseen URL submissions require explicit upload mode and the canonical action gate. Open local sources with `OpenToolInputFile` and retain that handle through hashing and upload. Browser capture/form screenshots require effective filesystem-write permission and publish atomically through a workspace `os.Root`; Chromium sandboxing stays enabled. Lint paths cannot introduce options and tool calls never install a latest executable. Verify VirusTotal, isolated-executor, lint argument and SSRF tool tests.
- Every Cloudflare quick entry point publishes one active registered Homepage project's immutable static snapshot, at a server-allocated port. Reject explicit ports, Web UI defaults, inactive/unregistered projects, symlinks and credential files; bound copying to 64 MiB. Named/token ingress remains administrative. Docker requires a local engine socket or a verified parent container namespace. The origin is host-bound, supports read-only HTTP and rechecks project revocation; uncertain start/termination retains a disabled listener until the original daemon or process confirms termination. Record the request and resulting URL plus snapshot hash in the Homepage ledger. Verify `TestHomepageQuick*`, `TestCloudflareQuick*` and the configuration browser test.
- Cloudflare's automatic certificate exception belongs only to the configured local AuraGo HTTPS origin. Never set global `originRequest.noTLSVerify`; migrate that legacy default to the matching ingress rule and preserve unrelated provider configuration and origin options. Named tunnel YAML follows the same origin match. Verify `TestCloudflareAPIExceptionAppliesOnlyToAuraGoOrigin` and `TestCloudflareNamedExceptionAppliesOnlyToAuraGoOrigin`.
- Cloudflare lifecycle mutations use `tunnelLifecycleMu`, keeping `tunnelMu` short. Discover/adopt only verified reserved-name/image/command/label token/named Docker containers, including without auto-start; stop disabled connectors and orphan quick containers. Preserve original engine/ID and disabled quick origins on uncertain create/start/stop. Inspect is bounded to three seconds outside the state lock; unknown is never stopped. Config revocation stops before Docker mutation permissions change. Named YAML uses explicit validated routes and one final 404. Linux installs serialize, verify fixed hashes, cap 100 MiB and atomically replace via fileutil. Metrics always bind loopback, including port zero. Verify `TestCloudflare*` and `TestHomepageQuick*`.
- Local Ansible performs effective context-bound shell/unsafe-host checks at the execution point, including check, status, inventory and facts. Preserve the selected sandbox and filtered environment. Stage bounded, rooted playbook snapshots and static inventories before execution; no absolute-path or executable-inventory bypass. SSH host-key checking defaults on. After `PrepareExecCommand`, `ApplyShellSandboxDockerGrant` adds the host and required unix socket only when `requireDockerPermission` allows it. Accept package requirements only, rejecting URLs, paths, pip flags and requirements files. Prepared shell/native skills follow the selected shell sandbox; service operations use bounded foreground execution and filtered environments.

### Mission completion chains

  owner marker before queued status, retain its context through dispatch, and
  retain it for dependent local missions and release it after the last callback.

  Desktop entry until its protocol can acknowledge cancellation.

## Background admission and retention

- Background tasks default to 256 active admissions and at most 64 due starts per
  tick. Persist a complete bounded claim batch before dispatch. Retain completed/
  canceled tasks for 30 days and failed/blocked tasks for 90 days, at most 2,000

  `action_rule_required` response is durably blocked and releases active capacity.

  shutdown waits for it before closing dependencies. Retry only definite dial
  failures; errors after request transmission retain an unknown outcome.
  Isolated code uses the existing SandboxManager callback, persists the original

  server cancellation. Host process execution is never a background fallback.
