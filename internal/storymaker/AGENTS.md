# Storymaker package contract

## Purpose

Go core of the Storymaker desktop app (explainer videos from a story document): the `storymaker/1` story model, strict
decoding, validation, defaults, the catalog index, code-scene bundling and the project storage layout. No server
dependency. Spec: `docs/superpowers/specs/2026-11-01-storymaker-design.md`. The player that renders the story is
JavaScript (`ui/js/storymaker/`); Go never recomputes the timeline.

## Ownership

- `model.go` types and JSON (polymorphic `Position` and `Duration` keep an unreadable value as `Invalid` so Validate reports
  it at the right path); `decode.go` `DecodeStory` and the field hints; `validate.go` + `issues.go` `Validate`,
  `CapIssues`; `defaults.go` `ApplyDefaults`; `catalog.go` + `catalog_files.go` the `storymaker-catalog/2` index and delivery validation (v1 fixtures remain supported); `codebundle.go`
  `BundleCodeScene`; `project.go` + `memstore.go` + `slug.go` storage, `MemStore` (test helper), `Slugify`. `ranges_gen.go` is
  generated by `scripts/build-storymaker-ranges.mjs`; never edit it by hand.
- `testdata/stories/*.json`, `testdata/scenes/*` (with the golden `s3.bundle.js`) and `testdata/catalog-mini/catalog.json`
  are shared fixtures: the player tests read the same files. `catalog-mini` has only the manifest; the files it
  references belong to the player part.
- The render job, listener and browser live in `render/`; HTTP handlers in `internal/server/storymaker_*.go`. Config is
  `internal/config/storymaker.go`.

## Local Contracts

- Issue shape `{severity, scene_id, path, code, message, at_seconds, fix}`; `path` is a JSON Pointer. `error` blocks a
  render, `warning` does not, `minor` is `not_supported_yet` and `canonicalised`. Codes are the constants in `model.go`;
  the app localises them as `storymaker.issue.<code>`. Model-facing answers carry at most `MaxModelIssues` (`CapIssues`).
  The motion lint codes and `cue_late` are constants too, but only the player's compile report emits them; `Validate` never does.
- `DecodeStory` fails with a `*DecodeError` that always carries issues. Unknown fields are reported with the path, a
  hint for common mistakes and the allowed fields; key matching is exact. Wrong types become `invalid_json` with the path.
- `Validate` canonicalises prefixed names in place (`pose.typing` becomes `typing`, with a `canonicalised` note), knows the
  closed pose/gesture/expression/transition/ease sets, reports names the catalog lacks as `not_supported_yet` and unknown
  names as `unknown_name` with at most 5 alternatives. A nil catalog skips asset, spot and catalog-name checks.
- The phase 1 support matrix lives in `model.go` (`phase1Beats`, `phase1Transitions`) and in `validate.go`; move a beat or
  transition out of "not supported yet" there when the player gains it. `highlight` moved in phase 2. `style.rhythm` is `calm`,
  `standard`, `lively` or absent, and Go never writes a default.
- `ApplyDefaults` fills only the static defaults of the spec and the show-beat instance id; timing (`delay`, `duration`,
  `ease`) is never defaulted: the player's compile step owns it. It is idempotent. The default transition is `cut` on scene 1,
  `wipe` when the environment differs from the previous scene's, else `fade`; a stored value stays. The editor saves a new scene
  at once with the fade of the environment it copied, so its environment edits go through `S.model.setEnvironment`
  (`ui/js/desktop/apps/storymaker-model.js`): a stored fade that now crosses into another environment becomes a wipe, on that
  scene and on the next. Other transitions stay, and `fade_between_worlds` still flags a fade the user picks afterwards.
- `LoadCatalog` checks the manifest, v2 file inventory and `glyphs.file` through `LoadGlyphs`. `VerifyFiles` streams v2 dependencies and checks exact length, SHA-256, encoded image type and dimensions; v1 fixtures retain existence checks. Server startup runs this verification before exposing the catalog. The catalog is immutable after
  loading. Search is term scoring over id, name and tags (default 6 results, cap 12).
- `BundleCodeScene`: esbuild `Transform` (IIFE, global `__smSceneModule`, ES2020, no legal comments) plus the appended
  `self.__smScene=__smSceneModule.default;`. The pre-check is a tokenizer over the author's source and is defence in depth
  only; the CSP and the worker realm are the barriers. A slash after `)`, `}`, `++` or `--` is read both ways. Positions
  are 1-based and count characters. The golden bundle is reproduced byte for byte by Node esbuild 0.28.2 in the player tests.
- `Store` is the only file access of `ProjectStore`. `Remove` behaves like `os.RemoveAll`; etags are
  `desktop.NoteVersion` (`ETag`); a failed precondition is `ErrConflict`. Project ids are lowercase UUID v4, scene ids slugs;
  every path is built from validated ids only.
- `SaveCodeScene` checks the precondition itself, removes the old bundle, and only then writes the source and the new
  bundle. A save that fails half way therefore leaves the old source with its own bundle or the new source without one, never a
  bundle built from older source: a render loads the bundle of every scene whose status is ok.
- Slugs for file names: ASCII letters, digits and dashes, umlauts transliterated, Windows device names refused, 80 characters.

- Music (`music.go`): `MusicMoods`, `MusicPrompt`, the keys `generated|mood|prompt`, `file|path|size|mtime` and `track|id|size|mtime`, with length excluded. `MusicMeta` is written after the audio file, and a file without valid meta counts as missing. Its optional `loudness_i` is the job's best-effort measurement for the preview's bed gain; the mix measures for itself. `auto_sfx` and the `sfx` beat left "not supported yet" in 2C, and a mood outside the presets is an error.
- Catalog `sfx` entries carry `takes`, `impact_ms`, `align`, `hit?`, `pattern?` and `source`, and have no thumb. `render.snapshot` skips them, because the page never reads WAVs.
- `storymakertest/seed.go` (`SeedNarration`, `SeedMusic`) gives fixtures audio, because the `narration_incomplete` and `music_incomplete` gates refuse a story without it.

## Work Guidance

- Keep one responsibility per file. New issue codes or fields need the model, the validator, the hint text
  and the app's `storymaker.issue.<code>` locale keys in step.
- Do not edit the `catalog-mini` fixture or the story fixtures without updating the player's Node tests that read them.
- Regenerate the golden bundle only for an intended esbuild change: `STORYMAKER_UPDATE_GOLDEN=1 go test ./internal/storymaker -run TestBundleGolden`.

## Verification

- `go test ./internal/storymaker/... -count=1` and `go test ./internal/config/... -count=1`.

## Speech

- `narration.go`: `Blocks` is the one list of what must be spoken: one narration block per scene that is not silent, and one dialogue block per `say` with text, also in a silent scene and also with its actor off stage. `StripMarkers` is byte for byte `SM.narration.parse(text).plain`, and `testdata/narration/cross_language.json` holds the two languages together. One sentence is one piece (`SplitPieces`). `PieceKey` hashes provider, voice, language and piece text, with provider and language trimmed and lower-cased.
- `audio_decode.go`: `DecodeAudio` and `ProbeAudio` detect the format from the bytes, never from an extension. WAV and MP3 only, at most 600 s. `ProbeAudio` reads a duration without keeping samples.
- `envelope.go`: `<hash>.env.json` is a 10 ms series, so it stays free of the frame rate. `AssembleBlock` is the one function behind `/narration` and `Plan.AudioInfo`. `ParseEnvelope` trusts nothing, because these are ordinary workspace files: an audio file without a valid envelope counts as missing.
- `glyphs.go`: reads the build-generated `ui/img/storymaker/glyphs.json`; Go never reads WOFF2. `Validate` adds `glyph_missing` for show text, say text and narration that is drawn. A silent scene's narration is never drawn, so it is not checked. Code-scene strings stay `layout_unverified`. The mini catalog has no `glyphs` key and skips the check.
- `voices.go`: `ResolveProjectVoice` takes providers in the order of `storymakerVoiceProviders`, so a paid provider never wins over a free one. `Validate` checks only the shape of a voice, because the package does not import `internal/tools`; `POST /narrate` checks the list.
- `Store.Open` returns a seekable file for the audio routes. `MemStore` and `storymakerStore` are its only implementers.

## Render and server (part B)

- `render/` turns a story into an MP4 (job manager, listener, ingest, browser, egress guard, FFmpeg); its contract is `render/AGENTS.md`. The package has no dependency on `internal/server`; the handlers are `internal/server/storymaker_*.go`.
- The server implements `Store` and `render.Publisher` over `*desktop.Service` (`storymakerStore`), passes `Limits.MaxDurationSeconds = storymaker.render.max_duration_seconds` to the validator and gives every request its own `Story` copy (`Validate` and `ApplyDefaults` mutate).
- Catalog version, canvas sizes (1920x1080, 1080x1920, 1080x1080), the support matrix and the error codes of a job (`invalid_story`, `browser_unavailable`, `ffmpeg_unavailable`, `render_failed`, `render_timeout`, `cancelled`, `busy`, `code_error`, `interrupted`, `storymaker_disabled`, `narration_failed`, `narration_unavailable`, `voice_required`, `budget_exceeded`) are shared with the app through `GET /status` and the job document.

## Fallback fonts (part G)

- `ui/img/storymaker/glyphs.json` (`storymaker-glyphs/1`) is generated by `scripts/build-storymaker-catalog.mjs` from the font cmaps (`assets/storymaker/lib/glyphs.mjs`). It joins the catalog version and `--check`. Never edit it by hand.
- Faces stay out of `catalog.fonts`, so `style.font` cannot name them. A face file that joins `glyphs.json` needs a licence text and a row in `licences/THIRD_PARTY_LIBRARIES.md` that names the file. `TestStorymakerGlyphFaceNotices` in `ui/storymaker_catalog_test.go` enforces this.
- `glyphs.go` reads the file through `LoadCatalog`. Go has no WOFF2 code.

## Phase 2 close

- Phase 2 (sound and export) landed in batches 2A to 2D. The contract is the reference, and the design spec section "Changes from the phase 2 plan" records every change to the original text.
- `testdata/stories/speech.json` (CJK, RTL, Greek, Hindi, bubbles) is shared with the player tests and the render smoke tests, so an edit there reaches both.
- Still open for the user's ears or hands: voice notes and rhythm factors, sentence pause and trim margins, the taste of the SFX set, prosody with per-sentence synthesis, and the aurago-test acceptance. Agent voice discovery is `storymaker_catalog kind=voice` (section Agent core).

## Agent core

- `studio*.go` hold the job tools and call no LLM: `studio.go` (phase table, session, budget, routing, read-only gate), `studio_args.go` (argument repair), `studio_story*.go` (story operations and drafts), `studio_code.go` (revision-bound code access), `studio_catalog.go` (search, describe, voices), `studio_reference.go` (embedded runtime guides), `studio_check.go` (lint, checks and compile cache), `studio_words.go` (word checks), `studio_packet.go` (context packets). `agentjob.go` holds outcomes, backups and `ChangedScenes`; `agentfacade.go` holds the chat facade types.
- The tools reach a job through a closure over its `*Studio` (`ExecutionHooks.HandleTool`), so a model cannot pick a project or a job. Schemas never carry an id the server binds. The tools stay out of the normal catalog: no feature flag, category, search term, manual or dispatch case. The chat tool `storymaker` is separate and calls `CurrentAgentFacade()`.
- `storymaker_catalog reference` serves embedded animation/code guides in cast, fill, check and revise; check permits reference only. `reference/` owns the guides and executable example. Both native and text profiles direct visual work to them; no RAG or checkout is required at runtime.
- `get_code`/`put_code` operate only on existing scenes in fill/check/revise; fill is restricted to its scene. Source exchanges are capped at `StudioCodeBytes` (8 KiB). Writes require the code revision from `get_code`, pre-bundle before saving and pass the observed full etag to `SaveCodeScene`. Invalid code preserves saved files. Larger user sources stay for manual editing. Code writes share scene write/correction budgets and the live read-only gate.
- Bundle code before activating `kind: code` with `put_scene`; source writes alone do not complete fill. Code changes invalidate compile/check caches and participate in revision change lists even when story JSON is unchanged. Reverting source does not count as changed. Story/project format and renderer isolation remain unchanged.
- A loop per phase, and a loop per scene in fill. The story is the checkpoint, so a job is never resumed: a later revise finishes it. An invalid write stays a per-scene draft and is dropped at the end. A failed or exhausted scene keeps its outline text and is recorded as `scene_unfilled`.
- Charging: a drop in the issue count, a first write and a new scene are free. Limits are `StudioSceneChargedLimit`, `StudioSceneWriteLimit`, `StudioDryRunsPerScene`, `StudioDryRunsPerJob` and `StudioCheckRounds`. `IssueAdvisory` lists the four codes and `words_tell` that get one optional fix loop and never block.
- `DecideOutcome` is the one rule for outcomes. This slice never emits `ready`, and `open_checks` always holds `layout_unverified`. `over_target` and environment items never downgrade.
- The backup methods of `ProjectStore` (`SaveSilentBackup`, `LoadSilentBackup`, `HasSilentBackup`, `RemoveSilentBackup`) keep `story.before-silent.json`. `MakeSilent` is pure: it sets `silent: true` and `duration = max(1, WordCount / 2.3 + 0.4)`, removes `cue`, and turns each `say` with text into a `show`. Without the duration the film collapses to about 1 s per scene. Ticking `silent` by hand has no such repair.
- `render.Runner.CompileCheck` reuses `snapshot`, the listener, the strict proxy and the page, captures the report and answers it with an error, so the page stops. It needs no FFmpeg, is bounded to 60 s and never downloads Chromium. Without a browser the job reports `compile_unverified` and still finishes.
- Narration runs after the check, because the audio key contains the text. No voice is not a failure: the story keeps `voice: null` and reports `narration_unavailable`.
- Compact story-tool schemas stay within 900 estimated tokens per tool with the current catalog; shorten redundant descriptions before removing fields or raising the bound.
- Both schema sizes expose delay/duration/ease/count, explicit SFX, scene kind/source and style rhythm/auto_sfx. Compact schemas omit duplicated asset/actor name enums already supplied by phase packets, catalog and beat enums; backend validation remains authoritative.
- The `storymaker_*` job tools stay out of the strict schema projection. `null` in `patch_scene` removes a field, so a required-and-nullable schema would delete fields.
- A job cancels only a narration it started itself, never one it joined by coalescing.
- Verify: `go test ./internal/storymaker/... -count=1` and `go test ./internal/server -run Storymaker -count=1`. `TestStorymakerAgentScriptedJobNative` and `TestStorymakerAgentScriptedJobTextMode` run the whole job with a scripted model, and no test calls a real model or voice.
