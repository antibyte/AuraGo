# Docker Manager stacks

## Purpose and ownership

`internal/dockerstacks` owns the Docker Manager's stacks: the compose projects that live as one folder per stack on a Docker host (`<stacks_dir>/<name>/compose.yaml` plus an optional `.env`). It discovers them, reads and writes their two files with revisions, runs compose operations in short-lived runner containers, keeps the operation journal and reattaches to operations that were running when AuraGo restarted. Lint and the `docker run` converter (`lint*.go`, `convert*.go`) are pure functions of the same package. The HTTP API lives in `internal/server`, the desktop app in `ui/js/desktop/apps/docker-manager*.js`, hosts and Engine clients in `../dockerhost/AGENTS.md`; the design is `docs/superpowers/specs/2026-10-26-docker-manager-design.md`. This package may import `dockerhost`, `dockerutil` and `tools`; `tools` and `dockerhost` must never import it.

## Local contracts

- Everything reaches a host through the Engine API of a `dockerhost` client; AuraGo's image needs no Docker CLI. Three helper containers, all created from the runner image `docker@sha256:5e6b…` (`docker:29.9.2-cli`, Compose 5.6.1; the constants and the pinning rule are in `names.go`): a **runner** per operation (`aurago-dm-op-<operation id>`), a **lister** per folder scan (`aurago-dm-ls-<8 hex>`) and the parked **IO container** `aurago-docker-manager-io`, which is created and never started. All three: no network, `CapDrop ALL`, read-only root file system with a 64 MB tmpfs, `no-new-privileges`, bounded json-file log, no restart, role label `aurago.docker-manager.role`. Only the delete runner gets `CapAdd DAC_OVERRIDE, FOWNER`. The goldens in `payloads_test.go` pin every field; the image digest is spelled out in them on purpose.
- The runner scripts (`scripts.go`) are constants run as `sh -ec <script> aurago-docker-manager "$@"`; stack names, paths and file names reach them only through the positional arguments or `STACK_DIR` and `PROJECT`. Never build script text from a value. Delete runs in the stacks directory so a broken compose file cannot stop the `down`.
- **Prepare** (`prepare.go`) is the only place that pulls or creates: API 1.41 or newer (`api_too_old`), runner image (pull; if that fails on a remote host, copy from the local engine with `GET /images/<ref>/get` into `POST /images/load`, only when both engines report the same OS and architecture, then tag `RunnerLocalTag`, because a saved digest reference loses its name; otherwise `runner_image_missing` with the exact `docker pull` command), IO container (recreated when its stacks-dir label differs; a container of that name without the IO role label is never touched, `stacks_dir_unavailable`). Every stack operation runs it implicitly first. Reads (`List`, `Get`, `Helpers`, file writes) never pull or create: an unprepared host answers `host_not_prepared` with the helper status.
- **Files** go through the IO container's archive API: `HEAD` for existence (a stack's data folder can hold gigabytes, so a directory is never fetched), `GET` of one file (at most `MaxFileBytes`), `PUT` of a tar owned by uid 0 (compose 0644, `.env` 0600). A new folder travels in the archive as a 0755 entry; an existing folder gets only its files, extracted inside it, so its owner and mode stay. Revisions are the hex SHA-256 of the bytes, `""` for a missing file; `WriteFiles` compares them under one mutex per (host, stack) and checks every file before writing any (`*ConflictError` with what is on the host). The Engine answers 404 both for a missing path and for a missing IO container; only the message tells them apart (`archivePathMissing`), and a bodiless `HEAD` 404 is rechecked against the helpers before a stack is declared missing.
- **Discovery** runs the lister (`find`, two levels, the stacks directory bound read-only, no socket) and caches the folder scan per host for `ListCacheTTL`; container status is read live on every call and never cached. Our own writes and finished stack operations drop the cache. `find` exiting 1 is no failure while it printed stacks. Names that fail `ValidateName` are ignored folders, never stacks. Status comes from `DeriveStatus` over the containers labelled `com.docker.compose.project=<name>`; helper containers never belong to a project.
- **Operations**: one lock per (host, stack), prepare locks (host, ""); a second start gets `*BusyError`. The row in `docker_operations` (shared `docker_manager.db`) is written at every state change and at most every 2 s for output; the newest 50 finished rows per (host, stack) are kept. Compose output is parsed line by line (`progress.go`): a JSON object becomes a `progress` event and, unless it carries a byte count, an output line; the line that explains a failure and the compose file line it names (`line N`) are extracted from the output. The runner is removed only after its result is recorded; the health wait after `up`/`update` polls the project's containers (`HealthPoll`, up to `HealthWait`) and only ever adds a warning. An operation older than `MaxDuration` has its runner killed (`timeout`). Subscribers get a snapshot and then events; one that falls 256 events behind is dropped and reconnects.
- **Restart safety**: `Open` registers unfinished rows with their locks at once and resumes each one: the runner is found by name, its log is read again from the start (the log is the source of truth), the exit code decides; no runner means `interrupted`, or `succeeded` for a row that only waited for health. A host that does not answer parks the operation until the next `List`, `Get`, `Start` or `Operation` call for it. `Close` stops the followers and leaves runners running. Leftover exited runners of finished operations and exited listers older than a minute are swept once per host and process.
- Engine and transport errors are returned as they are (`*dockerhost.StatusError`, net errors) so the server classifies them; this package's own failures are `*Error`, `*ConflictError` or `*BusyError` and carry stable codes (`errors.go`). The only place that matches Engine message text is the archive 404 above.
- **Lint** (`Lint`, files `lint*.go`, `yamlnode.go`) is pure: no Engine access, no host. The compose file is parsed into `yaml.v3` nodes, so every diagnostic has a line and column; a YAML error returns only `yaml_syntax` plus the `.env` warnings. It never blocks anything. The codes and their `params` are the contract with the UI strings `lint_<code>`: `yaml_syntax`, `not_a_mapping`, `no_services`, `service_no_image`, `invalid_port`, `port_duplicate`, `port_conflict`, `variable_missing` (fix `env_random`, none for `${X:?m}`), `image_latest`, `image_no_tag`, `privileged`, `docker_socket`, `network_mode_host`, `restart_missing`, `cap_add`, `env_syntax`. **`env_syntax` lines belong to `.env`, every other code to the compose file.** `published` are the ports other containers publish on the host; those of project `LintInput.Stack` are not conflicts. `interpolate` is the one implementation of Compose variable syntax (`$$`, `$NAME`, `${X:-d}`, `${X:?m}`, nested defaults); a port or volume that uses a variable without value and default is not judged (the variable warning covers it). Every list in the answer is non-nil. Adding a code means adding its `lint_<code>` strings to all 16 desktop locales and the test table in `lint_test.go`.
- **`docker run` converter** (`ConvertDockerRun`, files `convert*.go`) builds the compose file from `yaml.Node`s so the key order is fixed (`image`, `container_name`, `command`, ...). `splitCommand` is a shell word splitter that runs nothing: quotes, `\` and PowerShell backtick continuations, `C:\path` survives, `$(pwd)` in storage flags becomes `.`; a dollar sign the shell kept literally is emitted as `$$`. The flag tables in `convert.go` list every `docker run` flag: supported ones are converted, known ones without a conversion are reported as `flag_unsupported` and their value is skipped (so the image is still found). Errors carry `CodeConvertFailed`; everything else is a warning (`flag_unsupported`, `flag_ignored`, `flag_value_invalid`) with the long flag name.

## Work guidance

- Add Engine calls to `engineapi.go` (`engine.request` for bodies and streams, `engine.json` for JSON); streaming calls use a client copy without a total timeout and are bounded by their context.
- Tests use the stateful fake Engine in `fakeengine*_test.go` (containers, images, an in-memory file tree behind the archive API, volumes) with `newTestEnv`; none needs Docker. `live_test.go` runs the whole cycle against a real engine and is gated by `AURAGO_DOCKER_MANAGER_LIVE=1`; it prints the raw `--progress json` lines of the runner, which is how the field mapping of `parseProgressLine` is confirmed against a Compose release.
- A new pinned image, Compose release or script changes the constants in `names.go`/`scripts.go` and the goldens together.
