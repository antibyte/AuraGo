# Docker Manager live data

## Purpose and ownership

`internal/dockerwatch` is the Docker Manager's live data: one Engine events watcher per host, the stats sampler with its rings and the host gauges, the disk-usage cache, the per-host budget of streaming Engine connections, and the `Hub` that fans all of it out to the open `/api/docker-manager/stream` clients. The HTTP side (SSE writing, routes, the `dockerstacks` operation bridge, the terminal) lives in `internal/server`, the desktop app in `ui/js/desktop/apps/docker-manager*.js`; hosts and Engine clients are `../dockerhost/AGENTS.md`, the design is `docs/superpowers/specs/2026-10-26-docker-manager-design.md`. The package's own code imports `dockerhost` and `dockerutil` only (the live test also `dockerstacks`); nothing in `tools`, `dockerhost`, `dockerutil` or `dockerstacks` may import it.

## Local contracts

- **Hub and clients** (`hub.go`, `client.go`). `New(hosts, Options)` runs nothing until a client subscribes or `WatchHost` is called. `Attach` opens a stream client (at most `MaxClients` = 32, then `ErrTooManyClients`; its id is 32 lowercase hex characters from `crypto/rand`); `Messages()` is a channel of 512 (`ClientBuffer`) that is closed on `Close`. A client that falls 512 messages behind is sent `dropped` (in place of its oldest unread message) and closed; the UI reconnects. `Set` replaces the client's whole subscription (`Hosts`, `Stats` host -> ids, `HostStats`) after checking all of it: at most `MaxSubscribedHosts` = 20 hosts per list (`ErrTooManyHosts`), `MaxStatsIDs` = 50 container ids per host (`ErrTooManyIDs`), ids are 12 to 64 hex characters and are reduced to their first 12, host ids match `^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`; every error matches `ErrInvalidSubscription` and a refused `Set` changes nothing. The hub does not know whether a host exists (the server checks that first); a host the registry has forgotten shows as `unreachable` with reason `host_not_found`.
- **Locking.** `Hub.mu` guards the clients, their subscriptions and all host runtimes; messages are pushed into the clients' buffered channels while it is held (a push never blocks), so a client sees messages in the order they were produced (`stats_history` before the live `stats` that follow it). Order of locks: `Hub.mu`, then `Client.mu`. `budgetMu`, `dfMu` and a df entry's gate are leaves and are never held while taking `Hub.mu`. `WatchHost` callbacks run on the watcher goroutine without any lock and must not block or call back into the hub. `Publish` never blocks; the `dockerstacks` observer may call it with the operation's locks held.
- **Events watcher** (`watcher.go`, `eventmap.go`). One per host while a client has the host in `Hosts` or a `WatchHost` callback exists; it stops `IdleStop` (30 s) after the last user, and a client that arrives sooner finds it running and is sent its current `host_status`. It holds one stream slot while it runs (it runs without one when the budget is used up). States: `connecting` until the Engine accepts `GET /events`, `live`, `unreachable` (no answer; `reason` is `dockerhost.ClassifyError`) and `paused` (the host answers but `/events` does not: three refused connects in a row, or three stream ends within a minute): the container list is polled every `PollInterval`, a `resync` (reason `poll`) is sent whenever the digest of (id, state, status, health) changes, and the feed is retried every `RetryPaused`. A feed established again after any interruption sends `resync` (reason `reconnect`). Reconnect delays are `Backoff` (1, 2, 4, 8, 16, 30 s; the last repeats), a request the Engine never answers ends after `ConnectTimeout`. Container events forwarded: create start restart die stop kill pause unpause destroy rename oom update and `health_status: <x>` (action `health_status`, field `health`); everything else is dropped, image, volume and network events pass as they are. Only name, compose project and service, exit code and health are copied from the Engine's attributes; label values never reach a client.
- **Stats** (`stats.go`). Containers are sampled only when a client asks for their id: every `StatsInterval` (3 s), at most 4 Engine calls in flight per host (both sampling loops together), `stream=false` plus `one-shot=true` from API 1.41 (CPU from our own previous sample; the first sample is `-1`), plain `stream=false` below (CPU from `precpu_stats`). CPU is the container's percent of one core (the share of the system's CPU time times online CPUs); `-1` means unknown (no previous sample, system delta not positive, counter went backwards); a container that used no CPU reads 0. Memory is usage minus the cache (`RawStats.MemCache`). A ring holds 60 points; a client that starts asking for a container with a ring first receives `stats_history` (oldest first). A 404/409 answer or an all-zero sample (the Engine's answer for a stopped container) sends `stats_gone` once, frees the ring and stops sampling that id until a client asks again or a `start`/`restart`/`unpause` event for it arrives. A ring nobody sampled for 5 minutes is freed, and the loop ends when nothing is left.
- **Host gauges** (`gauges.go`). For a host with a `HostStats` subscriber: every `HostInterval` (10 s) the running containers are listed and up to `MaxHostSample` (100) of them sampled (`partial: true` above that); one that also has a stats ring with a point at most `HostInterval` old is not sampled again. `cpu` is the sum of the known container CPU values divided by the host's CPU count (`-1` while none is known; the second cycle follows after 2 s so the first reading is not a gap), `mem_used` the sum of memory, `mem_total` and `ncpu` come from `dockerhost.Info`, cached 5 minutes.
- **Disk usage** (`df.go`). `DiskUsage(ctx, host, refresh)` serves a cached `SystemDF` reading for 5 minutes; `refresh` re-reads only when the cache is older than 60 seconds; concurrent callers share one Engine call; a failed reading keeps the cache and returns the error. The Engine API reports no size of the file system, so the figure is Docker's own usage in bytes.
- **Stream budget** (`budget.go`). `Acquire(host)` takes one of `MaxStreamsPerHost` = 16 slots (events watcher, followed container logs, terminals) or fails with `ErrTooManyStreams`; the returned release can be called more than once.
- Engine and transport errors are returned unchanged; the server classifies them with `dockerhost.ClassifyError`. Message names are the `Msg*` constants and the JSON of the message types is the contract with the UI (`types.go`): change them together with `ui/js/desktop/apps/docker-manager-live.js`.

## Work guidance

- Tests use the fake Engine in `fakeengine_test.go` (an `httptest` server with `/version`, `/info`, `/containers/json`, `/system/df`, per-container stats generators and an `/events` feed the test writes to and drops), `newTestEnv` (a hub over host `h1` with intervals of a few milliseconds and an injected clock) and the `waitFor`/`waitUntil` helpers; none needs Docker. Keep waits short and drive time with `Options.Now`; sleeps over a few tens of milliseconds are a smell. `live_test.go` runs a throw-away container against a real Engine and is gated by `AURAGO_DOCKER_WATCH_LIVE=1`.
- New producers send through `Hub.publishLocked`/`Client.push` while holding `Hub.mu`; anything that calls into an Engine does so without it. A new background loop is started from `reconcileLocked` (with `h.wg.Add(1)`), stops with `h.ctx`, and clears its own flag under `Hub.mu` when it ends.
