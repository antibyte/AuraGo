# RuView sensing

## Purpose

Pinned RuView v3122 integration: managed or external runtime, passive status, authenticated proxy, and board setup.

## Ownership

This package owns the runtime client, proxy policy, node inventory, passive status, the lifecycle (`lifecycle.go`, `runtime.go`, `storage.go`) and the typed errors (`errors.go`). `internal/server` owns the HTTP routes, the admin gates and `ruviewError`. The Desktop app is four classic scripts: `ui/js/desktop/apps/ruview-model.js` (pure `RuViewModel`), `ruview-store.js` (`RuViewStore`: requests, timeouts, polling, epochs), `ruview-views.js` (`RuViewViews`: Status, Boards, Lab) and `ruview.js` (`RuViewApp`: composition root, command bar, menus, live region). `ui/js/ruview/wizard.mjs` owns the board wizard. `documentation/ruview.md` owns operator guidance. The vendored upstream UI stays untranslated.

## Local Contracts

- `Status()` is passive. It does not dial, resolve DNS, or read the node file. Opening the app does not start a runtime. The desktop store polls status every three seconds while the RuView window is visible. The Boards view reads `Nodes()` every three seconds while visible, including for an external instance. Status reads `Nodes()` only for a managed ESP32 service, and once after an explicit Check now on an external ESP32 service. For a managed runtime that is not running, `Nodes()` returns `not_running` without dialing. External services are dialed only by `Test` (Check now), the Boards view and explicit data reads (D6).
- Enabling RuView does not start a runtime in an already running session. A manual stop, process exit, or uncertain stop is not restarted automatically. `stop_failed` and `process_exited` survive `Configure()` and probes until an explicit `start` or `stop` replaces them.
- Status fields (`manager.go`, `lifecycle.go`): `runtime` is always set and comes from `runtimeLocked` (first match wins). `phase` and `phase_since`, `error_code` and `error_detail` (scrubbed, at most 240 bytes), `stop_reason` and `stopped_at`, `last_fresh_at`, `storage_used_bytes` and `storage_budget_bytes`, `recording_at`, and `hints` (sorted, never `null`) are derived in `Status()`. `error` stays as the legacy sentence. `error_code` precedence: lifecycle (`stop_failed`, `process_exited`), then a start or install failure, then probe results (`source_mismatch`, `unexpected_simulation`, connection codes), then `storage_unreadable` only when nothing else is set.
- Phases: a Docker start is `preparing`, then `pulling_image` only when the image is missing, then `creating`, then `waiting_ready`. A native start is `preparing`, `verifying`, `creating`, `waiting_ready`. An install is `downloading`. `waiting_ready` ends at the first stored probe that reports ready (`test`), or after 30 seconds (cleared by `watch`).
- Passive fields, copied from saved configuration and this process:
  - `udp_enabled` follows the saved flag and is false for external mode.
  - `udp_ready` is true only for a running managed runtime with UDP enabled, a private bind, and at least one allowlist entry.
  - `udp_scope` is `managed`, `external`, or `off`. External means the operator runs reception; it is not a failure. Disabled configuration is `off`.
  - `receiver_configured` is true when the saved receiver is a private IPv4 address.
  - `recording_session` is `unknown`, `started`, or `stopped` for this process only. It starts as `unknown`.
  - `recording_ack` is empty or `unconfirmed`.
- The recording marker lives on the manager. `Configure()` clears cached probe status and must not clear a confirmed session.
- `noteRecording` runs only after `/api/v1/recording/start` or `/api/v1/recording/stop` is forwarded. A 2xx start sets `started` and clears the acknowledgement. A 2xx stop sets `stopped` and clears it. Any other forwarded result, including a transport failure or an invalid body, sets `unconfirmed` and keeps the last confirmed session. A local rejection that never leaves AuraGo does not call it.
- The wizard never enables UDP and never stores Wi-Fi credentials. An uncertain flash is never retried. An explicit node ID from 1 to 255 is marked edited before discovery, so a suggestion cannot replace it. A blank partition-table area (all 0xFF) is written without erase; `erase_required` is returned only for an existing, different partition table.
- Agent `nodes` and the proxy stay live-only. `presence` is the only agent read that also returns saved offline IDs for this receiver. Its node `state` is `live`, `stale`, or `offline`. A node is `fresh` only when the source is `esp32`, the result is not simulated, `csi_status` is `active`, a sequence is present, and the age is at most 10 seconds. RSSI is included only for a node that is `live` in that reply. Offline nodes have no RSSI and `rssi_retained: false`. The summary has no Wi-Fi data, file path, or scope path. `fresh: false` does not prove presence. Simulation is not a sensor.
- `Nodes()` sets `live_state` to `ok`, `not_applicable` (source is not `esp32`), `not_running` (managed runtime not running in this process; upstream is not dialed), `unreachable`, or `invalid`. `available` is true exactly for `ok`. `presence` reports the same `live_state`. The setup list leaves the board step open (neither done nor the step to fix) for `not_applicable`, `not_running`, `unreachable` and `invalid`. The Boards view explains `not_applicable` and `not_running` with `devices_not_applicable` and `devices_not_running`.
- `Read` returns a successful data payload when the following status probe fails: `fresh: false`, `simulated` from the last known status, `data_state: disconnected`, and a short `status_error` without a URL or token. The call itself is not an error. A failed data read stays an error and has no invented payload. `status` still only calls `Test`.
- `waiting_for_frames` is true when a probe reports a connected source that has not delivered its first frame. Such a probe is never `fresh`. The config connection test and the Status view show it as waiting, not as success.
- `SetOperationalHint` receives `sensing_stale`, `storage_limit`, or `stop_unconfirmed` with `open` set only when that hint changes. The same state does not call again. This package does not import the planner, choose issue text, or send a notice. Disabled configuration does not close an open hint.
- `sensing_stale` opens when the integration is enabled, the effective source is `esp32`, the probe is not simulated, the previous probe was fresh or live, and the new probe is `stale`, `disconnected`, or `live_unverified` with an age above 10 seconds. It closes only when a later probe is fresh, `esp32`, and not simulated. It does not open while disabled, simulated, sourced from `wifi`, or before a fresh or live probe.
- `storage_limit` opens when a managed budget observation changes from false to true and closes when a later observation is false. External mode does not open it. A stop or disable that replaces status does not count as the budget returning to false.
- `stop_unconfirmed` opens when a non-external stop returns without releasing runtime ownership. It closes on a later stop that returns successfully or on a start that finishes. External mode does not open it.
- Configure (M27, `Configure()`): only runtime-relevant changes count. These are the RuView section without `ReadOnly`, `AgentAccess` and `StorageMB` (`runtimeFields`), plus the data directory, the Docker host, and the Docker enabled and read-only switches (`configKey`). A relevant change cancels a start in flight and the probes, and records `config_changed` for a starting or managed runtime. The watch loop then stops that runtime. Lifecycle errors survive; start failures are cleared. Read-only, agent access and the storage budget change nothing.
- Lock protocol (M29, `lifecycle.go`): `m.op` is the single slot for long work (`opStarting`, `opInstalling`). It is claimed only while `opMu` is held and is never waited on, so a second Start or Install answers `busy`. `opMu` serializes short state changes. It is never held across an image pull, a native download or file hashing. Lock order is `opMu → mu`. `Stop` cancels the generation first, then takes `opMu` with the caller's context only. Stop therefore works during `starting`, and the start ends `cancelled`. Start and Install wait for `opMu` at most `lockWait` (10 s), then answer `busy`; a watch tick that cannot get `opMu` is skipped. `emitHint`, `noteStop` and `noteStorage` run with neither lock held: `stopRuntime` records the outcome and `flushStopNote` emits it.
- Stop removes the owned container (M23, `stopContainer`): stop, then remove. A container named `aurago-ruview` that is not ours is never stopped or removed. Stop then succeeds and logs a warning, and Start returns `container_conflict`. A failed removal is logged, and the next start removes a stale container.
- Docker self-exit (M24, `inspectExit`): while a managed Docker runtime runs, the Engine is asked about the owned container at most every `dockerEvery` (5 s, 5 s timeout), outside `opMu`. A container that is missing, replaced or not running is recorded by `markExitedLocked` as `process_exited`. That error is sticky, `runtime` becomes `exited`, and `udp_ready` is false. A transport error is not an exit. Native exits are reaped by `reapNativeLocked`.
- Storage (M28, `storage.go`): `sampleStorage` walks at most every `storageEvery` (30 s). `storageCheck`, used by the recording proxy, reuses a sample younger than 30 s or walks again. A walk is capped at `maxStorageEntries` (200,000). More entries, links, special files and permission errors are `storage_unreadable`, not full. A missing data root counts as 0 bytes. The proxy refuses a recording start with 503 (unreadable) or 507 (full) as plain text, not the JSON envelope. The watch loop requests a recording stop only on a successful sample that is over budget.
- Errors (`errors.go`): `Code*` constants, `errorHTTP`, `codeText`, and `Error{Code, Detail, HTTP, msg, cause}`. `msg` (the legacy sentence in `Status.Error` and the `error` response field) and `Detail` are both `scrubDetail`ed, at most 600 and 240 bytes. `AsError` maps context errors to `cancelled` or `timeout`, and untyped errors to `unknown` with a scrubbed detail. `ruviewError` in `internal/server` writes `{error_code, error, detail}` with the code's HTTP status. The raw cause goes to the server log only (`rawText`).
- `request` (`client.go`) returns typed errors. A transport failure is `unreachable`, a deadline is `timeout` (504), upstream 401 or 403 is `upstream_auth`, other non-2xx is `upstream_error`, and invalid JSON, a 2xx that is not JSON, or `status != ready` is `contract_unsupported`. `errInvalidReply` stays matchable (`nodes.go`).
- The handler runs Start, Install and Stop under `context.WithoutCancel`, so a closed tab does not abort them. Each keeps a 10-minute cap.
- Desktop polling (D6, `ruview-store.js`): status is polled only while `state.visible` (window visible, in view, document visible). Request timeouts are status 10 s, nodes 10 s, test 20 s, stop 30 s and config 15 s. Start and install have no client timeout; only dispose aborts them. A status epoch drops answers older than the last applied one. A failed poll keeps the last status and sets `statusFailed`; it never becomes "off" (H9). `allowChanges()` sends `PUT /api/config` with `{"ruview":{"readonly":false}}` and nothing else.
- Desktop model (`ruview-model.js`): `deriveState` evaluates rows in table order. Row 10 (stop failed or unconfirmed, unless stopping) outranks row 3 (off). Any blocking error code (every code except `storage_unreadable`) suppresses rows 4 and 6, so a start error outranks read-only. A loaded status without a boolean `enabled` is row 2. `KNOWN_ERROR_CODES` mirrors `ErrorCodes()` plus `network` and `forbidden`. `diagnostics()` never reads the legacy `error` field and redacts URLs and secret-looking values.
- The live region announces headline changes and action results only, never routine polls.
- Pose, vital signs, model load, LoRa, camera, and timed recording stay blocked.
- The gate patches to the vendored upstream UI use checked anchors: `scripts/ruview/patch-controls.mjs`, the sensing and pose gates inline in `vendor-ui.mjs`, and `scripts/ruview/patch-honesty.mjs`. `patch-honesty.mjs` is the last stage of `vendor-ui.mjs`. A vendoring run with `--source` fails if an anchor moves; `--check` verifies only the pinned hashes. Honesty patches keep the Demo controls hidden unless the source is explicitly simulated, show `—` for invented CSI values, and label example data and upstream claims.
- The upstream iframe sandbox is `allow-scripts` only. UI responses use `connect-src 'none'`. The frame sends API calls and WebSockets by `postMessage`. The Desktop parent relays a call only when `Endpoint` allows that method and path, and only through the authenticated proxy. It also relays its own `status` and `capabilities` reads, and GET of a `.wasm` file under the RuView UI prefix, because the opaque frame cannot fetch those itself. Paths with a query or fragment are refused before any network call. Replies without a matching id are ignored. The parent accepts a message only when `event.origin` is `null` and the source is that frame. It replies to that frame with target origin `*`, because the browser rejects target origin `null`; the frame accepts a reply only from its parent window. Serial, camera, and microphone stay off the frame. Tour completion still uses only `aurago.ruview.onboarding.done`, seeded from the frame name.
