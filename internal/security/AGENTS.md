# Security primitives

## Purpose

Vault, token storage, URL trust and model-assisted security verdicts.

## Ownership

This package owns reusable primitives; server owns session and HTTP policy.

## Local Contracts

- Startup may read the unchanged master key from `AURAGO_MASTER_KEY_FILE`; an explicit environment key takes precedence. Initialize the Vault before child processes, retain the key only in the private trusted-updater store, then remove `AURAGO_MASTER_KEY` from the environment and config snapshot. No automatic rotation. Generic Vault mutation APIs must reject reserved authentication/session/master/internal keys; the server route remains administrator-only.

- OAuth rotation uses compare-and-swap against the exact previous Vault value under both process mutex and file lock; revocation or a new login cannot be overwritten. Rotated values remain agent-hidden.

- Public-only egress rejects unspecified/private/reserved and IPv6 transition addresses; retain DNS pinning and redirect validation. Explicit LAN integration permissions remain separate.
- Administrator-selected integration bases require absolute HTTP(S) URLs without userinfo, query or fragment. Credentialed API redirects stay on the exact scheme/host/effective-port origin; public download redirects use a fresh pinned client without inherited headers.
- The same-origin policy is implemented in the leaf package `internal/httporigin` (shared with `internal/llm`, which this package imports); `SameHTTPOrigin` and `SameOriginRedirect` here are wrappers around it.
- `NewSSRFProtectedHTTPClient` re-validates and re-pins every redirect hop but follows any public origin (307/308 re-send the body); keep it for uncredentialed fetches such as returned-media downloads. Credentialed callers use `NewSSRFProtectedHTTPClientSameOrigin`: `httporigin.SameOriginRedirect` first (a foreign target is refused unresolved), then the unchanged SSRF re-check. `internal/audit` `TestCredentialedHTTPClientsBindRedirectsToOrigin` guards both client kinds for the literal header names it knows (see its blind-spot comment); its `credentialedRedirectPending` ratchet of unbound files may only shrink.
- Both SSRF redirect checks drop credential headers (`Authorization`, `Proxy-Authorization`, `Cookie`, `X-Api-Key`, `X-Auth-Token`, `X-Goog-Api-Key`, and any header whose name contains `key`, `token`, `secret`, `auth` or `password`) on every hop that leaves the first request's exact scheme/host/effective-port origin. An http→https upgrade or apex→www redirect therefore loses `Authorization` too: configure the final URL. Verify `TestSSRFClientStripsCredentialHeadersAcrossOrigins`.
- Public scraper fetches use `GetPublic`: one `NewSSRFProtectedHTTPClient` GET with `ScraperUserAgent` and `ReadLimitedBody` capped at `MaxSSRFResponseBytes` (5 MiB). A longer body fails with `response exceeds 5 MiB` and a nil slice. Non-2xx responses fail as `HTTP %d`. Redirect checks stay on the SSRF client.
- `GuardRodPageSSRF` fulfills through the SSRF client and fails a body larger than `MaxSSRFResponseBytes` instead of calling `LoadResponse` with an unlimited read.
- `CaptureProxy` (`StartCaptureProxy`) is the egress boundary of a headless capture of untrusted pages: the browser gets `--proxy-server` plus `--proxy-bypass-list=<-loopback>`, so service workers, WebSockets and prerenders go through it too (a CDP request hook sees only the page target). It dials the allowed origin's host:port as given and every other destination only after the SSRF rules (`validatedSSRFDialTarget`, `AURAGO_SSRF_ALLOW_LOOPBACK` unchanged), dialing the validated IP. It never follows redirects, caps concurrent slots, lifetime outbound attempts and relayed bytes, and closes idle tunnels after 10 s. Launch Chrome with `--webrtc-ip-handling-policy=disable_non_proxied_udp` as well: `--force-webrtc-ip-handling-policy` alone still lets STUN reach loopback UDP. Verify `TestCaptureProxy*` and, with `AURAGO_RUN_BROWSER_SMOKE=1`, `TestCaptureHomepageAnnotationSnapshotReachesNothingBeyondThePreviewBrowser` in `internal/tools`.
- Spotlight, Canary and Structure are retired, including request-local Guardian construction. Legacy options cannot attach those guards or manufacture trusted prompt envelopes. Never infer trust or skip a scan from input tags or copied system text; preserve the original human request.
- Optional content scans and the PromptSec judge accept only completed, strictly parsed verdicts. Scan every contiguous UTF-8-safe 4 KiB section with 512-byte overlap, at most eight; excess content is incomplete quarantine. Apply the judge once to the full original after local window scans, preserving its escalation mode without upstream truncation or normalized cache keys. Ingresses with an explicit content scan use local-only prechecks. Missing scanners, transport errors, unfinished responses and unknown verdicts never allow content, independently of the tool-execution fail-safe. Cache only complete valid verdicts.
- `QuarantineNotice` provides fixed local reason categories and an isolated source/reference, never original payloads, subjects or model-written reasons. Callers deliver it only through the original target's authorized route, preserving acknowledgment/deduplication and never running the original payload callback. A notice grants no quarantine bypass.
- Shell, Python and `run_tool` output always use `IsolateExternalData`. Only Game Maker source tools and the CYD Creator read tools (`cyd_creator_read_project`, `cyd_creator_read_file`, `cyd_creator_build`, `cyd_creator_api_reference`; `classifyToolOutput`, `TestGuardianSanitizeToolOutputKeepsCYDCreatorSourceReadable`) may use the copyable source form. Scan original source before rewriting role markers; cap raw input before escaping and preserve isolation form during compression and archival.
- `IsolateExternalData` strips Unicode format characters, folds a fixed set of angle-bracket lookalikes, neutralizes `\u003c`, `\u{3c}`, `\x3c` and `[INST]` delimiters, then HTML-escapes. Ordinary ASCII without those sequences stays byte-identical. It does not decode HTML entities. Verify `TestIsolateExternalDataHardensBoundaryLookalikes`.
- `scanWithOptions` (behind `ScanForInjection`, `ScanExternalContent`, `SanitizeToolOutput` and every inbound gate) scans each window as written, as a scan view and as decode shadows, and keeps the maximum. The scan view (`scan_view.go`) never deletes separators: every `unicode.Cf` rune and the invisible fillers (U+034F, Hangul and Khmer fillers, U+2800) become one ASCII space with runs collapsed, other Unicode whitespace becomes a space, then NFKC folds mathematical, circled, squared, superscript, fullwidth and ligature letters. It is scanned only when it differs from the window and never feeds `Sanitized` or the isolated body. Decode shadows cover what the sanitizer cannot read: unpadded and URL-safe base64 runs of 16+ characters whose decoded text is mostly printable, percent-escape clusters and HTML numeric-entity clusters (at least two within 128 bytes). A shadow finding of Medium or higher is lifted to severity 0.7 (ThreatHigh); a shadow without findings changes nothing. A scan decodes at most 64 shadows and four windows of shadow text. Verify `TestScanView*`, `TestScanDecode*` and `TestScanViewAndShadowsReachChunkedWindows`.
- `injection_patterns.go` passes AuraGo's own `CustomPatterns` to the heuristic guard: override and prompt-disclosure phrases for Italian, Portuguese, Polish, Dutch, Turkish, Russian, Chinese, Japanese and Korean at severity 0.85 plus the Llama 3, Gemma, `<|endoftext|>` and `<tool_call>` tokens at 0.9. promptsec itself covers English, German, Spanish, French and Croatian; every other language is covered only by the opt-in judge. Rules stay phrase-specific (an imperative plus what it overrides or discloses). The sanitizer folds accents and swaps Cyrillic lookalikes before the heuristics run, so Latin rules list the accented and the plain letter and Russian rules go through `cyrillicRule`. Add a benign sentence to `TestGuardianLanguagePacksFlagOverridesAndPromptDisclosure` with every new rule. With the sanitizer off, promptsec's confusable check scores any Cyrillic text 0.7; that is existing behavior.
- `SanitizeToolOutput` for external and source output that starts with a JSON object or array (after `Tool Output:` labels) also scans the decoded string values joined by newlines, because a JSON encoder escapes the line breaks and quotes a phrase needs, and keeps the higher verdict. Role markers are rewritten in those values too (`neutralizeLeafRoleMarkers` re-encodes only changed tokens). Reading stops at the first syntax error, so output cut by a size budget still yields its complete values.
- External tool output at ThreatHigh or above becomes `QuarantineNotice` with no payload and no security-warning line. Source output at ThreatCritical is escaped with `IsolateExternalData`; other source output stays on the copyable source form until that threshold.
- When `SanitizeToolOutput` keeps an isolated body, `ToolOutputWarning(isolated)` is exactly the suffix it appends: a newline plus `[SECURITY WARNING: ...]` quoting only a sanitized category (letters, digits, underscore, at most 40), or empty when nothing is flagged (`TestToolOutputWarningMatchesSanitizeToolOutput`). The scanner message stays in the log. Tools that size their answers to the agent's output budget (CYD Creator) count the suffix on the warning path.
- Imported backup metadata cannot grant agent readability. Retain existing local grants only under the Vault's matching-value rules; new imported secrets default hidden.
- Token files use synced private temporary files and `fileutil` replacement. Cast media tickets expire, bind one path and invalidate after process restart; they grant GET/HEAD media reads only. Speech tickets last 10 minutes and cast-media tickets last 3 hours. When login is disabled, the main `/tts/` and `/cast-media/` listeners require a ticket too.
- Only the stored scope set `["cyd"]`, compared exactly like `Validate`, gets the short on-glass token (`scopesExactlyCYD`); any other set, including `cyd` mixed with another scope, gets a full-entropy token. A short token's stored prefix is `aura_...` and reveals no body characters. Verify `TestCreateMixedScopesNeverUsesShortToken` and `TestCYDTokenPrefixHidesBody`.
- `RegisterSensitive` is the only way a Vault-read credential becomes scrubbable, so every integration registers a provider token at its read site before the first network call. The Netlify and Vercel integration tokens are permanent registrations: a token echoed back by a provider, a container or a log is redacted. Registration is per read site, not once at startup, because a re-read or rotated token must be registered again. Verify `TestDispatchServicesRegistersVercelTokenForScrubbing` and `TestHomepageDeployVercelScrubsTokenFromDeployOutput`.

## Work Guidance

Register secrets for scrubbing; never print credentials in diagnostics or fixtures.

## Verification

The reserved `auth_webauthn_state` Vault value grants owner login authority.
Keep `auth_` keys inaccessible to agent reads, Python export and generic secret
prompts (`vaultprompt.NormalizeVaultKey`), including after encrypted backup
import. Preserve its stable handle/RP and full library credential metadata;
never expose registry contents through config or public status. Server-owned
WebAuthn transaction and policy rules live in `../server/AGENTS.md`; verify
`TestWebAuthnVaultRestartAndBackup` and the secret-prompt reservation tests.

`go test ./internal/security ./internal/fileutil` and server backup/logout/Cast tests.
