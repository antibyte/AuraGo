# Xapian glass format as written by libzim

Format knowledge for `internal/zim/xapian`, learned by reading Xapian 1.4 and libzim 9 sources (GPL; no code copied) and verified against real libzim 9.8.2 / Xapian 1.4.23 output. Golden data: `testdata/`, generated by `scripts/localwiki/fixtures/generate.sh`.

All multi-byte integers inside blocks are **big-endian**. "varint" means Xapian's `pack_uint`. Offsets inside the database are relative to the start of the embedded blob (byte 0 = first byte of `X/…/xapian`).

## 1. How libzim stores the index

- `X/fulltext/xapian` and `X/title/xapian` are content entries with MIME `application/octet-stream+xapian` in **uncompressed** clusters (libzim's Xapian handler is not compressible). Each blob is a complete single-file glass database produced by `WritableDatabase::compact(path, DBCOMPACT_SINGLE_FILE | Compactor::FULL)`. libzim opens it by seeking a file descriptor to the blob offset and calling `Xapian::Database(fd)`; Xapian takes that position as offset 0.
- libzim builds both with `DB_NO_TERMLIST`, so the termlist table is absent. The full-text index has no positions; the title index has positions (position table present, not read by this package).
- The file is a sequence of blocks of size B (from the version block; libzim: 8192). Block *n* starts at byte `n × B`. Block 0 holds the version data; all tables share the remaining block numbers (block numbers are absolute, starting at 1).

## 2. Version block (block 0)

| Offset | Size | Content |
|---|---|---|
| 0 | 14 | magic `0F 0D 'X' 'a' 'p' 'i' 'a' 'n' ' ' 'G' 'l' 'a' 's' 's'` |
| 14 | 2 | format version, BE u16 = `0x046E` = `(2016−2014)<<9 \| 3<<5 \| 14` (2016-03-14; the only glass format of Xapian 1.4) |
| 16 | 16 | database UUID |
| 32 | varint | revision (1 after compaction) |
| … | 6 × RootInfo | tables in this order: postlist, docdata, termlist, position, spelling, synonym |
| … | 8 varints | statistics |

RootInfo = varint root block · varint flags (bit 0 root_is_fake = table empty, bit 1 sequential, `flags >> 2` = B-tree level, 0 = root is a leaf) · varint entry count (without the null item) · varint `blocksize >> 11` · varint compress_min · varint length + freelist bytes (ignore).

Statistics (all 0 when the data ends right after the RootInfos): doccount · lastdocid − doccount · doclen lower bound · wdf upper bound · doclen upper bound − wdf upper bound · oldest changeset · total document length · spelling wordfreq upper bound. Xapian reads only the first 256 bytes of block 0.

Worked example — `fixture_de.zim` full-text index (18 documents, total length 359):

```
0f 0d 58 61 70 69 61 6e 20 47 6c 61 73 73   magic
04 6e                                       format 2016-03-14
d5 8c 2d 35 bb ed 40 30 99 af 1b b6 7a 4f b8 d6   UUID
01                                          revision 1
01 00 a3 01 04 00 06 01 02 00 00 00 00      postlist: root 1, level 0, 163 entries, 8 KiB, cmin 0, freelist(6)
02 00 12 04 12 06 01 03 00 00 00 00         docdata: root 2, level 0, 18 entries, 8 KiB, cmin 18, freelist(6)
00 03 00 04 12 00                           termlist: fake (flags 3 = fake|sequential)
00 03 00 04 00 00                           position: fake
00 03 00 04 12 00                           spelling: fake
00 03 00 04 12 00                           synonym: fake
12 00 0e 05 1c 00 e7 02 00                  stats: 18 docs, last 18, doclen 14..33 (5+28), wdf ub 5, total 359
```

## 3. Integer and string encodings (`common/pack.h`)

- **varint** (`pack_uint`): little-endian base 128; every byte but the last has bit 7 set. `300` = `AC 02`. 32-bit fields (docids, tf, wdf, lengths) must reject values > 2³²−1.
- **varint-last** (`pack_uint_last`): little-endian bytes without length, only as the last item of a key; slot 0 encodes as nothing. Used only by value-statistics keys (not read here).
- **string** (`pack_string`): varint length + bytes.
- **sortable uint** (glass `pack_uint_preserving_sort`): `v < 0x8000` → 2 bytes BE (first byte < 0x80). Otherwise total length `L = (bitlen(v) + 5) / 7` (3…9 bytes): the last `L−1` bytes are the low bytes of `v` BE, the first byte is the remaining high bits OR `(0xFF << (10−L)) & 0xFF` (`0x80`, `0xC0`, `0xE0` … `0xFE`). Decoding: first byte < 0x80 → 2 bytes; `0xFF` is invalid; otherwise the number of leading 1 bits *k* means *k*+1 bytes follow and the first byte contributes its bits below the leading `1…10` prefix. Examples: `1` → `00 01`, `0x8000` → `80 80 00`, `0x400000` → `C0 40 00 00`, `2³²−1` → `E0 FF FF FF FF`. Encodings sort like the numbers.
- **sort-preserving string** (`pack_string_preserving_sort`): bytes of the string, every `00` byte followed by `FF`, then a `00` terminator unless the string is the last thing in the key.

## 4. B-tree blocks

Header (11 bytes): `[0..3]` revision · `[4]` level (0 = leaf; 254 = freelist block, never part of a tree) · `[5..6]` max_free · `[7..8]` total_free · `[9..10]` dir_end = offset just past the directory. The directory holds `(dir_end − 11) / 2` item offsets (u16), sorted by item key; items are packed at the end of the block. A tree block with zero items is corrupt.

**Leaf item:** `[0..1]` I — low 13 bits = item length − 3; the top bits of byte 0 are flags `0x80` compressed, `0x40` last component, `0x20` first component · `[2]` K = key length (≤ 255) · key · if *not* first: 2-byte component number (≥ 2) · rest of the item = this component's tag bytes.

**Branch item:** `[0..3]` child block number · `[4]` K · key · 2-byte component number. Item 0 of every branch block is the leftmost child; its key (normally empty with component 0) is never compared. Other separator keys are the shortest prefix that separates two children and may carry a component > 1, because a tag's continuation components can start a new leaf.

**Order:** items compare by key bytes (memcmp of the common part, shorter key first), then by component number. A search for key *k* uses (k, 1). A valid tree is strictly increasing in (key, component) across the whole table; the reader checks this on every step of a walk (next/previous item, including steps across leaf boundaries) and fails with `ErrCorrupt` when an item does not sort strictly after (before, when walking backwards) the one it left. That also stops a damaged branch block that points several items at the same child from making a walk revisit the same items over and over.

**Lookup:** from the root (its level is the table level, ≤ 9), in a branch block pick the last item *i* ≥ 1 with item ≤ (k, 1), else item 0, and descend; the child must have level − 1. In the leaf take the last item ≤ (k, 1); if *k* sorts before the leaf's first item, step to the previous leaf's last item. If that item is a continuation component, step back to its first component. "Next entry" skips items without the first-component flag. Every table's first leaf item is the **null item** (empty key, empty tag, first|last).

**Tags:** concatenate the chunks of components 1…n (the last one has the last flag; components carry the same key and consecutive numbers). If the first component has the compressed flag, inflate the concatenation as **raw deflate** (zlib window −15, `compress/flate`). libzim tables: postlist compress_min 0 → never compressed; docdata compress_min 18 → compressed when that is smaller (the bulk fixture's 4,000-byte path is compressed *and* spans two components).

## 5. Postlist table keys and tags

| Key | Tag |
|---|---|
| `00 C0` + name — user metadata | value bytes |
| `00 D0` + varint-last(slot) — value statistics | (unused here) |
| `00 D8` + varint(slot) + sortable(first docid) — value chunk | string(value of first docid), then repeated: varint(docid gap − 1), string(value) |
| `00 E0` — first chunk of the document-length list | posting list, wdf = document length, tf = cf = 0 |
| `00 E0` + sortable(first docid) — later doclen chunk | chunk |
| sort-preserving(term, last) — first chunk of a term | posting list |
| sort-preserving(term) + sortable(first docid) — later chunk | chunk |

All term keys sort at or after `00 FF` (terms are never empty; a leading NUL byte would be escaped `00 FF`), so a term walk starts at `00 FF` and skips keys that end in a terminated string (continuation chunks).

**First chunk tag:** varint tf · varint cf · varint (first docid − 1) · chunk header · chunk data. **Later chunk tag:** chunk header · chunk data (first docid comes from the key). **Chunk header:** one byte `'1'` (last chunk) or `'0'` · varint (last docid in chunk − first docid). **Chunk data:** varint wdf of the first docid, then pairs varint (docid gap − 1), varint wdf. Chunks are ≈ 2,000 bytes. A later chunk's first docid must exceed the previous chunk's last docid. To reach docid *d* without scanning: seek the entry ≤ key(term, d); if that chunk ends before *d* and is not last, take the next entry.

Worked examples (`fixture_de` full-text):

```
key 62 65 72 6c 69 6e ("berlin")   tag 04 07 00 31 0f 04 03 01 05 01 04 01
  tf 4, cf 7, first docid 1, last chunk, last docid 16, wdf 4; then docid 5 wdf 1, docid 11 wdf 1, docid 16 wdf 1
key 00 e0                          tag 00 00 00 31 11 21 00 16 00 18 …
  tf 0, cf 0, first docid 1, last chunk, last docid 18, doc 1 length 33, doc 2 length 22, doc 3 length 24 …
key 00 d8 00 00 01                 tag 06 "berlin" 00 07 "hamburg" 00 07 "munchen" …
  slot 0 from docid 1: values of docids 1, 2, 3 …
```

## 6. Other tables

- **docdata:** key sortable(docid) → document data; no entry when the data is empty.
- **termlist:** absent in libzim indexes (root_is_fake). **position, spelling, synonym:** not read.

## 7. libzim's index conventions (libzim 9.8.2)

- Metadata: `kind` (`fulltext` | `title`), `data` = `fullPath`, `language` (the indexing language passed to the creator; mwoffliner uses ISO 639-3, e.g. `eng`, `deu`, `nob`), `valuesmap` (`title:0;wordcount:1;geo.position:2` resp. `title:0;targetPath:1`), `stopwords` only when non-empty.
- Document data = `"C/" + path` (title index: the redirect's own path for redirects).
- Values — full-text: slot 0 = **normalised** title (`removeAccents(title)`, e.g. `große straße`), slot 1 = whitespace word count of the extracted text, slot 2 = geo position (rare); title: slot 0 = original title, slot 1 = target path (redirect target, else own path).
- Full-text documents: every `C/` item of MIME `text/html` whose extracted text is non-empty and not marked `NOINDEX` (front article or not). Terms come from Xapian's TermGenerator with `FLAG_CJK_NGRAM`; when `Xapian::Stem(lang2)` exists the strategy is `STEM_ALL` (all terms stemmed, no `Z` prefix), otherwise the default `STEM_SOME` with no stemmer (raw terms). No positions. wdf increments: article text 1, title `len(text bytes)/500 + 1`, keywords 3. Terms longer than 64 bytes are dropped. Stop words: libzim loads `stopwords/<language>`, whose resource names are two-letter, so Kiwix's ISO 639-3 languages index **all** words including stop words (`die`, `the`); verified on the real fixture (empty `stopwords`).
- Title documents: front articles and front redirects with a non-empty title. Text indexed = `"0posanchor " + removeAccents(title)` (anchor term `0posanchor` at position 1), strategy `STEM_SOME`: each word as raw term with a position plus `Z` + stem without position (only for words starting with a letter Ll/Lt/Lm/Lo and only when a stemmer exists), max word length 240, wdf 1 each. A title without word characters is indexed as one raw term.
- Stemmer language: ICU `Locale(language).getLanguage()` turns ISO 639-2/T codes into two-letter codes (`deu`→`de`, `nob`→`nb`, `jpn`→`ja`); Xapian 1.4.23 stems `ar hy eu ca da nl en fi fr de hu id ga it lt ne nb nn no pt ro ru es sv ta tr`; anything else (cs el hi ja pl zh …) is unstemmed.

## 8. Normalisation (`zim::removeAccents`)

ICU transliterator `"Lower; NFD; [:M:] remove; NFC"`: full lowercase mapping (root locale, **with** Greek final sigma), canonical decomposition, removal of **all** combining marks (Mn, Mc **and** Me — Devanagari vowel signs are Mc), recomposition. Go: `transform.Chain(cases.Lower(language.Und), norm.NFD, runes.Remove(runes.In(unicode.M)), norm.NFC)`. Examples (golden): `Häuser in Berlin`→`hauser in berlin`, `Straße`→`straße` (ß stays; the German stemmer turns it into `ss`), `Łódź`→`łodz` (ł has no decomposition, so `lodz` does not match), `ガンダム`→`カンタム` (kana voicing marks are marks), `हिन्दी`→`हनद`, `ΟΔΥΣΣΕΥΣ`→`οδυσσευς`, `İstanbul`→`istanbul`.

## 9. Tokenisation (Xapian 1.4 TermGenerator, index side)

Input is normalised text. Word characters = categories Lu Ll Lt Lm Lo Mn Me Mc Nd Nl No Pc. Unbroken (CJK) code points: 2E80–2EFF, 3000–9FFF, A700–A71F, AC00–D7AF, F900–FAFF, FE30–FE4F, FF00–FFEF, 20000–2A6DF, 2F800–2FA1F. A run of unbroken word characters `c1…cn` yields `c1, c1c2, c2, c2c3, …, cn` — unigrams get positions, bigrams do not. A word ends at a non-word character or where an unbroken character starts; a single infix character between two word characters is kept (`'` `&` U+00B7 U+05F4 U+2027; U+2019/U+201B become `'`), U+200B–200D, U+2060, U+FEFF are skipped inside a word, and between two digits `, . ;` (and a few others) are kept. Up to three trailing `+`/`#` stay (`c++`, `c#`) unless a word character follows (`fish+chips` → `fish`, `chips`). Positions count positional terms from 1; terms longer than the maximum word length (64; title index 240) are skipped without using a position.

## 10. Query parsing (Xapian 1.4 QueryParser as libzim configures it)

Both parsers get `removeAccents(query)`; libzim attaches an **empty** `Database` to them, so the `c++` suffix rule always keeps the suffix.

- **Full-text** (`Searcher`): flags `FLAG_CJK_NGRAM` only, default operator AND, `STEM_ALL`: every non-CJK word is stemmed (no `Z`); a CJK run becomes the AND of its unigrams and bigrams (raw). Words joined by `. - / : \ @` form a phrase, which Xapian runs as AND because the index has no positions. Result: the AND of all terms.
- **Suggestions** (`SuggestionSearcher`): OR of three subqueries over the title index:
  1. `FLAG_DEFAULT | FLAG_PARTIAL | FLAG_CJK_NGRAM`, `STEM_SOME`, AND of the words: a word becomes `Z`+stem when it starts with an Ll/Lt/Lm/Lo letter, a stemmer exists and the next character is not one of `( / \ @ < > = * [ { "`; words joined by phrase generators become an unstemmed phrase; a CJK run becomes the AND of its n-grams. If the query ends right after the last (non-CJK, non-phrase) word, that word is *partial*: `SYNONYM(the 100 most frequent terms starting with the raw word) OR SYNONYM(the word's normal term)`.
  2. The raw words (`STEM_NONE`, n-grams for CJK) as `OP_PHRASE` with window = number of terms; one term means just that term.
  3. `"0posanchor " + query` parsed the same way, as `OP_PHRASE` (title starts with the words).
  A query without any word becomes `OP_WILDCARD(query)`. Since bigrams have no positions, phrases containing CJK bigrams never match.

## 11. Weighting and ordering

`BM25Weight(k1, k2=0, k3=1, b, min_normlen=0.5)` without relevance set, for a term with term frequency *n* in a database of *N* documents and average length `avlen = total length / N`:

```
tw = (N − n + 0.5) / (n + 0.5);   if tw < 2 { tw = tw × 0.5 + 1 }
termweight = ln(tw) × (k1 + 1)                      (k3 factor (k3+1)·wqf/(k3+wqf) = 1 for wqf 1)
normlen = max(doclen / avlen, 0.5)
sumpart = termweight × wdf / (k1 × (normlen × b + (1 − b)) + wdf)
```

A document's score is the sum of the sumparts of the matching leaf terms; a phrase contributes the sumparts of its terms; repeated query terms count once per occurrence. **Search**: k1 = 1, b = 0.5; order by score descending, then docid ascending. **Suggest**: k1 = 0.001, b = 1; `set_sort_by_relevance_then_value(0)` (score descending, then title value ascending bytewise, then docid) and `set_collapse_key(1)` (keep the best document per non-empty target path). **Synonym** (partial word): wdf = sum of the members' wdf (capped at the document length), term frequency = Xapian's OR estimate: repeatedly replace the two smallest estimates *l*, *r* by `round(l + r − l·r/N)` (`round` = `+0.5` and truncate).

Measured: the Go implementation reproduces the python3-xapian weights to 1e−9 relative for every golden query and libzim's order for every fixture query. One inherent difference: when more than 100 terms start with the partial word and several share the cut-off term frequency, libzim picks among them with `std::nth_element`; this package keeps the earliest in term order (real fixture: `climate c`, 53 terms tied at tf 2, identical up to position 8).

## 12. Snowball parity

`blevesearch/snowballstem` v0.9.0 matches Xapian's stemmers on **accent-stripped** input (which is all libzim ever stems): compared on the full Snowball test vocabularies after `removeAccents` — da 23,797 · de 34,684 · en 42,649 · es 27,763 · fr 20,910 · it 36,955 · nl 45,327 · no 20,794 · pt 31,568 · sv 29,734 words — zero differences except English `skis`, where Debian's Xapian 1.4.29 carries the 1.4.28 regression (Xapian 1.4.23 in libzim and Snowball agree on `ski`). On accented input Portuguese would differ for `-ução` words (Xapian 1.4's `portuguese.sbl` has the Spanish `ución` rule), but libzim never stems accented words. Snowball stemmers for Xapian languages without parity proof (ar fi hu ga ro ru ta tr) and Xapian languages without a Go stemmer (hy eu ca id lt ne) report `FulltextSupported() == false`.

## 13. Detection rules

Test with `errors.Is`.

`ErrUnsupportedFormat` (well-formed input this reader does not implement): blob shorter than 2 KiB; magic is not glass (another backend such as `Xapian Honey`, or not Xapian); format ≠ `0x046E`; a block size field above 64 KiB (`blocksize >> 11` above 32) or a block size that is not a power of two in 2048…65536; tables with different block sizes (empty/fake tables are ignored); more than 2³² blocks.

`ErrCorrupt` (structurally invalid data):
- Version block: truncated or overflowing varints; a revision, root block number or `compress_min` above 2³²−1; a B-tree level above 9; a freelist length overrunning the data; truncated statistics; doccount, lastdocid − doccount, doclen lower bound, wdf upper bound or doclen upper bound − wdf upper bound above 2³²−1, or sums of them that wrap. Every field is range-checked on its `uint64` value before it is narrowed, so 32-bit builds (386, ARMv6/v7) classify a hostile value the same way as 64-bit builds.
- Blocks: block number 0 or past the end of the database; a block cut short by the end of the data; a block shorter than its header; level above 9, or not exactly the parent's level − 1; a freelist block inside a tree; a directory end outside the block; an empty block; an item, key or component number outside its item/block.
- Tree walks: keys that do not strictly increase (see §4); a continuation component with no first component before it; a broken component sequence (wrong number, wrong key, ends early); a tag above 16 MiB before or after inflating; invalid deflate data.
- Postings and values: non-increasing docids or chunk ends; a chunk end or docid above 2³²−1; a missing continuation chunk; a bad chunk or value-chunk key; a string overrunning its data; a document with postings but no length entry; documents present while the postlist table is empty.

An error from the underlying `io.ReaderAt` is wrapped with `%w` and is neither class (an end of the data inside a block is `ErrCorrupt`). Callers treat every `Open` error as "full-text unavailable" and keep title search running.

Reader limits (memory is bounded by these, not by the size of the index): a tag is at most 16 MiB; the block cache holds 4 MiB of block data per `Database` (512 blocks at libzim's 8 KiB, 64 at 64 KiB, never fewer than 16); a B-tree has at most 10 levels; a block is at most 64 KiB.
