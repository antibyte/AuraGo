# Release notes: security audit remediation (October 2026)

This release closes the findings of the application audit of 5 October 2026 that survived verification against the code. The report listed 56 entries (12 high, 22 medium, 18 low, 4 hints); each was re-checked against commit `65bb7f77f`. Two were not defects, three were overstated, one was broader than reported (the egg never persisted a rotated key, so every restart after a rotation locked the egg out) and one had a different root cause (cosign verification cannot become mandatory because current releases ship no signature). The fixes landed in three waves: core (shell and sudo, tool-output trust, Guardian parsing, LLM redirects, remote-agent replay and enrollment), channels, files and egg (chat-bot operator commands and sessions, symlink-following file serving, token scopes, SQL write functions, the Docker socket leak into the shell environment, egg key rotation) and hardening (CI pinning, security hints and a batch of low findings). Labels such as C1, D5 or E8 below are plain tags that group related changes; the audit report and the remediation plan are not part of the repository.

The guiding rule was the home-lab trade-off: close what matters for a single owner on a trusted-ish LAN, without removing or silently changing any feature an existing configuration relies on. Where behaviour had to change, existing configurations keep working through the project's `yamlHasPath` grandfather pattern and only new installations get the safe default; a few small compromises are accepted on purpose (for example the intentionally world-writable store bind directories that a container uid needs). Some findings stay deferred: M8 (a transient session purge leaves derived facts, because memory tools are not gated by `SuppressTurnSideEffects`), M10 (activity, journal, episodic, audit and long-term memory are unbounded; the retention keys are a product decision), M11 (the knowledge-graph privacy and retention columns are unused and to be documented as reserved), M20 (cosign verification stays optional until the release pipeline signs, because a strict default would break every install), the retry cap for provider-validation errors (chat POSTs are retried up to ten times; cost only, a test contract), the chat transport inheriting `HTTP_PROXY`, the egg HTTP signature without a nonce (both sides must change together), Landlock allowing write and exec in `/tmp` (needs Linux host validation), MySQL `REPLACE` needing only the write right (changing it would break write-only connections) and a CodeQL workflow.

## Breaking or behaviour changes you may notice

- **Linux and macOS shell (C1).** The shell on Linux and macOS now needs `agent.allow_unsandboxed_shell` or `allow_unsafe_host_execution`, the same gate Python and Windows already had. Upgrades set `allow_unsandboxed_shell`, so existing setups keep their shell. `allow_unsandboxed_shell` has no switch in the web UI yet: set it in `config.yaml`, or enable unsafe host execution in the Danger Zone, which also unlocks host Python.
- **Sudo (C2/C10).** `execute_sudo`, package management, the firewall guard, virtual-computer setup and network-share writes need sudo timestamp caching or a `NOPASSWD` rule. `NOPASSWD` hosts no longer authenticate at all and ignore a stale Vault password.
- **Cross-origin provider redirects (C5/C11/C13).** A provider base URL that answers with a cross-origin redirect, including http to https behind a reverse proxy, now fails fast with `cross-origin integration redirect rejected`. This covers speech-to-text for Telegram, Discord, SIP, RTL-SDR and the web voice handler, mission preparation, the summary LLM, the Personality V2 provider and the AI Gateway live probe, and (C13) the vision, multimodal-embedding, text-to-speech and image-generation base URLs. The realistic cases are a LAN Whisper server behind Caddy auto-HTTPS configured as `http://`, or a LAN Ollama, LocalAI or embedding server configured as `http://` that answers 308 to https behind Caddy or Traefik. Configure the final `https://` URL. Provider-returned image downloads still follow CDN redirects.
- **Remote agents and pairing tokens (C12).** Enrollment and AgoDesk pairing tokens issued before the upgrade are invalid; create new ones. Remote agents deployed before the upgrade cannot reconnect until their binary is replaced with a download from the upgraded supervisor, because frames are now version 2 with a length-prefixed HMAC form. Their device keys survive, so no re-enrollment is needed, and the supervisor logs `unsupported frame version` per affected device. The enrollment MAC key now lives in the vault as `remote_enroll_key_<id>` for the token's lifetime, and the first agent frame no longer carries it.
- **Remote agent enrollment (C8).** The remote agent refuses enrollment answers it cannot verify: tokenless agents accept only `pending` or `rejected` and no longer store a device id from `pending`. Agents an earlier version left with a device id but no shared key recover automatically once restarted with the token shown after approval, and until then reappear as pending. `remote_control.auto_approve` has no effect (it already had none before this release), and its security hint is now an informational note; prefer `wss://` for token enrollment.
- **Operator commands in shared channels (D1).** `/sudopwd`, `/addssh`, `/restart`, `/personality`, `/debug` and `/voice` typed in a Discord server channel, a Telegram group or a shared Rocket.Chat room are refused with a hint; Telegram replies already go to the owner's private chat. Set `rocketchat.allow_operator_commands: true` to restore the old Rocket.Chat behaviour. Model-written follow-up prompts can no longer run operator commands; owner missions still can.
- **Rocket.Chat sessions (D2).** Rocket.Chat conversations are now per room and sender, like Discord. Earlier Rocket.Chat context in the shared default conversation history is no longer visible to the bot, so Rocket.Chat starts fresh, and `/reset` and `/stop` from Rocket.Chat affect only that sender's conversation. The web console's Stop button no longer stops a Rocket.Chat run: toggle the Rocket.Chat config, restart, or call `/api/agent/interrupt` with `X-Session-ID: rocketchat:<room>:<user>`. Long-term memory, journal and tools stay shared.
- **Blocked free-text answers (D3).** Free-text answers to the agent's questions are wrapped as external data before the model sees them. An answer that matches prompt-injection patterns is withheld as `blocked` when it was typed in Telegram, Discord or SMS; answers from the web console or desktop chat are never withheld, only logged. (Rocket.Chat has no question-answer path, so it is not among the blocked sources.)
- **API token scopes (D4).** Creating an API token that mixes `cyd` with other scopes, or uses a scope the server never checks, is refused with 400. Existing tokens are unaffected; check the Tokens tab for any pre-existing token pairing `cyd` with another scope and recreate it, because they use the short 9-character CYD format (about 45 bits) while carrying broader scopes. New CYD token prefixes display as `aura_...`.
- **Symlinks and special files under `/files/` (D5).** Host-side symlinks or junctions from `agent_workspace` or any served media directory to locations outside it are no longer served under `/files/`; a refused escape is logged at debug level. Links that stay inside keep working, relative or absolute. Non-regular files such as FIFOs, devices and sockets are no longer served.
- **AgoDesk media and TTS buckets (D6).** Symlinks placed inside the AgoDesk media or TTS buckets are no longer served through signed URLs, even links pointing back inside a bucket, and directories are not listed. A file literally named `index.html` is now served instead of redirected. Media files whose extension has no known type are served as `application/octet-stream` unless the content sniffs as image, audio, video, PDF, Ogg or plain text, and document download names are now RFC-2231-quoted.
- **Desktop pets (D7).** Desktop pet lookups reject pet ids outside the id pattern, spritesheet paths that are absolute or contain `..`, `:` or `\`, and linked files or folders; errors no longer show host paths. Hand-made pet folders with non-matching names or linked pet folders drop out of the pet list. Built-in pets are reinstalled only when a file is actually missing or the manifest cannot be parsed, never through a link, and a customised valid manifest is kept.
- **New-install defaults (D9).** New installations start with the web scraper off and incoming webhooks limited to 60 requests per minute per token. Existing configurations keep their explicit values, and configurations that never set the keys keep their previous behaviour via the merger's upgrade rule.
- **SQL tool denylist (D10).** SQL write and DDL statements that reach the database server's file system, loader or administration (`pg_read_file`, `LOAD_FILE`, `load_extension`, `INTO OUTFILE`, `CREATE EXTENSION`, `CREATE FUNCTION`, `ALTER SYSTEM` and similar) are refused through the SQL tool. Ordinary write functions, tables and columns are unaffected, including names like `copy`, `outfile` or `edit`. Granting the privileged Postgres roles `pg_read_all_data`, `pg_write_all_data`, `pg_read_server_files`, `pg_write_server_files` and `pg_execute_server_program` through the tool is refused as well; multi-statement trigger bodies with inner `;` were already impossible through the tool. A later sample closed further gaps: the Postgres SQL-string runners (`query_to_xml`, `ts_stat`, the `crosstab`/`connectby` family), SQLite `VACUUM INTO`, `CREATE SUBSCRIPTION`/`TABLESPACE`/`TRUSTED LANGUAGE`, the `*_preload_libraries` settings, MySQL `DATA`/`INDEX DIRECTORY` and the CONNECT-engine `FILE_NAME` table option are now refused too, and an alias or column named like an object keyword (`1 AS key, pg_read_file(...)`) no longer lets a denied call through.
- **Docker variables hidden from shells (D11).** Shell, sudo and host Python commands run by the agent no longer see `DOCKER_HOST` and the other Docker client variables unless the Docker tool is enabled; Python skills and daemon skills still do. This is a speed bump, not isolation: in the compose setup the `docker-proxy` endpoint stays reachable from any shell on the `docker-control` network, and skill execution and provisioning keep the variable by design, so hiding it only stops a casual `docker` from an agent without the Docker permission, not a determined one. The compose socket-proxy image is pinned to `tecnativa/docker-socket-proxy:v0.5.0` by digest, the same image `latest` resolves to today, so the first `docker compose up -d` after the upgrade recreates `aurago_docker_proxy` once because the image string changed. [`docker_installation.md`](docker_installation.md) now lists every feature that needs `EXEC=1` on the proxy and the digest refresh procedure.
- **Egg key rotation (D12).** Egg key rotation is confirmed by the egg before the master commits it, and the egg stores the new key in its vault, so a lost acknowledgement or an egg restart no longer locks the egg out. A second rotation while one is in progress or unresolved answers 409, and a rotation the egg rejects drops its staged key at once. An upgraded egg confirms persistence in its acknowledgement and the old key is retired at commit; only an egg still on the previous binary can reconnect once with the old key within an hour, and re-hatching revokes every candidate key. A rotation retried after a failed master vault commit heals itself when the egg already holds the staged key, but commands sent during a rejected or late rotation are lost. An egg's HTTP artifact uploads and host messages still use the key it started with, so restart the egg after a rotation until that follow-up lands. The egg's `config.yaml` must stay writable: a read-only file that still holds `egg_mode.shared_key` copies the hatch-time key over a rotated one at every restart and can still lock the egg out (see `internal/invasion/AGENTS.md`). Update the master and all eggs together.
- **MQTT relays (E4).** MQTT relays (`relay_to_agent`, the Frigate relays) and MQTT-triggered missions now require broker authentication, meaning a username or a client certificate presented over TLS (a `tls.cert_file` on a plain `tcp://` broker URL is never sent and does not count), unless `mqtt.allow_unauthenticated_relay: true`. A refused delivery is logged once per path. Existing configurations with an enabled anonymous broker keep working: the loader grandfathers the missing key to `true` and config-merger writes `true` on the next upgrade. The critical security hint `mqtt_relay_no_auth` appears whenever `allow_unauthenticated_relay` is true on an anonymous broker, including the explicit `true` config-merger writes on upgrade, until broker credentials are set or the key is set to `false`. Tool-only MQTT setups can set it to `false`. Configurations whose MQTT was disabled at upgrade time get `false`, so enabling MQTT with a relay later shows a warning hint that the relay is refused; new installations default to `false`.
- **Checksum-verified installer and a new release (E6).** The docs now lead with the verified install: download `install.sh` and `SHA256SUMS` from the latest release and run `sha256sum -c --ignore-missing SHA256SUMS && bash install.sh`. The main-branch one-liner stays as the quick install. The Windows release scripts now write `SHA256SUMS` with LF line endings. If `sha256sum -c` prints "no file was verified", that release predates this fix; use the quick install or wait for the next release.
- **sha1 webhooks (E7).** Incoming webhooks signed with `sha1` are no longer accepted without their bearer token. sha256 signatures still authenticate on their own, and a sha1 webhook keeps working once it is called with its token; a deprecation warning names each sha1 webhook at load. The token must arrive as `Authorization: Bearer <token>`, the only header the webhook reads for a token, so a sha1 webhook keeps working only for senders that can set that header. A GitHub-style sender that only signs the body (`X-Hub-Signature-256`) and sets no `Authorization` header must switch the webhook to sha256, which then authenticates on the signature alone.
- **Remote shell needs allowed paths (E8).** Shell commands on an `aurago-remote` device now need a non-empty allowed-paths list: the device's own list or, when that is empty, the global `remote_control.allowed_paths` from the config page, which until now was read by nothing. A read-write device with neither loses shell until one of the two lists is set; the hub answers `REMOTE_ALLOWED_PATHS_REQUIRED` and the agent refuses again. AgoDesk desktop devices are unaffected. The hub evaluates the global list live and pushes a changed global list to connected agents without their own list. Because the global list now applies, devices without their own list, read-only ones included, also gain file read access within it wherever it is non-empty (read-write devices gain read and write access); before, their file operations stayed disabled because the global list was read by nothing.
- **Remote-agent download URL (E8).** The remote-agent download now hands out a `wss://` URL on the HTTPS port whenever the server has HTTPS enabled, even when the admin page was reached over plain HTTP from the LAN. The `wss://` URL needs a certificate the agent trusts: a self-signed master needs its CA in the agent host's trust store, Tailscale, or a reverse proxy with a trusted certificate. A download made on the AuraGo host itself over the loopback listener keeps its `ws://127.0.0.1` URL.
- **Egg certificate pin (E9).** Eggs hatched or safe-reconfigured by a master with self-signed HTTPS now receive `egg_mode.tls_pin_sha256`, the SHA-256 of the master's certificate, and verify it for every WebSocket and HTTP call instead of skipping verification. Egg configs written by older masters with `tls_skip_verify: true` keep working and log a deprecation warning until the next safe-reconfigure. After regenerating the master's self-signed certificate every egg must be safe-reconfigured, otherwise it stays disconnected, so the order is: regenerate the certificate, restart the master, safe-reconfigure each egg. If the master cannot read its own certificate at hatch time the generated config falls back to `tls_skip_verify: true` with a warning. The master's TLS setup and the pin follow the same rule, and `server.https.cert_mode` is now read trimmed and case-insensitively by both. An egg reached through a custom route behind a TLS-terminating proxy is accepted when the proxy's certificate is trusted by the egg host: a public CA, or a private CA installed in the host trust store.
- **SQL connections must name a TLS mode (E10).** New PostgreSQL and MySQL connections must name a TLS mode. The connection form pre-selects `require`, `disable` is meant for local containers, and a request without `ssl_mode`, or with a value other than `disable`, `require`, `verify-ca` or `verify-full`, is refused with 400. For MySQL, `require` verifies the server certificate against the host trust store (unlike PostgreSQL's `require`), so a self-signed MySQL server needs its CA installed or a different mode. Stored connections and SQLite are unchanged, and the API reference's create example now uses the real field names `driver`, `database_name` and `ssl_mode`.
- **Log file permissions (E11).** Log files are now created mode 0600 and an existing world-readable log file is tightened on start. A log shipper running as another user needs `chmod 640` plus group access, which is then kept.
- **Telnyx number policy (E11).** The Telnyx client refuses every mutating call unless it carries the configured number policy, so notification SMS now obey `telnyx.allowed_numbers` and `telnyx.read_only`.
- **Private caching under `/files/` (E11).** Files under `/files/` are cached `private` instead of `public`, and workspace-root files are not cached at all.
- **Credentials dropped on cross-origin redirects (E11).** SSRF-protected HTTP clients drop `Authorization`, `Proxy-Authorization`, `Cookie`, `X-Api-Key`, `X-Auth-Token`, `X-Goog-Api-Key` and any header whose name contains key, token, secret or auth on redirects that leave the exact origin. An http to https upgrade or apex to www redirect on such a client (WebDAV, GitHub, OneDrive, Veo/Lyria downloads) now loses its credentials, so configure the final URL.
- **SFTP drive letters (E12).** SFTP paths with a Windows drive letter (`C:/...`) or a UNC host (`//server/...`) are refused with a clear message.

## Hardening with no action needed

- **CI pins (E1).** CI only: every GitHub Action is pinned to a commit SHA with a full-version comment, Dependabot refreshes them monthly, and workflows default to `contents: read`.
- **SIP hints (E2).** Two new SIP security hints, `sip_auto_answer_all_interfaces` and `sip_wildcard_callers_cidr_peers`; no behaviour change.
- **Fritz!Box TLS port and hint (E3).** With `fritzbox.https: true` the default TR-064 port 49000 is remapped to AVM's TLS port 49443. A new hint `fritzbox_plaintext_sessions` appears when a writable Fritz!Box group is used over plain HTTP, so existing configs that enabled Network, Telephony, SmartHome or Storage without `readonly` will see it.
- **Compressed tool output (D8).** Compressed tool output is scrubbed of registered secrets before it is archived, like the original output.
- **Bluetooth pairing agents (E5).** Linux only: the BlueZ pairing agents answer PIN, passkey, confirmation, authorization, service and display requests only for the device being paired. The short-lived Just-Works/PIN agent is bound to the device of the call, and the interactive agent is bound while an operator's outgoing pairing runs and otherwise, during a discoverable window, still asks the operator for any device. A second interactive pairing of another device while one runs now fails with `BLUETOOTH_OPERATION_BUSY` instead of silently replacing the first pairing's question, and a phone pairing through a discoverable window that overlaps an operator's outgoing pairing is rejected until that pairing ends.
- **Fedora installer and install docs (E6).** On Fedora the installer imports the RPM Fusion 2020 signing key only after checking its fingerprint and installs the release RPM with `localpkg_gpgcheck=1`, so a tampered key or package skips RPM Fusion instead of installing it. The docs drop the never-implemented `AURAGO_INSTALL_DIR` and `AURAGO_VERSION` variables in favour of `AURAGO_DIR` and fix the Linux asset names.
- **Provider logging and key masking (E7).** Provider base URLs are logged without credentials, query or fragment, and 429 bodies from providers are capped at 4 KiB in error messages. LLM, helper, fallback and provider API keys and OAuth client secrets are masked in logs after start and after every config reload; short placeholder keys such as `not-needed` are left alone so ordinary words are not redacted.
- **Remote-control database (E8).** The remote-control database file is created mode 0600 on Linux/macOS.
- **AgoDesk reconnect.** An AgoDesk session reconnect is accepted only for a device that AgoDesk pairing created; the key of an `aurago-remote` device is refused like a wrong key.
- **Remote agent frame checks (C9).** Agents now drop supervisor frames that are more than 15 minutes off the agent's clock, replayed, malformed or addressed to another device; agents whose clock is more than 15 minutes off already failed authentication. The supervisor keeps nonces for 30 minutes and closes a connection after repeated bad frames, and an agent whose session drops within a minute of connecting, for example on a supervisor restart, now waits 5 to 60 seconds before redialing.
- **Virtual-computer lease release (E10).** A human control lease on a virtual computer that expires is released with a scoped update instead of a full row rewrite, so a renewal that races the reconciler is no longer overwritten.
- **Vault, Guardian log and printer cameras (E11).** The vault's secret file is fsync'ed through its directory after each write, and the Guardian's "suspicious user input" log line shows a redacted 80-character preview. At most four 3D-printer camera streams run at once; a fifth answers 503.
- **Docker inspect masking (E11).** `docker inspect` output masks more credential-like variable names (`*_PASS`, `*_PASSWD`, `*_PWD`, `*_PASSPHRASE`, `*_CREDENTIALS`, `REQUIREPASS`, `MASTERAUTH`) and reduces bind-mount sources to their last path element.
- **Rocket.Chat allowlist warning (E11).** The Rocket.Chat bot warns at start for every `username:` allowlist entry and recommends `id:<user-id>`.
- **Knowledge-graph search and Tresor files (E12).** Knowledge-graph context search treats `%` and `_` in a query literally in its LIKE fallback, and the Tresor database and its WAL/SHM sidecars are created mode 0600 from the first byte.
- **Windows desktop file open (E12).** On Windows the desktop file open now compares the opened handle with the entry it checked, so a file swapped between the check and the open is refused. A concurrent atomic replace of the same file at that exact instant yields a permission error instead of a read.
