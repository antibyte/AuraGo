# EasyDrag recorded child-step inspection

Status: implemented local contract; exact-snapshot and release acceptance follow the flagship verification gates. Owners: `internal/flows/AGENTS.md`, `internal/server/AGENTS.md`, `ui/AGENTS.md`, and `ui/js/desktop/apps/AGENTS.md`.

## Product boundary

Inspect retained child calls, nested calls and batch items from the existing result inspector, including isolated flow/block/scenario simulation. Capture evidence as a call completes; do not create child runs, child SSE, a second editor or a live child-progress promise. Parent canvas state, draft/undo/save state and execution remain separate. A missing historical parent document must not hide retained child evidence: use the same viewer in the existing run-details modal. Child documents always belong to the inspected immutable invocation.

C11's default-off durable allowlist stays unchanged. Effectful or durable child execution, replay, child controls and trace exports are outside this slice.

## Identity and wire shape

- Use trace format `schema: 1`. The real-run owner is `(run_id, parent_seq)`, using the actual stored parent-step sequence. Never infer it from a step array index or node ID. Simulation uses its own actual engine sequence within that particular response, omits `run_id`, and never constructs a persistent URL.
- Each frame has an opaque trace-local `invocation_id` (`i_1` through `i_1000`, without leading zeroes), optional `parent_invocation_id`, `call_node_id`, `call_attempt`, verified `block_id`, positive `revision`, canonical `hash`, optional zero-based `item_index`, `entered`, and a confirmed `status`/fixed `error_code` when known. Parent links reconstruct ancestry without duplicating full paths. Item zero differs from absent.
- Frame records are `{ordinal, step}`: a one-based frame-local ordinal and the existing bounded `StepRecord`, including its actual attempt and value-truncation flags. Equal node IDs across frames never alias. Only frame-local record order is promised.
- The trace contains `schema`, optional `run_id`, `parent_seq`, `history`, and `frames`. A parent summary contains `parent_seq`, `state`, `truncated`, retained invocation/step counts and nullable total counts. Run detail exposes a small run-level history state and optional parent summaries, never the full trace.
- History states are `pending`, `complete`, `truncated`, `incomplete`, and `legacy_unknown`. `incomplete` plus `truncated: true` preserves both conditions. Terminal pending state reads as incomplete. Transport/storage failure is unavailable, not complete empty data. Only proven totals may be zero.

## Capture and limits

- Limits are 256 KiB encoded per trace, 4 MiB encoded traces per run/simulation, 512 KiB aggregate frame/index/row metadata, 1,000 frames, and 2,000 child step-attempt records. Metadata is included in the trace-byte cap; its separate limit never increases that cap. Reserve bounded space for identity, status and omission markers before values. Exhaustion truncates capture, never execution inputs or the execution itself.
- Share one bounded reservation through the existing block-run scope across parallel parents and nested calls. Each outer call/batch has an independent collector; nested calls append frames to that collector. Do not charge child values twice against existing output/log budgets. Physical trace-byte limits remain separately enforced.
- Reuse the existing omission wrapper and truncation flags. Retain a params/output value only when its complete scrubbed form fits 16 KiB; already-partial or larger values become `_omitted` without a raw text prefix. A partial prefix cannot reliably be scrubbed if a secret crossing its cut boundary is registered later. Preserve readable identity/status and omission evidence, and scrub retained complete values again at response time. Do not change ordinary preview semantics or invent a second encoding.
- A failure can expose an already-shortened `error.message` to later steps. After an error, conservatively omit later child-history values through the shared run scope, including a later outer call; keep ordinary execution outputs unchanged. Use the neutral `child_history_omitted` reason rather than claiming every omission was a size limit.
- Carry the collector independently of `ExecResult`. Capture actual failed child attempts at the existing retry boundary and the final attempt exactly once; do not rerun, renormalize or change retry decisions. Preserve ordinary parent records. Existing final step times describe node lifetime; do not present cumulative timings as independent attempt durations or fabricate earlier attempt timestamps.
- Freeze on every outer-worker exit, including error, cancellation, panic, `runtime.Goexit`, and abandonment. A collector closed by abandonment is incomplete; late worker writes are ignored without consuming more quota. No database, authority or user callback runs under its synchronization lock.
- Pre-engine input rejection records an entered-false frame and fixed failure code. Empty batches may be known complete with zero frames. Stop-mode batches may retain diagnostic evidence while continuing to withhold partial structured batch output.

## Persistence and compatibility

- Use a backed-up schema-v7 migration from v6. Verify a consistent WAL-inclusive backup before writes; install tables/columns/checks/keys transactionally, advance the version last, and verify the installed contract. Preserve documents, hashes, pins, scenarios and C11 ciphertext. Old rows become `legacy_unknown`; previous binaries refuse the newer schema without changing it.
- Store one bounded trace/marker per `(run_id,parent_seq)` with a cascading foreign key to its parent step. New capture-capable runs start pending atomically with admission. Persist parent step, frozen trace and shared committed-byte accounting in one transaction using INSERT, never a replacement that can silently cascade away a prior trace. Reserve 512 KiB within the existing 4 MiB total for bounded parent markers; retained full trace payloads use at most 3.5 MiB. Marker summaries and row overhead also count against the same total and metadata limits.
- A failed or uncertain write never triggers node replay, a blind mutation retry, or a false available/complete summary. Retain conservative run-level completeness until terminal status and history state commit together. An observed committed journal remains authoritative. Fixed bounded markers may represent missing/truncated trace payloads when the blob quota is exhausted.
- Commit trace-bearing parent steps before advertising a positive child summary. Preserve parent event types, node identity and ordinary event ordering; child records never enter the parent node map or parent sequence stream. Run reads join small summaries in bulk and return actual parent sequences.
- Retention/delete cascades with the existing run and parent step. Existing transitive run pins retain child versions. Do not add a separate history database or retention service.

## Reads, privacy and simulation

- `GET /api/desktop/flows/runs/{run}/steps/{parent_seq}/children` returns the complete retained trace on demand, at most 256 KiB after response scrubbing. There are no server frame/step cursors. A second GET at `.../children/{invocation_id}/document` returns the exact verified child document or an explicit missing-document result.
- Document reads verify the run, captured frame, matching run-owned block pin, version kind/ID and canonical hash in one read snapshot. Never substitute a current draft/live version, user-supplied identity or same-numbered replacement. Preserve record inspection if document context is missing.
- Reuse existing Desktop read/app/origin policy, `no-store`, bounded request context, fixed errors and strict identifier/body limits. Apply registered-secret and credential-field redaction before persistence and again before response. Keep structural identity separate from redacted display data; withhold unusable/redacted identities instead of fabricating actionable IDs. No raw values go to audit, logs or providers.
- Runtime supplies shared typed trace/simulation sanitizers, identifier validators and byte-limit constants; Server applies them immediately before encoding. Do not run an untyped final string replacement over structural IDs or completeness counters. Missing document reasons are fixed `unavailable`, `redacted`, or `budget` values. Child errors retain fixed codes; any pre-shortened free text without a proof of complete redaction is omitted.
- Simulation returns the same trace shape inline from its existing isolated execution, linked by explicit engine sequence. Include deduplicated child document snapshots from that same verified plan under a 2 MiB aggregate encoded document budget. When that budget or post-redaction validity fails, keep trace evidence and report document context missing. Do not fetch media/FileRefs, persist traces, create fake runs or add a simulation history endpoint. Block simulation already exposes root steps; these traces inspect its nested invocations.

## Viewer and ownership

- Use one read-only inspector viewer with breadcrumbs, local pages of at most 50 frames/100 records, and at most 250 rendered rows. Render only the selected record's bounded value view. Keep one selected trace and a bounded, deduplicated document cache; bind every reply to its run/simulation generation, parent sequence and invocation. Dispose on navigation/read-permission loss and restore focus on close. Phones use list/detail turn-taking and 44-pixel Back/Close targets; the same viewer may use the existing modal shell in narrow app windows so the selected value and return controls remain visible together. Label repeated invocations with localized call numbers instead of requiring users to interpret opaque IDs.
- Runtime owns collectors, engine/block integration, DTOs, all Store/Service trace and verified-document methods, migration, tests and its guide. Server owns routes, HTTP bounds/auth/redaction tests and shared native fixtures/browser tests. Frontend owns the viewer, narrow existing-module hooks, styles, EN/DE keys/manuals and Apps guide. Root coordinates the final all16 translation matrix, independent review, migrations/old-binary proof, clean gates and selective local commits. Shared files and loader/guide fragments must preserve concurrent edits.
